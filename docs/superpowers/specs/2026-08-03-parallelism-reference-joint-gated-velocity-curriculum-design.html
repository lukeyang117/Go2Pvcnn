Parallelism Reference 对齐与关节门控速度课程

适用分支：Parallelism-flat-rl　|　任务：平地 Go2 Parallelism tracking

核心目标：Parallelism 规划逻辑保持不变。RL 接口负责把规划结果转换成 policy 当前 root 坐标系下的 reference；速度课程只有在关节位置持续跟踪良好、且 root reference 速度跟踪达标时才允许升级。

1. 范围与不变项

本次修改范围

  • 只修改 tracking/RL 接口、reference observation、reward、curriculum 和 termination 对齐逻辑。
  • 使用当前 reference phase 的数据，不使用整段 24 帧平均 reference 作为 policy 当前输入。
  • 增加 episode 内关节误差统计，用于速度课程的严格门控。

明确不修改

  • Parallelism 的 root、foot、touchdown、swing、IK、FK 和 trot 规划逻辑。
  • 24 帧规划长度、规划频率和每 24 帧重规划机制。
  • 原始 base_velocity 的采样和传入 planner 的语义。

2. Reference root 速度坐标变换

Parallelism 输出的 root 速度先被视为 reference root frame 下的 6D twist：

twist_ref_b_ref = [vx, vy, vz, wx, wy, wz]

RL 接口执行两级转换：

v_ref_w = R_ref_w * v_ref_b_ref
w_ref_w = R_ref_w * w_ref_b_ref

v_ref_b_policy = transpose(R_policy_w) * v_ref_w
w_ref_b_policy = transpose(R_policy_w) * w_ref_w

其中：

  • R_ref_w 是当前 reference root 到世界系的旋转。
  • R_policy_w 是当前时刻实时读取的 policy robot root 到世界系的旋转。
  • 最终输入、奖励和课程使用的是 twist_ref_b_policy。
  • 线速度和角速度都使用完整三维旋转，不只使用 yaw。
防止坐标混用：不能直接把 reference root frame 下的速度当成 policy body-frame 速度。每一个 RL step 都必须读取 policy 当前真实 root 姿态，先经过 reference frame 到世界系、再到当前 policy root frame 的转换。不能缓存 episode 开始时的 policy 姿态，也不能使用 reference 自己的姿态代替 policy 当前姿态。

统一转换接口

训练和 play 共用同一个 tracking 接口，例如语义上统一为：

reference_root_twist_in_policy_frame(env) -> [num_envs, 6]

这个接口内部同时读取：

  • Parallelism reference 当前 phase 的 root-frame twist 和 reference root pose；
  • env.scene["robot"].data.root_quat_w 的 policy 实时 root 姿态；
  • 然后批量返回当前 policy root frame 下的 reference twist。

observation、reward、curriculum、velocity termination 和 play diagnostics 都不能各自实现一套坐标转换。

3. RL 输入接口

原始 command
base_velocity
只给 Parallelism 生成规划。
规划结果
当前 reference joint 和 root twist。
Policy 输入
转换后的当前 root-frame reference。

Actor 和 critic 都移除原始速度 command 观测：

删除：velocity_commands = base_velocity

改为输入：

parallelism_ref_root_lin_vel_b_policy = [vx, vy, vz]
parallelism_ref_root_ang_vel_b_policy = [wx, wy, wz]
parallelism_ref_joint_pos
parallelism_ref_joint_vel

关节角和关节速度不做 root 坐标转换，因为它们已经是在各自关节坐标定义下的量。

训练与 play 对齐：play 使用训练时相同的 observation manager 计算 policy 输入。因此加载训练 checkpoint 后，play 中的 policy 也会在每一步根据当前真实 policy root 姿态重新计算 reference twist，不需要额外输入或手动重建速度观测。

4. 当前时刻的 tracking 误差

关节位置误差

joint_abs_error_t = abs(policy_joint_pos_t - reference_joint_pos_t)
joint_mean_error_t = mean(joint_abs_error_t)
joint_max_error_t = max(joint_abs_error_t)

joint_mean_error_t 用来衡量整体跟踪质量，joint_max_error_t 用来防止单个关节或单条腿被平均值掩盖。

root 速度误差

lin_vel_error_t =
    norm(policy_root_lin_vel_b_t - reference_root_lin_vel_b_policy_t)

ang_vel_error_t =
    norm(policy_root_ang_vel_b_t - reference_root_ang_vel_b_policy_t)

这三个误差都在同一个当前时刻、同一个 reference phase、同一个 policy root frame 下计算。

5. Episode 内关节统计

参考 InstinctLab 的 tracking monitor，不只检查 episode 结束时的一帧。每个 step 使用当前 reference phase 更新每个环境的统计量：

joint_mean_sum += joint_mean_error_t
joint_max_over_episode =
    max(joint_max_over_episode, joint_max_error_t)
valid_frame_count += 1

episode_joint_mean_error =
    joint_mean_sum / valid_frame_count
episode_joint_max_error =
    joint_max_over_episode

环境 reset 时读取统计结果，然后清零对应环境的累计状态。任意中间摆腿阶段出现大的关节偏差，都会体现在 episode 统计中。

关键区别：“当前时刻 reference”决定每一步如何计算误差；“episode 统计”决定速度课程是否真的可以升级。这样既保持 phase 对齐，又能保证关节是持续跟踪良好。

6. 奖励设计

速度奖励

速度奖励追踪转换到当前 policy root frame 的 reference root twist，不再直接追踪 base_velocity：

track_linear_reference:
    policy_root_lin_vel_b vs reference_root_lin_vel_b_policy

track_angular_reference:
    policy_root_ang_vel_b vs reference_root_ang_vel_b_policy

当前版本保留原有 reward 结构和主要权重，先保证目标替换正确，再根据 TensorBoard 调整权重。

关节奖励：采用 InstinctLab 风格

关节跟踪奖励参考 InstinctLab 的 joint_pos_tracking_gauss 和 joint_vel_imitation_gauss。每个当前 reference phase 都计算所有 12 个关节的误差，先合并关节误差，再通过 Gaussian 指数得到一个整体 tracking reward。

joint_pos_diff = policy_joint_pos_t - reference_joint_pos_t
joint_pos_diff = sign(joint_pos_diff)
                 * max(abs(joint_pos_diff) - tracking_tolerance, 0)
joint_pos_err = sum(square(joint_pos_diff), dim=-1)

reference_joint_pos_reward =
    exp(-joint_pos_err / (joint_pos_sigma * joint_pos_sigma))

关节速度使用同样的结构：

joint_vel_diff = policy_joint_vel_t - reference_joint_vel_t
joint_vel_err = sum(square(joint_vel_diff), dim=-1)

reference_joint_vel_reward =
    exp(-joint_vel_err / (joint_vel_sigma * joint_vel_sigma))
  • 默认采用 InstinctLab combine_method="prod" 的等价形式：先对所有关节平方误差求和，再计算一次指数。
  • 不使用当前实现的 mean(square(error)) 作为唯一关节 tracking reward。
  • tracking_tolerance 以内的微小误差不继续惩罚，用于吸收仿真噪声和执行器误差。
  • 位置和速度奖励都逐步作用于全部 12 个关节，不修改 planner reference，不做 default pose 与 reference 的混合。
  • joint_pos_sigma、joint_vel_sigma 和 tracking_tolerance 放入 tracking config，后续可以独立调节。
尺度注意：对 12 个关节求和会比平均误差更严格。sigma 不能直接照搬当前 reward 的 std=0.35，需要结合 TensorBoard 中的 reward 分布调节，否则 reward 可能在摆腿阶段快速接近 0。

7. 速度课程门控

不新增独立 joint level。关节 tracking 是速度课程的严格前置条件。

单个 episode 的升级条件

指标条件含义
episode 结束方式 正常 timeout，且没有 termination 不能通过提前失败来升级
关节平均误差 episode_joint_mean_error < 0.20 rad 整体关节跟踪稳定
关节最大误差 episode_joint_max_error < 0.45 rad 不能有单关节严重偏离
root 线速度误差 episode_lin_vel_error < 0.25 m/s 跟踪当前 reference root 线速度
root 角速度误差 episode_ang_vel_error < 0.35 rad/s 跟踪当前 reference root 角速度

其中 root 速度误差也应按 episode 累计平均，和关节误差一样不能只看最后一帧。

episode_lin_vel_error =
    mean_over_valid_frames(lin_vel_error_t)

episode_ang_vel_error =
    mean_over_valid_frames(ang_vel_error_t)

升级规则

  • 所有条件同时满足，当前环境 velocity level 才加 1。
  • 只要关节 mean、关节 max 或 root 速度任一项失败，当前环境不升级。
  • 发生关节、root、姿态或接触 termination 时，当前环境降级 1 级。
  • level 始终限制在 0~max_level。
  • 速度范围由所有环境 level 的平均值线性插值，但升级资格按环境独立判断。

8. Termination 对齐

所有 reference tracking termination 继续使用当前 reference phase：

  • root z：policy 当前 root z 与当前 reference root z 比较；
  • projected gravity：policy 当前姿态与当前 reference 姿态比较；
  • foot z：policy 当前足端高度与当前 reference 足端高度比较；
  • joint position：policy 当前关节角与当前 reference 关节角比较。

如果保留或新增 root velocity termination，它必须使用同一份由实时 policy root 姿态转换得到的 twist_ref_b_policy，不能重新使用 base_velocity，也不能使用 episode 初始姿态转换出来的缓存速度。

base_contact、bad_orientation 和实际物理非法接触仍然判断 policy robot 自身状态，不被 reference 坐标转换替代。

9. TensorBoard 验证指标

训练中需要明确区分“当前帧”和“episode 统计”：

日志指标用途
Metrics/reference_joint_mean_error_current当前 reference phase 的平均关节误差
Metrics/reference_joint_max_error_current当前 reference phase 的最大关节误差
Metrics/reference_joint_mean_errorepisode 平均关节误差
Metrics/reference_joint_max_errorepisode 内最大单关节误差
Metrics/reference_root_lin_vel_errorepisode 平均 root 线速度误差
Metrics/reference_root_ang_vel_errorepisode 平均 root 角速度误差
Curriculum/parallelism_velocity全环境平均速度课程等级
Curriculum/parallelism_velocity_upgrade_blocked_joint因关节 mean/max 不达标而阻止升级的次数
如果速度课程继续上升，但 episode 平均关节误差、episode 最大关节误差或 joint termination 仍然很高，说明课程门控实现或统计时机有问题，不能只看速度 reward。

10. Play 接口与 reset/replan 同步

训练和 play 必须遵守同一时序：

1. 读取或更新 base_velocity，仅用于触发 planner
2. Parallelism manager 刷新当前 phase
3. 读取 policy robot 当前实时 root pose
4. 计算当前 policy root frame 下的 reference twist
5. observation manager 生成 actor/critic 输入
6. policy 推理并执行 action
7. env.step()
8. 若 reset/replan，下一次 observation 前重新读取 policy root 状态

reset 后不使用 reset 前的 root 姿态缓存。重规划后 reference phase 可以变化，但坐标转换始终使用当前 policy robot 的真实 root 姿态。

play 中的 reference Go2 只负责显示 reference pose/joint，不参与 policy reference twist 的坐标转换，也不参与物理约束。policy 的输入必须来自和训练相同的 observation term。

11. 验证标准

  • Planner 输出和 viewer 中的 Parallelism reference 不发生变化。
  • Actor 和 critic 不再接收原始 base_velocity 速度观测。
  • reference root twist 经过 reference root frame → world → 当前 policy root frame 的两级转换。
  • 连续改变 policy 当前 yaw、roll、pitch 时，reference twist 输入会实时随 policy root frame 变化。
  • reward、curriculum、velocity termination 使用同一份当前 phase 的转换后 reference twist。
  • 关节 position 和 velocity reward 使用当前 phase 的原始 joint reference。
  • 速度等级只有在 episode 平均 joint mean、episode joint max、root 线速度和角速度都达标时才提升。
  • 1024 个环境下所有统计和条件判断保持 Torch/GPU 批量执行，不使用逐环境 Python 循环。
  • 训练得到的 checkpoint 使用当前 scripts/play.py 启动后，policy 输入维度、reference 速度语义和训练保持一致。
