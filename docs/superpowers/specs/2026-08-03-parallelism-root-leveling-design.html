Parallelism Root 姿态快速水平化设计

目标：机器狗从倾斜 root 状态开始规划时，第一帧保持真实状态对齐，并在第 12 帧之前快速、连续地恢复到水平。

一、问题与目标

当前 rollout 会把测量状态中的 roll/pitch 原样复制到整段 24 帧。机器人如果开始时倾斜，候选 hip、IK、FK 和碰撞几何体都会持续使用倾斜 root，造成候选点大量失效。

本设计要求：

  • 第 0 帧 reference 与 policy 当前真实状态完全一致。
  • roll 和 pitch 在前 12 帧内恢复到 0。
  • 第 12 帧至第 23 帧保持水平。
  • yaw 继续按原有速度规划。
  • 所有几何计算使用同一帧的水平化 root 姿态。

二、姿态轨迹

在配置中增加可调参数：

root_leveling_frames = 12

对每个 batch、每个 horizon frame 并行计算：

u = clamp(frame / root_leveling_frames, 0, 1)
s = u * u * (3 - 2 * u)

roll_t  = roll_0  * (1 - s)
pitch_t = pitch_0 * (1 - s)
yaw_t   = yaw_0 + yaw_delta_t

其中 roll_0、pitch_0 是当前实测状态。这样第 0 帧完全对齐，第 12 帧精确水平，且使用 GPU 上的 Torch 张量操作，不增加逐帧 Python 循环。

帧范围roll/pitch用途
第 0 帧当前实测值保证 reset、重规划和 policy reference 对齐
第 1~11 帧平滑下降到 0避免 root 和关节 reference 瞬时跳变
第 12~23 帧固定为 0以水平 root 进行稳定行走规划

三、几何计算一致性

水平化后的 root_rpy_w[:, t] 是该帧唯一的 root 姿态输入，并统一传给：

  1. 四个 hip 对应的 candidate 参考位置；
  2. candidate IK 和 FK 硬过滤；
  3. active leg 的 swing collision 检查；
  4. 最终 24 帧 IK/FK 轨迹；
  5. 输出给 RL 的 root、joint 和 foot reference。

不能只在显示或最终输出阶段水平化，否则规划内部几何体仍然会使用倾斜 root，造成检查结果与实际 reference 不一致。

四、root 位置与 fallback

root 的 XY 位移和 yaw 逻辑保持不变。root Z 继续使用当前 stance 足端对应的高程加 root_clearance_m，不额外引入新的 root 高度策略。

如果候选点全部无效且启用 standstill fallback：

  • root、joint、foot 输出保持当前实测状态；
  • 不输出一段虚假的水平化轨迹；
  • contact state 继续保持全 stance。

五、并行性与接口

输入为 [B, 3] 的 root position 和 root RPY，输出为：

root_rpy_w: [B, 24, 3]

帧索引通过广播生成，roll、pitch、yaw 全部使用 Torch 运算。该设计适用于 1 个环境和 1024 个环境，不改变 Parallelism 规划的 24 帧固定形状。

六、验收标准

  • 水平初始状态：root roll/pitch 全程保持 0，既有平地规划结果不变。
  • 仅 roll 倾斜：第 0 帧保留初始 roll，第 12 帧及以后为 0。
  • 仅 pitch 倾斜：第 0 帧保留初始 pitch，第 12 帧及以后为 0。
  • roll 和 pitch 同时倾斜：候选点不再因为整段倾斜而系统性失效。
  • 检查 24 帧 root、joint、foot shape 和 GPU batch 计算。
  • 无效规划时 fallback 仍保持实测状态。
  • 重规划时新轨迹第 0 帧仍与当前 policy 状态一致。

七、明确不修改的内容

保持 root XY 位移

保持 yaw 速度 rollout

保持 trot contact schedule

保持 touchdown candidate、semantic filter、score 和碰撞几何体

保持 RL reward、termination 和 curriculum
