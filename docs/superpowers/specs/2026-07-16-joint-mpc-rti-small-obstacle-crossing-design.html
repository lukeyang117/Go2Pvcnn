Joint MPC RTI 小障碍跨越与几何净空设计

日期：2026-07-16 ｜ 主线：T302v.4 ｜ 目标路径：Go2Pvcnn/extension/joint_mpc_rti/ ｜ 分支：joint_mpc

延续关系：本设计是 docs/superpowers/specs/2026-07-15-joint-mpc-rti-gpu-design.html 和 docs/superpowers/specs/2026-07-16-joint-mpc-rti-joint-order-stance-grounding-design.md 的增量。前者定义同步 GPU RTI、151×151 世界高程/距离场、任意环境数封装、一次 MPC 发布 x1 和 5 秒性能目标；后者修复关节顺序与 stance 贴地。本设计只补齐小障碍跨越的几何净空和优化方向，不改变这些基础合同。

1. 当前问题

真实 viewer 中 stance 已经贴地，零速度 root 也不漂移；但是低矮小语义物体场景下，轨迹仍经常直接穿过物体。受控量化显示，在五种小物体原生形状、三种前进速度下，strict cross 成功率只有 1/223 = 0.45%，其中 calf 接触导致失败 97.8%，foot 接触导致失败 78.0%。

根因不是“最终总 loss 看不到碰撞”，而是当前碰撞净空在优化链路中的位置不一致：部分小障碍 link clearance 只进入完整 merit 评分，line search 能看见轨迹差，但 LQ/GGN 子问题没有同源 residual/Jacobian，因此不会主动产生把 calf、thigh 或 foot 从障碍中推出去的搜索方向。

2. 设计目标

  • 保持 H=16、dt=0.02s、每帧真实 x0、只发布未来 x1。
  • 把 fixed trot 从 half_cycle_steps=4 改为 half_cycle_steps=8，让一个 horizon 覆盖一整次 stance -> swing -> stance 周期，而不是腿摆得过快。
  • 用连续 loss 让轨迹自然选择抬脚跨越、减速或绕行；不增加 small/large 行为硬 gate。
  • 让 foot、calf、thigh 的小障碍净空 residual 同时进入 GGN/LQ 和 merit，确保优化方向与最终验收指标一致。
  • 统一只使用当前世界高程图和 semantic signed distance，不再建立双高度场。
  • 新增 strict cross 成功率和 stance 落地指标，并要求旧指标全部继续通过。

3. 修改约束

禁止新增硬行为 gate：不引入 crossable_small、指定跨越腿、按物体形状分支、固定避障侧、后处理 snapping、hard projection 或 optimize-then-repair。small 语义只产生连续 signed-distance residual；是否跨越由 command/progress、stance、swing clearance、touchdown avoidance、link clearance 和 smoothness 的总代价共同决定。

允许保留或新增的硬约束只属于问题定义和数据一致性：

  • X[:,0] 必须等于真实 IsaacLab 当前状态。
  • root/joint 到 foot/calf/thigh 的几何必须来自同一套 Go2 FK，不能让诊断几何和优化几何各算各的。
  • field version、env id、世界坐标原点和 yaw 必须与 RayCaster 当前帧对齐。
  • batch size 由上层 num_envs 参数构建；改变 1/40/512/1024 等环境数必须重建 manager/cache/graph，不能在固定实例里偷偷 resize。
  • 非有限输入、无效 field 或地图越界查询必须暴露 invalid 诊断。

5.2 Semantic signed boundary distance

对旧设计的覆盖：2026-07-15 GPU RTI 设计中的 small exact EDT、large exact EDT 和无符号 small_distance_m/large_distance_m 在本设计中统一升级为有符号边界距离。后续实现、loss、GGN/LQ、merit 和测试不得继续把障碍内部表示为零距离。

small 和 large 两个语义通道使用相同符号合同：

outside: signed_distance > 0
on boundary: signed_distance = 0
inside: signed_distance < 0

设语义占据栅格为 M，分辨率为 r=0.01m。每个语义通道在 GPU 上对 M 和 ~M 分别执行一次 CUDA warp-level exact EDT，得到自由栅格中心到最近占据栅格中心的 D_out，以及占据栅格中心到最近自由栅格中心的 D_in。缓存值按下面的半栅格修正构建：

free cell:     phi =  max(D_out - 0.5 * r, 0)
occupied cell: phi = -max(D_in  - 0.5 * r, 0)

半栅格修正把零等值线放在占据 cell 与自由 cell 的公共边界，而不是错误地放在 cell center。world query 对 phi 做双线性插值，所以穿过该公共边界时连续经过零；不能只把原无符号 EDT 乘以占据符号，因为原场在障碍内部为常数零，乘符号后仍没有退出梯度。

  • 缓存 ABI 明确为 small_signed_distance_m[B,151,151] 和 large_signed_distance_m[B,151,151]；loss 不再读取旧的 unsigned distance。
  • CUDA 主路径把互补 mask 作为固定通道批量 dispatch，不允许 Python per-env/per-channel 循环；workspace 在 steady-state 原位复用。
  • 空障碍通道返回正的有限饱和值；全占据通道返回负的有限饱和值并标记该通道无有效自由边界；禁止输出 inf 或 NaN。
  • signed distance 的世界 XY 梯度由 query-time 双线性插值解析导数给出。foot/calf/thigh 已经进入小物体，或 root/body 已经进入大物体时，仍必须得到朝增大 phi 方向的有限退出梯度。
  • field version、世界坐标原点/yaw、valid mask 和同步发布合同保持不变；每次 MPC 仍消费本帧同版本的 height、semantic 和 signed distance。

5.3 统一高程图

所有地面、物体顶面、stance 接触和 swing clearance 都查询同一张 height_w。small semantic 不再生成第二高度场，只在同一 height 表面之上叠加 signed-distance 和额外 margin residual。

6. Loss 设计

本设计不新增离散模式，只调整和补齐连续 residual。关键原则是：同一个安全概念必须同时出现在 LQ/GGN 方向和 line-search merit 中。

6.1 Stance 落地相关 loss

Loss实际做什么验收指标
stance_xy_lockstance 段足端世界 XY 贴住当前 stance anchor，避免脚跟着 root 滑走。stance XY slip、足端跳变。
stance_ground_contactstance foot Z 等于 height_w(foot_xy) 加 foot radius 接触偏置。新增 stance_ground_gap_max_m 和 stance_ground_penetration_max_m。
stance_semantic_avoidancestance/touchdown foot 到 small signed distance 保持 margin，防止站在小物体上。strict cross 的前后 stance 不在语义物体上。

6.2 Swing 足端跨越 loss

Loss实际做什么连续性
terrain_swing_clearance所有 swing foot 高于统一高程图表面和基础 margin。与地形无关，普通坡面、台阶、小物体顶面都生效。
small_object_foot_over当 swing foot XY 接近 small footprint 时，连续增加额外净空，让脚从物体上方过去。权重由 signed distance kernel 连续衰减，不要求离散判断“正在跨”。
swing_velocity_smoothness限制 swing foot 速度和加速度，防止为了净空产生尖峰抬腿。保护 viewer 里看起来像真实走路。
touchdown_velocity落地前足端速度降低，避免扫过物体后砸地或擦地。配合 half_cycle_steps=8 让摆动不那么急。

6.3 Small link clearance loss

这是本次修复的核心。foot、calf、thigh 都用同一类 signed-distance residual，并进入 LQ/GGN：

clearance = signed_distance_xy(sample_xy) - radius - margin_xy
height_weight = sigmoid((height_w(sample_xy) + margin_z - sample_z) / temperature)
residual = height_weight * relaxed_barrier(clearance)
Residual采样对象实际做什么
small_object_foot_clearancefoot sphere center避免 swing 或 stance foot sphere 和小物体水平 footprint 相交。
small_object_calf_clearanceknee-foot 插值 capsule samples针对当前 97.8% 失败主因，主动把小腿从物体侧面或上方让开。
small_object_thigh_clearancehip-knee midpoint/samples补齐大腿碰撞诊断和优化方向，避免只修 calf 后换成 thigh 撞。

height_weight 的作用不是硬 gate，而是让“远高于物体顶部”的 link 不再被二维 footprint 过度惩罚；当 link 低、近、甚至已经在障碍内部时，signed distance 提供强梯度。

6.4 Touchdown avoidance

touchdown 和 stance 用 signed-distance barrier 远离 small footprint。这个项只表达“不要踩上去”，不指定“必须跨越”。如果 command/progress 和 swing/link clearance 的总代价认为绕行更便宜，也允许绕行。

7. 优化链路

当前名词关系保持如下：

组件职责本设计要求
LQ / GGN把 residual 和 Jacobian 近似成二次子问题，产生 Δu 优化方向。small foot/calf/thigh residual 必须进入这里。
line search只沿 u + αΔu 尝试几个步长。继续使用完整 merit 选择候选，但不能承担创造方向的职责。
merit完整非线性总分，用于判断候选轨迹好坏。必须和 LQ/GGN 的 residual 语义一致，用来验收而不是藏诊断项。

实现上使用局部 3×3 或低维 analytic Jacobian：

  • foot 使用现有 foot analytic Jacobian。
  • knee 使用 knee Jacobian。
  • calf sample 使用 knee/foot Jacobian 按插值比例组合。
  • thigh sample 使用 hip-zero/knee Jacobian 按插值比例组合。
  • signed-distance residual 的空间梯度通过 chain rule 传到 joint/root block。

为了避免 H×4×samples 平均把少数真实碰撞稀释，small clearance 采用 proximity-weighted normalization：靠近或穿入的样本权重大，远离物体的样本几乎不影响归一化。

8. 指标与验收

8.1 新增 strict cross 指标

一个 cross 事件定义为某条腿完成：

stance -> contiguous swing -> stance

并满足：

  • 前一个 stance 不在 small semantic footprint 上。
  • swing 阶段 foot XY 经过 small obstacle 上方。
  • 后一个 stance 不在 small semantic footprint 上。
  • 该腿 foot、calf、thigh 在整个事件中没有几何接触或穿入。
  • side bypass 不算 cross。
指标目标
总体 strict cross success>= 95%
每个 shape-speed 组合 strict cross success>= 90%
foot/calf/thigh 最大穿入<= 1mm
stance 落在 small semantic 上0
base collision0

指标目标说明

stance_ground_penetration_max_m<= 0.001mstance foot contact surface 低于 height_w 的最大穿入。

8.3 旧指标必须继续通过

  • joint/viewer regression 继续通过，不能恢复关节顺序错配。
  • old MPC/reward/viewer regression 继续通过，不能破坏现有后端。
  • public factory batch 支持 1/40/512/1024，动态环境数由上层参数构建。
  • 真实九命令 viewer：不同方向、速度大小、yaw 和混合命令下 root 速度跟踪和 stance 贴地不退化。
  • 同步 signed distance + MPC：1024 × H16 × 1000 在空闲 GPU 上仍需满足 <= 5s；计时必须包含 small/large 占据区与自由区互补 exact EDT、半栅格修正、field 发布和 MPC，不得只计单侧 unsigned EDT。
  • 无非有限值、无 CUDA graph batch-size 隐式 resize、field version 正确递增。

10. 实施顺序

  1. 先把 strict cross、stance ground、signed-distance 和 GGN visibility 测试写成 RED，复刻当前失败。
  2. 修改 gait scheduler：half_cycle_steps=8，保持 H=16。
  3. 把 small/large distance 都改为 signed boundary distance：互补 exact EDT、半栅格修正、有限饱和值，并补内部梯度和退化通道测试。
  4. 在 Go2 FK 中补齐 thigh sample/Jacobian，calf sample 继续复用 shank/knee-foot 插值。
  5. 把 foot/calf/thigh small clearance residual 接入 linearization/GGN/LQ，同时保持 merit 同源。
  6. 调整 normalization，让近障碍样本不被全 horizon 平均稀释。
  7. 跑 strict cross、stance ground、旧 regression、真实 viewer 和 1024 性能验收。

11. 风险与边界

  • 如果 clearance 权重过高，可能牺牲 command tracking 或让 robot 在小物体前绕行；用 strict cross 中的 side-bypass 排除假成功。
  • half_cycle_steps=8 会降低摆腿频率，低速更自然，但高速 command 可能需要更强 progress/velocity 平衡。
  • signed distance 内部梯度在极小物体中心可能方向不唯一；测试应覆盖中心、边缘和偏心穿入。
  • thigh/calf sample 增加会提高 GGN 计算量；必须用固定形状、batched query 和 proximity normalization 控制性能。
  • 本设计仍是运动学可行，不声明动力学、力矩或真实接触力可行。
