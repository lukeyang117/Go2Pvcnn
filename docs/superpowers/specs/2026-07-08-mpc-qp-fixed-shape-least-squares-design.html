MPC-QP Fixed-Shape Least-Squares 设计

日期：2026-07-08。目标是在保留 mpc 与 mpc_qp 隔离的前提下，把 mpc_qp 从“联合 loss + 多个条件 gate / decode 硬修正”改成固定形状的 batched least-squares / QP-style 求解器。

核心合同：除 plane_row 锁 root z 和 P3.z = height_at(P3.xy) 外，不允许通过 gate、repair、candidate search、readback replacement 或 decode projection 修轨迹。轨迹质量问题必须通过 residual、权重、damping、变量缩放、采样密度和不超过 3 次的 QP iteration 解决。

1. 背景与问题

当前 mpc_qp 已经有联合 loss：foot control、root、rpy 一起进 loss 并通过 autograd 求梯度。但在梯度应用和 decode 阶段，又加入了许多条件逻辑，例如 semantic / low-small / risky terrain gate、low-small arc 手工更新、root z readback、high semantic root lift、foot z terrain clamp、FK foot 替换 planned foot。

这些逻辑会带来两个问题：第一，轨迹看起来通过了某些测试，但并不是 QP 真正优化出来；第二，语义图或小障碍一出现，root、foot、joint 可能发生条件切换式抖动。新设计要求把这些行为全部收回到统一 residual 里。

2. 保留与禁止

2.1 唯一允许的硬规则

规则原因边界
plane_row=True 时锁 root z 平地上 root 高度必须对齐老 mpc，避免 semantic small obstacle 把 root 当成地形抬高。 plane_row 只能影响 root z，不能锁 root xy，不能改变 foot 更新。
P3.z = height_at(terrain, P3.xy) touchdown 的 z 是地形几何边界，不应作为自由变量漂浮。 只绑定 touchdown endpoint P3.z；不能顺手把整条 foot trajectory clamp 到地形上方。

2.2 明确禁止的逻辑

  • 禁止 candidate endpoint search、ring search、nearby-cell lookup、fixed-offset touchdown selection。
  • 禁止 repair main path，包括 touchdown semantic repair、FK body-leg repair、contact suppress 作为主路径修正。
  • 禁止 semantic / low-small / risky row gate 改变 delta、清零 delta、放大 delta 或替换 delta。
  • 禁止 foot_pos.z = max(foot_pos.z, terrain_z) 这类 decode 硬抬足端。
  • 禁止 low-small swing z lower/upper hard cap。
  • 禁止 root z readback 和 high semantic obstacle root z += 0.06。
  • 禁止用 foot_pos = fk_foot 条件覆盖 planned foot 来掩盖 IK/FK 不一致。
  • 禁止为了过测试把 qp_iterations 增加到 4 或更多。

3. 求解器总体方案

新 mpc_qp 采用固定形状 batched least-squares / QP-style step。每轮 iteration 在当前轨迹附近构造 residual 和局部 Jacobian，解一个阻尼最小二乘问题：

min_delta || W * (J delta + r) ||^2 + ||lambda * delta||^2

A = J^T W^T W J + lambda I
b = -J^T W^T W r
delta = solve(A, b)
x_new = x_old + delta

这相当于 Gauss-Newton / Levenberg-Marquardt 风格的 SQP/RTI 单步近似。所有 env 使用相同变量结构、相同 residual 结构、相同采样数量，避免动态分支和大规模 pairwise tensor。

4. 优化变量

4.1 Foot Bezier 控制变量

foot_control_w: [B, 4 legs, 4 control points, 3]

P0: 当前足端边界，不优化
P1: 优化 xyz
P2: 优化 xyz
P3: 优化 xy，z 由 height_at(P3.xy) 绑定

foot 仍使用 Bezier，因为用户关心“优化整条轨迹，然后从轨迹里面取点”，而不是离散修点。

4.2 MPC-style 低维 root 参数

root 不再使用每一帧完全自由的 [H, 3] 变量。新方案参考老 mpc：先生成 nominal root 轨迹，再用低维 smooth basis 优化 correction。

root_xy(t)  = nominal_root_xy(t)  + basis(t) @ root_xy_delta
root_z(t)   = mpc_root_z(t)       + basis(t) @ root_z_delta
root_rpy(t) = nominal_root_rpy(t) + basis(t) @ root_rpy_delta

平地时只保留唯一 gate：

if plane_row:
    root_z(t) = mpc_plane_root_z

非平地时 root z 可通过低维 correction 与 foot、IK/FK、reachability residual 联合优化。不能再按 semantic、low-small 或 risky terrain 切换 root 行为。

5. Residual 设计

所有安全和质量要求都进入 residual。任何测试失败都必须从这里调，不允许新增硬约束。

Residual作用依赖变量
semantic touchdown 惩罚 P3 落在语义物体或 footprint 语义风险区域。 P3.xy
touchdown roughness 惩罚 P3 footprint 高程变化过大，避免踩坡度突变处。 P3.xy
swing terrain clearance 惩罚 swing 采样点低于地形和安全 margin。删除 decode clamp 后由该项保证不穿地。 P1/P2/root/rpy
semantic swing / low-small crossing 在轨迹附近存在小障碍时，通过 residual 鼓励 FK/planned foot 具备足够 clearance，不能手工改 P1/P2/P3。 P1/P2/P3/root/rpy
FK readback 惩罚 fk_foot_w - planned_foot_w，保证可视化和真实执行足端与规划轨迹一致。 foot controls、root、rpy
joint limit 使用 unclamped IK 检查关节上下界，不能靠 IK clamp 隐藏不可达。 foot controls、root、rpy
reachability 约束 hip-to-foot 距离在可达范围内，让 root 和 foot 联合移动，而不是 foot 独自追语义目标。 foot controls、root、rpy
joint smooth 惩罚关节一阶、二阶差分，避免足端可达但关节快速抖动。 foot controls、root、rpy
root smooth / root height 非平地控制 root 高度和加速度；平地 root z 直接锁 MPC 高度。 root low-dim params
nominal / progress 弱约束，不要离 nominal 过远；速度跟踪优先级低于语义、高程、FK、连续性。 foot controls、root、rpy

6. FK 可视化合同

viewer 显示的足端轨迹应是 FK 后的实际足端轨迹，因为这是机器人关节执行后真正会到达的位置。

但禁止用 FK foot 条件覆盖 planned foot 来掩盖优化误差。正确合同是：

planned_foot_w = Bezier(root, foot_controls) 采样得到
joint_angles   = IK(root, planned_foot_w)
fk_foot_w      = FK(root, joint_angles)

loss/residual += ||fk_foot_w - planned_foot_w||^2
viewer foot    = fk_foot_w
metrics        = ||fk_foot_w - planned_foot_w||

不增加 planned-vs-FK overlay。planned 和 FK 的重合只通过测试指标覆盖。

7. QP iteration 预算

固定预算：qp_iterations 默认是 3，且 3 是质量预算上限。后续调参只能减少到 2 或 1，不能为了通过测试增加到 4、5 或更多。
  • 验收主配置：qp_iterations = 3。
  • 速度 sweep 可测试 2 和 1。
  • 代码应对 qp_iterations > 3 报错，而不是静默 clamp。
  • 如果 3 次不通过，说明 residual、权重、damping、变量缩放、采样或 conditioning 不对。

8. 性能与显存策略

  • 所有变量和 residual 固定形状，初始化时准备固定采样基、offset、索引、权重模板。
  • 优化过程中只查询 height / semantic / risk fields，不构建动态候选集。
  • 禁止构建 [B, K, 22500, ...] 这类 dense semantic pairwise tensor。
  • 第一版使用 batched dense least-squares，小变量维度优先；如果 1024 env 压力过大，再做 block / Schur / diagonal LM 近似，但不能加 gate。
  • viewer 和训练使用同一 iteration 上限，避免 viewer 靠更多迭代调出训练里不可复现的轨迹。

9. 测试指标

9.1 结构指标

  • 源码/行为测试确认没有 candidate、search、repair main path。
  • 源码/行为测试确认没有 semantic / low-small / risky gate 改 delta。
  • 确认 plane_row 只影响 root z，不影响 root xy 和 foot update。
  • 确认 P3.z 绑定 height_at(P3.xy)。
  • 确认不存在 foot z terrain clamp、low-small z hard cap、root readback、high semantic root lift、conditional FK replacement。
  • qp_iterations > 3 必须报错。

9.2 FK / planned-foot 重合指标

  • max_fk_planned_foot_error_m <= 0.03。
  • mean_fk_planned_foot_error_m <= 0.01。
  • terminal_fk_planned_foot_error_m <= 0.02。
  • small obstacle crossing 可设置 crossing_max_fk_planned_foot_error_m <= 0.05。

9.3 语义与高程安全指标

  • touchdown_on_semantic_count == 0。
  • touchdown_on_small_count == 0。
  • stance_on_semantic_count == 0。
  • fk_foot_semantic_collision_count == 0。
  • fk_knee_semantic_collision_count == 0。
  • fk_shank_semantic_collision_count == 0。
  • root_underbody_semantic_collision_count == 0。
  • planned_foot_terrain_penetration_max_m <= 0.005。
  • fk_foot_terrain_penetration_max_m <= 0.005。
  • touchdown_footprint_height_variation_max_m <= 0.04。

9.4 平地稳定与 small obstacles

  • flat no obstacle：root z range、step、accel 对齐老 mpc。
  • flat root xy 不硬锁，但 root_xy_step_max 和 root_xy_accel_max 应接近 MPC baseline。
  • flat small obstacle：至少出现 required crossing leg，语义碰撞和 touchdown-on-small 均为 0。
  • flat small obstacle：root z 不能因为小障碍抬升；foot clearance 不能过低也不能飞太高。
  • off-path semantic：语义物体不在路径上时，root/foot/joint 连续性应接近 no-semantic baseline。

9.5 row 8 col 12 与性能

  • --terrain-row 8 --terrain-col 12 用 qp_iterations=3 作为 hard terrain acceptance。
  • 该场景要求无语义碰撞、无 touchdown-on-semantic、FK/planned 重合达标、root/joint/foot 连续。
  • 1024 env smoke 不 OOM，记录 CUDA memory、qp_solve_ms、qp_total_ms 的 p50/p95/max。
  • 性能目标先按当前 mpc_qp baseline 附近验收；若 fixed-shape LS-QP 更快，再收紧。

10. 失败处理规则

任何指标失败时，只允许以下处理：

  • 调整 residual 定义、权重和归一化。
  • 调整 damping、变量 scaling、trust region 的统一数值稳定参数。
  • 调整固定采样密度和 field 查询精度。
  • 减少不合理的变量自由度，例如 root basis 维度，而不是加场景 gate。
  • 在质量已达标后减少 qp_iterations 到 2 或 1 以优化速度。

明确禁止以下处理：

  • 新增硬约束、repair、candidate search。
  • 新增 semantic / low-small / risky terrain 条件 gate。
  • 通过 decode 覆盖 planned foot 或 root 高度。
  • 增加 qp_iterations 超过 3。

11. 与当前实现的迁移边界

  • 保留 mpc_qp package 与 backend selection，不修改默认 mpc。
  • 保留 viewer/manager 的 backend ABI 和 cache 输出 ABI。
  • 替换 continuous_qp_update() 当前 autograd-gradient step 为 fixed-shape least-squares step。
  • 重写 decode，使其只做 Bezier 采样、P3.z 地形绑定、IK/FK 输出和 result 组装。
  • 新增 planned-vs-FK 指标，但不增加 viewer overlay。
验收一句话：在 qp_iterations=3 内，mpc_qp 必须通过 flat small obstacles、flat root stability、FK/planned 重合、语义/高程安全和 row 8 col 12 基础验收；所有失败都回到 residual 和数值求解器本身解决。
