Go2 线性椭圆碰撞体设计

日期：2026-07-27 · 分支：Parallelism · 范围：仅 parallelism foot planner 的 collision boundary
核心设计：Go2 腿部碰撞体不再使用当前粗糙的 knee -> foot 直线 calf。新的碰撞边界用可配置的线性变截面椭圆体表示：每个 section 沿线性区间放置若干椭圆中心点，每个中心点用该处椭圆边界到高程图的距离判断是否碰撞。所有参数进入 ParallelismCfg，所有检查保持 torch/GPU 并行。

1. 范围

本设计只修改 extension/parallelism 的碰撞边界和诊断，不修改 root rollout、score、semantic filter、landing filter、IK、gait timing，也不修改任何 joint_mpc_rti 代码。

目标是在平地和后续语义高程图中，用更贴近 Go2 USD 的腿部几何描述，避免当前 calf 误杀所有候选点，同时仍然适合每轮 200 个 foothold candidates 的 GPU 暴力并行搜索。

2. Go2 USD 参考

Go2 资产路径：

{ISAACLAB_NUCLEUS_DIR}/Robots/Unitree/Go2/go2.usd

USD collision 结构里，FL 腿对应的关键 primitive 是：

/go2_description/FL_thigh/collisions/mesh_0 : Cube
/go2_description/FL_calf/collisions/mesh_0  : Cylinder
/go2_description/FL_calf/collisions/mesh_1  : Cylinder
/go2_description/FL_calf/collisions/mesh_2  : Cylinder
/go2_description/FL_foot/collisions/mesh_0  : Sphere

foot 是独立 rigid body，通过 fixed joint 接到 calf 末端：

/go2_description/FL_calf/FL_foot_joint
physics:localPos0 = (0, 0, -0.213)

因此 calf 不能再建模成一根直接到 foot contact 点的直线；foot 必须从 calf collision 中分离。

3. 碰撞体总结构

每条腿分成三个类：

ThighCollision
CalfCollision
FootCollision

每个类下面由若干个 LinearEllipseSection 表示：

ThighCollision:
  thigh_main

CalfCollision:
  calf_upper
  calf_lower
  calf_end

FootCollision:
  foot_pad

一条腿一共 5 个 section。每个 section 是一段线性变化的椭圆截面序列。

4. LinearEllipseSection 参数

每个 section 的参数全部进入 config：

radius_a
radius_b
start_pos_l
delta_pos_l
center_count
radius_scale_k
radius_scale_b
参数含义
radius_a椭圆长轴基础半径
radius_b椭圆短轴基础半径
start_pos_lsection 起始位置，定义在对应 link local frame 下
delta_pos_l线性变化区间，end = start + delta
center_count该 section 上椭圆中心点数量
radius_scale_k截面边界线性变化斜率
radius_scale_b截面边界线性变化截距

第 i 个椭圆中心：

t = i / (center_count - 1)
center_l(t) = start_pos_l + t * delta_pos_l
scale(t) = radius_scale_k * t + radius_scale_b
radius_a(t) = radius_a * scale(t)
radius_b(t) = radius_b * scale(t)

当 center_count == 1 时，t = 0。

如果 radius_scale_k = 0 且 radius_scale_b = 1，该 section 的截面大小不变化。如果 radius_scale_k > 0，沿区间方向变粗；如果 radius_scale_k < 0，沿区间方向变细。

5. 碰撞检测语义

每个椭圆中心都检查。对每个 candidate、leg、section、center：

center_w = link_frame_w @ center_l
terrain_p = (center_w.x, center_w.y, height_map(center_w.x, center_w.y))
clearance = center_w.z - terrain_p.z

该中心处的椭圆边界半径取竖直方向上的边界距离：

r = ellipse_vertical_radius(radius_a(t), radius_b(t), section_orientation_w)

碰撞-free 条件：

ok = clearance >= r + collision_margin_m

也就是用户定义的距离语义：

||center_w - terrain_p|| >= ellipse_boundary_radius(center_w -> terrain_p) + collision_margin_m

由于 terrain point 和 center 的 x, y 相同，实际实现不用三维 sqrt，直接用 center_z - terrain_h 做标量比较，等价且更快。

section 内所有中心点都必须通过：

section_ok = all(center_ok)

非 foot 腿部碰撞聚合：

leg_collision_ok = thigh_main_ok & calf_upper_ok & calf_lower_ok & calf_end_ok

foot 独立处理，不混进 calf collision。正常 touchdown 由 landing_ok 控制，是否踩到语义障碍物由 semantic filter 控制。

7. Config 可调性

所有 section 参数必须放入 ParallelismCfg 或其嵌套 dataclass。未来调参方式：

增加检查点

调大 *_center_count。代码会自动在对应 section 的 start_pos_l -> start_pos_l + delta_pos_l 区间内增加椭圆中心。

调整粗细

修改 *_radius_a 和 *_radius_b。

调整变粗/变细趋势

修改 *_radius_scale_k 和 *_radius_scale_b。

调整位置和方向

修改 *_start_pos_l 和 *_delta_pos_l。

planner 内不应保留隐藏的 hard-coded collision boundary。

8. GPU 并行数据流

运行时将所有 section 参数打平成 tensor：

section_radius_a: [S]
section_radius_b: [S]
section_start_pos_l: [S, 3]
section_delta_pos_l: [S, 3]
section_center_count: [S]
section_radius_scale_k: [S]
section_radius_scale_b: [S]
section_class_id: [S]

其中 S = 5，分别为 thigh_main、calf_upper、calf_lower、calf_end、foot_pad。

并行展开维度：

[batch, leg, candidate, section, center]

所有中心点一次性 query height map，并用 torch 条件判断生成 collision mask。

9. 诊断输出

viewer 和 planner diagnostics 应输出每个 section 的碰撞计数：

collision_detail(
  thigh_main=...
  calf_upper=...
  calf_lower=...
  calf_end=...
  foot_pad=...
)

输出每个 section 的中心点数量：

collision_centers(
  thigh_main=3
  calf_upper=3
  calf_lower=3
  calf_end=2
  foot_pad=1
)

可选输出 scale 范围：

collision_scale(
  calf_lower=0.95->1.05
  calf_end=0.90->1.10
)

10. IsaacLab 验收测试

真实 IsaacLab 测试必须使用 parallelism backend 并给非零速度，例如：

--planner-backend parallelism
--scripted-command "0.5 0.0 0.0"
--scripted-command-cycles 3

如果 IsaacLab 初始状态让机器人漂在空中，测试必须先使用 viewer 的 R 键 grounded reset 等价逻辑，把机器人贴到地面，然后 refresh scanner/height map，再发送速度。

验收流程：

1. 启动 parallelism viewer/backend。
2. 如果机器人初始漂浮，执行 grounded reset。
3. refresh scanner/height map。
4. 发送非零速度。
5. 验证 flat terrain 下 planner 不再 standstill。
6. 验证 replay horizon 内 root displacement 非零。
7. 验证 collision diagnostics 是 section-based，而不是 legacy calf-only。

成功标准：

valid candidate count > 0
standstill=False
root delta != 0
collision_detail 不再被误导为 calf 整体碰撞

11. 非目标

  • 不引入 root search。
  • 不改 score。
  • 不改 semantic filter 语义。
  • 不改 landing filter。
  • 不接入梯度 terrain query。
  • 不做 triangle mesh collision 或 SDF collision。
  • 不修改 joint_mpc_rti。
实现提醒：当前分支上已有未提交的实验性 calf clearance 调参改动。正式实现本设计时，应以本 spec 为准重写 collision boundary，而不是继续沿用旧的 calf_radius_m 调参方案。
