Parallelism RL Reference 时序设计

日期：2026-08-04　分支：Parallelism-flat-rl
目标：让 policy 在动作执行前看到下一帧 Parallelism 关节目标，同时让速度 reference 使用当前帧到下一帧的差分；奖励、termination、metric 和 curriculum 使用同一套时间戳。Parallelism 仍然每次生成 24 帧，不访问不存在的第 24 帧。

一、范围与不变项

本设计只修改 RL 接口读取 reference 的时间戳，不修改 Parallelism planner 的规划逻辑。

项目处理方式
Policy action保持完整 12 维 action
IsaacLab 关节目标default_joint_pos + 0.25 * policy_action
Reward 公式不改公式、权重、范数和聚合方式
Metric不改误差实现、mean/max 和累计逻辑
Parallelism horizon保持 24 帧，索引为 0 到 23
Planner reset/replan与新的 22 帧结束边界对齐

二、参考轨迹与第 0 帧

每次 reset 或重新规划时，从 IsaacLab 读取当前 Go2 的真实状态并生成新轨迹：

reference_new[0] = 当前 IsaacLab 真实状态
reference_new[1...23] = Parallelism 规划出的后续轨迹

第 0 帧包含并对齐：

  • root 世界坐标位置；
  • root 姿态；
  • 12 个关节角；
  • 四个足端世界坐标位置。
第 0 帧不是 Policy 的直接目标输入。 它是新轨迹的真实状态锚点，并用于计算第一步的速度： (reference_new[1] - reference_new[0]) / dt。

三、普通控制周期

设当前控制周期开始时，真实状态是 actual[t]，Parallelism 当前帧是 reference[t]。

当前时刻：
  actual[t]
  reference[t]
  reference[t+1]

Policy 输入：
  joint position = reference[t+1]
  joint velocity = (reference[t+1] - reference[t]) / dt
  root velocity  = (reference[t+1] - reference[t]) / dt

Policy 输出：
  action[t]

IsaacSim 执行：
  actual[t] -> actual[t+1]

root 线速度和角速度沿用当前 policy root 坐标系转换规则，只改变差分使用的 reference 帧。

四、Reward、Termination 与 Metric

4.1 Position reward

actual_joint[t+1] vs reference_joint[t+1]
actual_foot[t+1]  vs reference_foot[t+1]

当前代码在物理推进后计算 reward，因此执行后的 reference 目标帧为 t+1。

4.2 Velocity reward

actual velocity[t -> t+1]
vs
reference velocity[t -> t+1]

reference velocity[t -> t+1]
  = (reference[t+1] - reference[t]) / dt

速度 reference 在动作执行前确定并保存，避免物理推进后 phase 变化导致误读成 t+1 -> t+2。

4.3 Termination

actual_joint[t+1]      vs reference_joint[t+1]
actual_foot[t+1]       vs reference_foot[t+1]
actual_root[t+1]       vs reference_root[t+1]
actual_gravity[t+1]    vs reference_gravity[t+1]

termination 的判断公式不变，只保证读取动作对应的目标帧。

4.4 Metric

metric 使用与 reward 相同的时间戳：

joint / foot position：
  actual[t+1] vs reference[t+1]

root / joint velocity：
  actual velocity[t -> t+1]
  vs reference velocity[t -> t+1]

不修改 metric 内部的误差计算、mean/max、缓存、episode 累计或输出名称。

五、24 帧边界与重规划

轨迹帧索引为 0...23。不访问 reference[24]，也不跨旧轨迹和新轨迹做差分。

5.1 最后一段有效控制

当当前帧为 t=22：

Policy 输入：
  position = reference[23]
  velocity = reference[23] - reference[22]

执行：
  actual[22] -> actual[23]

这一步完成旧轨迹的最后一个有效控制区间。

5.2 重规划触发点

动作 22 -> 23 执行完成后：

1. 使用旧轨迹 reference[23] 计算最后一次 reward、termination 和 metric
2. 读取当前 IsaacLab 真实状态 actual[23]
3. 生成 reference_new[0...23]
4. 设置新轨迹 phase = 0

因此重规划发生在旧轨迹第 22 帧动作完成之后，而不是动作执行前。

5.3 新轨迹第一步

reference_new[0] = actual[23]

下一次 Policy 输入：
  joint position = reference_new[1]
  joint velocity = (reference_new[1] - reference_new[0]) / dt
  root velocity  = (reference_new[1] - reference_new[0]) / dt

执行：
  actual[23] -> actual_new[1]
新轨迹的第 0 帧只作为真实状态锚点，Policy 直接输入新轨迹第 1 帧。 不使用旧轨迹第 23 帧到新轨迹第 0 帧的差分。

六、Reset 对齐

环境 reset 与重新规划采用同样的接口：

IsaacLab reset
    ↓
读取 reset 后的真实 Go2 状态
    ↓
生成 reference[0...23]
    ↓
phase = 0
    ↓
Policy 首次输入 reference[1]

首次速度 reference 使用：

(reference[1] - reference[0]) / dt

这样 reference 第 0 帧不会与 reset 后的真实机器人状态发生跳变。

七、Termination 放宽方案

训练目标是覆盖全部速度命令并学习完整走路轨迹。训练初期不能因为 tracking 暂时误差大而频繁 reset。

保留真实物理失稳相关 termination：

  • time_out；
  • base_contact；
  • bad_orientation。

Parallelism reference tracking termination 第一阶段放宽为：

Termination第一阶段阈值
root z error0.50 m
projected gravity error1.50
foot z error0.30 m
joint position max error2.00 rad

放宽 termination 只减少早期 reset，不修改 reward 和 metric。

八、Curriculum 阈值

Curriculum 仍然使用完整 episode 的 tracking metric，不改变升级逻辑，只放宽两个关键门槛：

参数原值新值单位
joint_max_threshold0.451.0rad
ang_vel_threshold0.351.0rad/s

其他 curriculum 指标、速度范围、升级方式和 episode metric 不变。

课程升级仍要求 episode 完成 timeout，且不发生真实物理 termination。

九、训练输出目录

每次训练使用当前 Git HEAD 的 short hash 建立版本目录：

logs/rsl_rl/<experiment>/<日期时间>/<git_short_hash>/

示例：

logs/rsl_rl/parallelism_tracking_flat/2026-08-04_15-30-00/a1b2c3d/

目录内直接保存模型和训练参数，不再生成 tag.txt，也不处理 dirty/clean 状态。

十、最终时序摘要

当前控制帧 t：

Policy observation：
  q_ref[t+1]
  v_ref[t -> t+1]
  root_v_ref[t -> t+1]

Policy action：
  完整 12 维 action[t]

IsaacSim：
  actual[t] -> actual[t+1]

Reward / Termination / Metric：
  position：actual[t+1] vs reference[t+1]
  velocity：actual[t -> t+1] vs reference[t -> t+1]

t=22 动作完成：
  计算旧轨迹最后一次结果
  读取 actual[23]
  生成 reference_new[0...23]

下一次 Policy：
  输入 reference_new[1]
  速度使用 reference_new[0] -> reference_new[1]
