Parallelism Large Obstacles Distillation RL 设计

日期：2026-08-14　 分支：parallelism-large-obstacles-distillation-rl　 目标 experiment：parallelism_tracking_cross_large_complex_distillation

1. 目标

在当前 parallelism_tracking_cross_large_complex teacher RL 任务基础上， 新建一个教师-学生蒸馏任务。teacher 网络使用完整 privileged 信息，包括 Parallelism 规划出的 reference trajectory；student 网络不输入 reference trajectory，只输入速度命令、 本体状态和高程/语义图，并学习 teacher 输出的 action。

训练完成后，部署或 play 时使用 student policy。student 不依赖 parallelism_ref_joint_pos、parallelism_ref_joint_vel、 parallelism_ref_root_pos 和 parallelism_ref_root_rot 作为策略输入。

新任务只新增教师-学生配置和 student 网络；原来的 parallelism_tracking_cross_large_complex 继续作为 teacher/PPO 训练配置，不改变其行为。

2. RSL-RL 接口结论

当前环境中的 RSL-RL 已经有 Distillation 和 StudentTeacher 逻辑。 它的核心约定是： 

student_obs = obs
teacher_obs = extras["observations"]["teacher"]

student_action = student(student_obs)
teacher_action = teacher(teacher_obs)
loss = MSE(student_action, teacher_action) 或 Huber(student_action, teacher_action)

但是当前 Go2Pvcnn teacher 使用的是项目内扩展的 ActorCriticCNN，而默认 StudentTeacher 是 MLP，不能直接加载现有 CNN teacher checkpoint。因此本设计不升级整套 RSL-RL，而是在项目内补齐 CNN 版本的 student-teacher 模块和 distillation 配置。

重要边界：不把 teacher 的 reference observation 暴露给 student。teacher 只在训练时产生监督 action； 环境执行的是 student action。

5. Observation 分组

5.1 Teacher observation

teacher observation 等价于当前 large/complex PPO teacher 的 policy observation。 它包含 reference trajectory，用来让 teacher 产生高质量动作。

组内容
teacher_elevation_semantic_map 高程/语义图，结构与当前 policy_elevation_semantic_map 一致。
teacher_state 本体状态、历史 action，以及 parallelism_ref_* reference observation；不额外加入 velocity_commands，以兼容已有 PPO teacher checkpoint 的输入维度。

5.2 Student observation

student observation 不能包含任何 reference trajectory。它保留 terrain 感知和机器人本体信息， 让学生能在没有 reference 的情况下根据速度和地形输出动作。

组保留删除
student_elevation_semantic_map 高程/语义图 无
student_state base velocity、projected gravity、joint pos、joint vel、previous actions、velocity command parallelism_ref_joint_pos、parallelism_ref_joint_vel、parallelism_ref_root_pos、parallelism_ref_root_rot

6. 训练数据流

IsaacLab env observation
  ↓
flatten student groups
  → obs
  → 输入 student

flatten teacher groups
  → extras["observations"]["teacher"]
  → 输入 frozen teacher

student action
  ↓
env.step(student action)

teacher action
  ↓
只用于 distillation loss，不直接控制机器人

每个训练 step 的监督目标：

teacher_action_t = Teacher(teacher_obs_t)
student_action_t = Student(student_obs_t)
loss_t = mean((student_action_t - teacher_action_t)^2)

初版采用 action-level behavior cloning，不引入 PPO reward 混合训练。这样可以明确判断学生是否能复刻 teacher。 后续若 student 已经接近 teacher，再考虑 PPO fine-tune。

7. StudentTeacherCNN 网络

StudentTeacherCNN 包含两个子网络：

  • teacher：CNN + MLP，输入完整 teacher obs，输出 12 维 action。
  • student：CNN + MLP，输入去 reference 后的 student obs，输出 12 维 action。

teacher 权重加载规则：

如果 checkpoint 来自 PPO ActorCriticCNN:
  读取 model_state_dict
  取出 actor 相关权重
  加载到 StudentTeacherCNN.teacher
  不加载 critic
  teacher.eval()
  teacher.requires_grad_(False)

如果 checkpoint 来自 distillation:
  同时恢复 student 和 teacher
  用于 resume distillation training

student 初始化规则：

  • 新训练时随机初始化；
  • resume distillation 时从 checkpoint 恢复；
  • 不从 teacher 强行拷贝前几层，因为 student 输入维度少于 teacher。

8. 训练配置

新增 experiment：

parallelism_tracking_cross_large_complex_distillation

训练配置核心字段：

{
  "algorithm": {
    "class_name": "Distillation",
    "num_learning_epochs": 5,
    "gradient_length": 15,
    "learning_rate": 1e-3,
    "loss_type": "mse"
  },
  "policy": {
    "class_name": "StudentTeacherCNN",
    "student_hidden_dims": [256, 128],
    "teacher_hidden_dims": [256, 128],
    "activation": "elu",
    "cost_map_channels": 2,
    "cost_map_size": 16
  },
  "obs_groups": {
    "student": ["student_elevation_semantic_map", "student_state"],
    "teacher": ["teacher_elevation_semantic_map", "teacher_state"]
  }
}

训练脚本新增显式参数 --teacher_checkpoint。它只用于加载 frozen teacher，不代表 resume student。 student 的 resume 仍然使用现有 --resume、--load_run 和 --load_checkpoint。

9. Play 设计

play distillation checkpoint 时默认使用 student：

load distillation checkpoint
  ↓
runner.get_inference_policy()
  ↓
返回 student.act_inference
  ↓
wrapper 只构造 student observation
  ↓
env.step(student action)

play 时可以继续创建 reference manager 和 reference robot 作为 debug 可视化， 但 reference trajectory 不进入 student policy 输入。

11. 错误处理

  • 如果 --teacher_checkpoint 缺失，distillation 训练直接报错，不允许随机 teacher。
  • 如果 teacher checkpoint 不是 PPO actor 或 distillation checkpoint，报错并打印缺失 key。
  • 如果 teacher/student observation 维度为 0 或 action 维度不一致，初始化时报错。
  • 如果 reference manager 生成 standstill，仍按当前环境逻辑处理；teacher 会对当前 observation 输出动作。
  • 如果 student resume checkpoint 与当前 observation 维度不一致，报错，不自动跳过权重。

12. 测试要求

测试要求
静态配置测试 确认新 experiment 注册、继承 large/complex terrain、保留 termination/reward/curriculum。
observation 测试 确认 student obs 不含任何 parallelism_ref_*，teacher obs 含完整 reference。
checkpoint 加载测试 用已有 PPO ActorCriticCNN checkpoint 加载 teacher，确认 teacher loaded 且 frozen。
distillation smoke 测试 启动 1024 环境 headless，跑 4 iterations，确认 Loss/behavior 有输出且 iteration 增加。
play 测试 加载 distillation checkpoint，确认实际控制 action 来自 student，并且无需 reference observation 输入。
