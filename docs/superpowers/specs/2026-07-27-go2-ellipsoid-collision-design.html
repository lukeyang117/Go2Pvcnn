Go2 椭圆体碰撞体设计

日期：2026-07-27 · 分支：Parallelism · 范围：仅 parallelism foot planner 的 collision boundary
核心设计：Go2 腿部碰撞边界不再使用 knee -> foot 直线胶囊，也不使用线性椭圆截面。新的边界由一组固定椭圆体拟合 visual mesh：每个椭圆体挂在对应刚体的 local frame 下，参数只有中心位置、三个半径、heightmap 查询偏差。碰撞检查为“高程图表面点是否进入椭圆体内部”，并保持 torch/GPU 并行。

1. 范围

本设计只修改 extension/parallelism 的碰撞边界和诊断，不修改 root rollout、score、semantic filter、landing filter、IK、gait timing，也不修改任何 joint_mpc_rti 代码。

目标是在平地和后续语义高程图中，用更贴近 Go2 visual mesh 的腿部几何描述，避免当前 calf 被粗糙直线胶囊误判为大量碰撞，同时仍然适合每轮 200 个 foothold candidates 的 GPU 暴力并行搜索。

2. Go2 mesh 参考

Go2 资产路径：

{ISAACLAB_NUCLEUS_DIR}/Robots/Unitree/Go2/go2.usd

USD collision primitive 可作为尺度参考，但本设计优先参考 visual mesh 外形定默认椭圆体。FL 腿 collision primitive 的粗略结构是：

/go2_description/FL_thigh/collisions/mesh_0 : Cube
/go2_description/FL_calf/collisions/mesh_0  : Cylinder
/go2_description/FL_calf/collisions/mesh_1  : Cylinder
/go2_description/FL_calf/collisions/mesh_2  : Cylinder
/go2_description/FL_foot/collisions/mesh_0  : Sphere

foot 是独立 rigid body，通过 fixed joint 接到 calf 末端：

/go2_description/FL_calf/FL_foot_joint
physics:localPos0 = (0, 0, -0.213)

因此 calf 不能建模成一根直接到 foot contact 点的直线；thigh、calf、foot 必须使用各自对应的刚体坐标系。

3. 碰撞体结构

每条腿分成三个类，每个类下面直接放若干个固定椭圆体：

ThighCollision:
  thigh_body_inner
  thigh_body_mid
  thigh_body_outer
  thigh_outer_cap

CalfCollision:
  calf_knee_cap
  calf_upper_bar
  calf_mid_bar
  calf_lower_bar
  calf_ankle_cap

FootCollision:
  foot_pad

一条腿一共 10 个椭圆体，四条腿一共 40 个椭圆体。椭圆体不是运行时采样点，而是一开始就在 config 中建好的 collision primitive。

4. Ellipsoid 参数

每个椭圆体参数全部进入 config：

name
link_type
center_l
radii_l
probe_offset_l
参数含义
name诊断名，必须稳定输出到 viewer diagnostics。
link_typethigh、calf 或 foot，决定该椭圆体使用哪个刚体 frame。
center_l椭圆体中心，定义在对应 link local frame 下，单位米。
radii_l椭圆体在 link local frame 三个轴向上的半径 (rx, ry, rz)，单位米。
probe_offset_lheightmap 查询偏差 (ox, oy)，定义在 link local frame 的局部 xy 平面内，单位米。

第一版不加椭圆体自身旋转，椭圆体轴向跟随对应 link frame。后续如果 visual mesh 的局部斜向形状必须更精确，可以新增 rot_l，但不进入第一版。

4.1 Link local frame 语义

center_l 和 probe_offset_l 都不是 IsaacLab 直接读出来的关节坐标，也不是在 world frame 下的固定点。它们是相对某个刚体 frame 的固定局部偏移。

joint_pos_from_isaaclab / candidate_ik_joint
  -> FK
  -> thigh/calf/foot link pose
  -> link_pose_w @ center_l
  -> ellipsoid center in world

对 viewer 当前状态，关节角来自 IsaacLab robot state；对每个 foothold candidate，关节角来自该 candidate 的 IK 结果。两者都必须先通过 parallelism 自己的 FK 得到 thigh_link_pose_w、calf_link_pose_w、foot_link_pose_w，然后再叠加椭圆体局部偏移。

center_w = link_pos_w + link_rot_w @ center_l

因此完整位置不是“关节坐标 + 椭圆体偏移”，而是“由 root pose 和 joint position 通过 FK 算出对应刚体坐标系，再把椭圆体局部偏移变换到 world”。

4.2 刚体 frame 映射

每个椭圆体必须挂到与它 mesh 部位一致的刚体 frame。planner 内部腿顺序为 FL, FR, RL, RR，对应 Go2 link 名称如下：

planner legThighCollision frameCalfCollision frameFootCollision frame
FLFL_thighFL_calfFL_foot
FRFR_thighFR_calfFR_foot
RLRL_thighRL_calfRL_foot
RRRR_thighRR_calfRR_foot

绑定规则：

thigh_* ellipsoids -> same-leg *_thigh link frame
calf_* ellipsoids  -> same-leg *_calf link frame
foot_* ellipsoids  -> same-leg *_foot link frame

实现时不能用 hip 点、knee 点、foot contact 点替代这些刚体 frame。hip/knee/foot 关键点可以继续用于 IK/FK 几何求解，但椭圆体碰撞体必须使用对应 link 的刚体位姿。

如果 parallelism FK 当前只返回 hip、knee、foot 点而没有 link pose，本任务需要补足内部 FK 输出：至少返回每条腿的 thigh_pos_w/thigh_rot_w、calf_pos_w/calf_rot_w、foot_pos_w/foot_rot_w。这些 pose 由 root pose 和 candidate joint angles 计算，不能从 viewer 的 body state 直接拷贝到 candidate 上。

foot_pad:
  center_l = (-0.002, 0.000, 0.000)
  radii_l = (0.026, 0.024, 0.022)
  probe_offset_l = (0.020, 0.018)

6. 碰撞检测逻辑

碰撞检查必须使用椭圆体对应刚体的坐标系。不能在 world frame 里直接按固定长短轴判断，因为椭圆体会跟随 thigh、calf、foot 刚体运动和旋转。

6.1 单个椭圆体检查

对某个 candidate、某条腿、某个椭圆体：

ellipsoid:
  center_l = (cx, cy, cz)
  radii_l = (rx, ry, rz)
  probe_offset_l = (ox, oy)

link pose:
  link_pos_w
  link_rot_w

先在 link local frame 下构造 5 个 heightmap 查询 anchor：

probe_l = [
  center_l + (0,   0,   0),
  center_l + ( ox, 0,   0),
  center_l + (-ox, 0,   0),
  center_l + (0,   oy,  0),
  center_l + (0,  -oy,  0),
]

再把这 5 个 anchor 变换到 world frame，用它们的 xy 查询高程图：

probe_w = link_pos_w + link_rot_w @ probe_l
terrain_h = height_map(probe_w.x, probe_w.y)
terrain_p_w = (probe_w.x, probe_w.y, terrain_h)

然后把高程图表面点变回同一个 link local frame：

terrain_p_l = link_rot_w^T @ (terrain_p_w - link_pos_w)

最后在 link local frame 下代入椭圆体隐式方程：

d_l = terrain_p_l - center_l
effective_radii_l = radii_l + collision_margin_m

inside =
  (d_l.x / effective_radii_l.x)^2 +
  (d_l.y / effective_radii_l.y)^2 +
  (d_l.z / effective_radii_l.z)^2 <= 1.0

只要 5 个 probe 对应的高程图表面点有任意一个进入椭圆体，就判该椭圆体碰撞：

ellipsoid_collision = any(inside over 5 probes)

6.2 Candidate 聚合

每个 candidate 需要检查四条腿的所有椭圆体。每个椭圆体的碰撞结果先按名字保留，用于诊断；最终 hard filter 使用任意碰撞即 invalid：

candidate_collision = any(
  ellipsoid_collision
  over checked legs and ellipsoids
)

collision_ok = ~candidate_collision

这里的 checked legs 是 FK 后完整姿态中的四条腿，不只检查正在 swing 的落脚腿。这样可以排除候选点导致 IK/FK 后任意腿部连杆撞到高程图的情况。

6.3 与 landing / semantic filter 的边界

collision filter 只负责“高程图表面点进入腿部椭圆体”。以下逻辑不放进 collision：

candidate 落点是否在 valid map 内
candidate touchdown 是否落到 semantic obstacle
FK touchdown 是否落到 semantic obstacle
FK touchdown 是否贴地
IK 后关节角是否超限
速度跟踪 score

这些仍由已有 valid map、semantic、landing、joint limit、score 各自负责，避免 filter 和 score 混乱。

7. GPU 并行数据流

运行时将所有椭圆体参数打平成 tensor：

ellipsoid_center_l: [E, 3]
ellipsoid_radii_l: [E, 3]
ellipsoid_probe_offset_l: [E, 2]
ellipsoid_link_type: [E]
ellipsoid_name: [E]

其中 E = 10，分别为 4 个 thigh、5 个 calf、1 个 foot 椭圆体。每条腿复用这一套模板，并按 leg side 对需要镜像的局部 y 参数做符号转换。

并行展开维度：

B = num_envs
L = 4 legs
C = 50 candidates per leg
E = 10 ellipsoids per leg
P = 5 probes per ellipsoid

link_pos_w:       [B, L, C, E, 3]
link_rot_w:       [B, L, C, E, 3, 3]
probe_l:          [E, P, 3]
probe_w:          [B, L, C, E, P, 3]
terrain_p_w:      [B, L, C, E, P, 3]
terrain_p_l:      [B, L, C, E, P, 3]
inside:           [B, L, C, E, P]
ellipsoid_hit:    [B, L, C, E]
candidate_hit:    [B, L, C]

所有判断必须使用 torch 条件判断和 reduction，例如 <=、torch.logical_or、torch.any、torch.where。不能用 Python if 对单个 candidate、单个 env、单个 probe 做逐项分支。

7.1 显存控制

1024 个环境时，第一版维度约为：

B = 1024
L = 4
C = 50
E = 10
P = 5

total probe checks = B * L * C * E * P = 10,240,000

如果一次性同时保留 probe_w、terrain_p_w、terrain_p_l、link_rot_w 等大 tensor，collision 本身就可能接近数百 MB，再叠加 FK、IK、terrain query 和 PyTorch 临时 tensor，峰值显存可能明显升高。

实现时不允许为了简单而长期保存所有中间大 tensor。推荐按 link_type 或 ellipsoid chunk 分块计算，并且每块立即 reduce 到命中 mask：

candidate_hit = zeros([B, L, C], dtype=bool)
ellipsoid_hit_diag = zeros([B, L, C, E], dtype=bool)

for group in [thigh_ellipsoids, calf_ellipsoids, foot_ellipsoids]:
  probe_w = compute_probe_world_for_group(...)
  terrain_p_w = query_height_map(probe_w.xy)
  terrain_p_l = world_to_link_for_group(terrain_p_w)
  inside = ellipsoid_equation(terrain_p_l)
  group_hit = torch.any(inside, dim=-1)
  candidate_hit = torch.logical_or(candidate_hit, torch.any(group_hit, dim=-1))
  ellipsoid_hit_diag[..., group_indices] = group_hit
  release large temporaries before next group

这个循环只在椭圆体 group 维度上做小粒度分块，不破坏 env、leg、candidate、probe 的 torch 并行。1024 env 下最大临时张量按 calf 组 E=5 估算，比一次性 E=10 全展开低一半，且不会同时保留多份重复中间量。

如果后续增加椭圆体数量或 probe 数量，必须优先增加 group/chunk 分块，而不是全量展开所有 [B,L,C,E,P,3] 中间张量。

8. Config 可调性

所有椭圆体参数必须放入 ParallelismCfg 或其嵌套 dataclass。planner 内不应保留隐藏的 hard-coded collision boundary。

移动碰撞体

修改 center_l。如果某个诊断名持续误杀，优先检查该椭圆体中心是否偏到 visual mesh 外。

调整包络大小

修改 radii_l。三个半径分别控制 link local frame 下 x、y、z 方向的包络。

调整地形查询范围

修改 probe_offset_l。它只控制 heightmap 查询点位置，不改变椭圆体本身大小。

增加拟合细节

新增一个具名椭圆体。新增后 diagnostics 会按名字暴露该椭圆体的碰撞计数。

9. 诊断输出

viewer 和 planner diagnostics 应输出每个椭圆体的碰撞计数：

collision_detail(
  thigh_body_inner=...
  thigh_body_mid=...
  thigh_body_outer=...
  thigh_outer_cap=...
  calf_knee_cap=...
  calf_upper_bar=...
  calf_mid_bar=...
  calf_lower_bar=...
  calf_ankle_cap=...
  foot_pad=...
)

同时输出椭圆体参数摘要，便于确认调参是否生效：

collision_ellipsoids(
  count=10
  probes=5
  margin=0.003
)

10. IsaacLab 验收测试

真实 IsaacLab 测试必须使用 parallelism backend 并给非零速度，例如：

--planner-backend parallelism
--scripted-command "0.5 0.0 0.0"
--scripted-command-cycles 3

如果 IsaacLab 初始状态让机器人漂在空中，测试必须先使用 viewer 的 R 键 grounded reset 等价逻辑，把机器人贴到地面，然后 refresh scanner/height map，再发送速度。

验收流程：

1. 启动 parallelism viewer/backend。
2. 如果机器人初始漂浮，执行 grounded reset。
3. refresh scanner/height map。
4. 发送非零速度。
5. 验证 flat terrain 下 planner 不再 standstill。
6. 验证 replay horizon 内 root displacement 非零。
7. 验证 collision diagnostics 是 ellipsoid-based，而不是 legacy calf-only。

成功标准：

valid candidate count > 0
standstill=False
root delta != 0
collision_detail 不再被误导为 calf 整体碰撞

11. 非目标

  • 不引入 root search。
  • 不改 score。
  • 不改 semantic filter 语义。
  • 不改 landing filter。
  • 不接入梯度 terrain query。
  • 不做 triangle mesh collision 或 SDF collision。
  • 不修改 joint_mpc_rti。
实现提醒：当前分支上已有未提交的实验性 calf clearance 调参改动。正式实现本设计时，应以本 spec 为准重写 collision boundary，而不是继续沿用旧的 calf_radius_m 调参方案。
