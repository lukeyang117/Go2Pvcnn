Joint MPC RTI Root-Joint 耦合步态与联合指标设计

日期：2026-07-17 ｜ 主线：T302v.7 ｜ 目标路径：Go2Pvcnn/extension/joint_mpc_rti/ ｜ 分支：joint_mpc

继承关系：本设计是 docs/superpowers/specs/2026-07-15-joint-mpc-rti-gpu-design.html、 docs/superpowers/specs/2026-07-16-joint-mpc-rti-joint-order-stance-grounding-design.md 和 docs/superpowers/specs/2026-07-16-joint-mpc-rti-small-obstacle-crossing-design.html 的连续增量。它保留 H16、dt=0.02、fixed trot、真实 x0 注入、只发布 x1、世界坐标单高程图、signed small/large field、连续语义 loss、strict cross、stop-support、全身零碰撞、任意环境数封装和 viewer/PPO 边界；不另起 planner 后端。
对旧设计的明确修正：2026-07-16 stance 设计只把足端残差通过每腿 3x3 joint Jacobian写入 joint block；当前生产 LQ 又使用 root block + 逐关节对角块求解。结果是 root 与关节虽位于同一 state tensor，优化方向仍然解耦。本设计以完整 root-joint FK Jacobian、非零交叉 Hessian和结构化耦合求解覆盖该近似，不允许只提高 stance_xy_lock 权重代替结构修复。

1. 问题证据

64 次 rolling x1、八组平移 command 的量化结果表明：

  • consecutive stance 足沿 command 的平均位移是 root step 的 1.040x。
  • 只有 4.02% 的 stance 样本保持在 1mm/frame 以内。
  • swing 足相对 root 的主动推进平均只有 root progress 的 7.0%，八组命令中六组不超过 10%。
  • root 从第一个 20ms 发布帧按 command 移动；固定相位 joint target 主要负责抬腿，没有 command-conditioned touchdown XY。

因此当前轨迹是 root-driven kinematics：root 先由独立速度积分产生路径，关节围绕这条路径补偿。足端世界运动大部分来自 root 携带，而不是 stance 锚定、swing 主动迈步和 touchdown 支撑切换。

2. 设计目标与非目标

目标

  • scheduled stance 足在世界系成为真正的运动学等式约束。
  • stance residual 同时对 root pose 和对应腿关节产生优化方向。
  • 非零平移 command 下，swing 足具有方向、大小相关的 touchdown lead。
  • 启动时 swing 足主动运动至少领先 root 一个 20ms 发布帧。
  • root 用 horizon progress 跟踪 command，不再逐帧锁死完整命令速度。
  • 每个场景同时检查全部通用 JointMetrics，禁止场景选择性漏检。

非目标

  • 不增加质心动力学、接触力、摩擦锥、关节力矩或执行器模型。
  • 不优化 gait topology、per-leg phase offset 或 swing duration。
  • 不添加 crossable_small、指定跨越腿或固定绕行侧。
  • 不通过发布后 IK snapping、root 修补或轨迹投影掩盖求解器问题。
  • 不在步态行为尚未通过时同时改写 exact signed EDT；性能优化排在联合行为指标通过之后。

5. 优化变量与完整运动学耦合

状态和控制 ABI 保持不变：

x_t = [root_pos_w(3), root_rpy_w(3), joint_pos(12)]
u_t = [root_lin_vel_b(3), root_ang_vel_b(3), joint_vel(12)]

第 l 条腿的世界足端为：

p_foot_l(x) = p_root + R(root_rpy) * p_foot_body_l(q_l)

线性化必须使用完整 Jacobian：

J_foot_l = [
  I_3,                                  # root translation
  -R * skew(p_foot_body_l) * E_rpy,     # root rotation
  0 ... R * J_leg_l ... 0               # corresponding leg joints
]

任一足端 residual 的 GGN 均构造：

g += J_foot_l^T * W * r
H += J_foot_l^T * W * J_foot_l

因此 H[root, joint_l] 和 H[joint_l, root] 必须非零。stance 足滑动时，求解器能够同时选择 root 减速/转动和对应髋膝关节补偿，而不是只让关节追逐已经走远的 root。

6. 修改约束

约束边界：以下硬约束只定义运动学一致性、fixed contact 和启动时序，不依据 small/large 语义选择跨越或绕行。语义行为继续由连续 height/signed-distance residual 决定。
约束定义作用
真实起点X[:,0] = measured_state保持 rolling MPC 闭环。
运动学转移X[t+1] = f(X[t],U[t])保持 multiple-shooting 一致性。
scheduled stance world anchorFK_l(X[t]) = anchor_l，至少约束 XY；Z 等于同一高程图表面加 foot radius。禁止 stance 足被 root 携带。
joint boundsposition/velocity 位于 Go2 允许范围。禁止通过极端关节姿态满足锚点。
启动足端领先零/近零平移转为非零平移时，首个发布帧 root command-axis 位移不超过 0.5mm，scheduled swing 足必须先形成至少 1mm 的 relative-root 主动位移。保证足端先动，root 后动。
地图和数据有效性field/env/version/world pose 对齐，非有限或越界显式 invalid。不让无效数据进入发布结果。

stance equality 在 swing→stance 时使用安全 touchdown 的世界位置建立新 anchor；连续 stance 段保持同一 anchor。若计划 touchdown 位于语义风险内，连续 touchdown avoidance 必须在进入 stance 之前把它移到安全区域，不能在约束层临时 snap。

7. Command、Swing 与 Touchdown

7.1 Command 从逐帧锁定改为 horizon 任务

删除“每个节点都强制 root 速度等于完整 command”的主导作用。主要平移任务改为：

v_avg_body = Rz(-yaw0) * (root_xy[H] - root_xy[0]) / (H * dt)
L_command_progress = ||v_avg_body - command_xy||^2
L_root_smooth = ||delta root_velocity||^2

可以保留较弱的局部速度 residual，但它不能压过 stance equality、启动足端领先和 touchdown coordination。这样 root 的瞬时速度可以随 stance/swing 相位变化，而 horizon 平均进度仍跟踪 command。

7.2 Command-conditioned Touchdown

固定相位 joint target 继续提供弱姿态先验，但不再单独决定 swing XY。每条 swing 腿生成连续 touchdown reference：

touchdown_ref_l =
  hip_world_l
  Rz(yaw) * nominal_footprint_l
  k_step * command_world_xy * remaining_swing_time
  + continuous terrain / signed-distance correction
  • 前进、后退、横移和斜向命令自然得到不同 touchdown lead。
  • 速度越大，允许的步长参考越大，但受 reach、joint bounds、smoothness 和 terrain safety 限制。
  • 纯 yaw 使用围绕 root 的切向 touchdown reference，不把 yaw 错误转成平移。
  • touchdown 仍由最终 root/joint FK 实现，不新增一条与 FK 脱离的可发布足端轨迹。

7.3 启动足端领先

运动启动事件定义为平移 command 从 norm 不超过配置 deadband 转为非零，或方向发生足够大的改变。事件状态按环境独立存入 solver/runtime state，不跨环境共享。

t_foot = first t where
  delta(foot_world - root_world) dot command_direction >= 1mm

t_root = first t where
  delta(root_world) dot command_direction >= 0.5mm

foot_root_lead_time = (t_root - t_foot) * dt

首帧 root hold 属于已批准的启动运动学约束；后续使用连续 progress/smoothness恢复 command。稳定 trot 不要求 root 每个 half-cycle 完全停住，因为已有另一对 stance 足提供世界锚点；稳定阶段由 stance slip、swing active motion 和 touchdown lead 约束协同。

8. Loss、Constraint、Merit 与 LQ 一致性

所有场景使用同一套目标与约束，不按 terrain row、shape 或测试名称切换 loss：

task:
  horizon command progress, direction, yaw

contact / gait:
  stance equality, swing touchdown reference, swing shape,
  touchdown velocity, support viability, foot-leads-root startup

terrain / semantic:
  stance ground, terrain clearance, signed small/large clearance,
  safe landing, full-body collision margins

regularization:
  posture, joint limits, root/joint velocity and acceleration,
  first-control and rolling continuity
  • 同一 residual 的几何、mask、normalization、margin 和权重在 GGN/LQ 与 full nonlinear merit 中必须一致。
  • line search 只能选择步长，不能承担创造 root-joint 耦合方向的职责。
  • scheduled stance equality 进入 SQP constraint system；对应 residual 仍可进入 merit 作为 constraint violation 评分和诊断，但不靠调普通 loss 权重实现。
  • 所有旧 terrain、small/large、support、smoothness、terminal 项继续存在，不能为了新 gait 指标关闭旧安全项。

9. 耦合 LQ 求解器

现有 diagonal state Riccati 和 root/逐关节独立 block solver不能用于新生产路径，因为它们会丢弃 H[root,joint]。采用 root-centered arrowhead 结构：

[ Hrr  Hr1  Hr2  Hr3  Hr4 ]
[ H1r  H11   0    0    0  ]
[ H2r   0   H22   0    0  ]
[ H3r   0    0   H33   0  ]
[ H4r   0    0    0   H44 ]

root block: 6x6
leg block:  3x3 each

每个时间节点用 batched Schur complement 消去四条腿：

S_root = Hrr - sum_l Hrl * inv(Hll) * Hlr
solve root delta from S_root
back-substitute each leg delta

实现必须使用稳定的 batched Cholesky/LDLT 或解析小块 solve，不显式构造 matrix inverse。若时间递推导致腿间间接耦合不能保持 arrowhead，则允许使用完整 18x18 batched Riccati 作为正确性基线；生产结构化近似必须与完整基线的方向和 merit 改善一致，不能为了速度再次丢弃交叉块。

10. Rolling RTI 数据流

measured x0 + command + field + previous solver state
  -> update per-env command-start state
  -> fixed trot contact schedule
  -> command-conditioned touchdown references
  -> shifted warm start
  -> full root-joint FK / link geometry / field queries
  -> residuals + stance equalities + complete Jacobians
  -> coupled GGN + arrowhead/Schur Riccati
  -> parallel line search with full merit and constraint violation
  -> publish x1 only
  -> update stance anchors, gait phase, command-start state

环境 reset 清空对应环境的 stance anchor、warm start、dual、pending reference 和 command-start state；其他环境不受影响。环境数量继续由上层 num_envs=N 构建，底层不写死 1024。

11. JointMetrics 统一数据合同

联合原则：场景只负责产生 terrain、command、phase 和事件，不得选择计算哪些通用指标。所有 rolling 场景调用同一个 JointMetrics accumulator。任何指标的改善都不能以另一个场景中旧指标退化为代价。

原始指标保留维度：

[scenario, command, phase, environment, time, leg_or_body_part]

12. 场景与指标必须做笛卡尔联合

每个场景均计算 Root、Stance、Swing、Coupling、Geometry、Continuity 和 RTI 通用组。事件型指标只有在数学上不适用时才为 N/A：

场景通用指标事件指标
平地零速、前后、横移、斜向、yaw、mixed全部计算。非零平移计算 touchdown/lead；零速方向指标 N/A。
小物体五 shape × 三速度 × 多 gait phase全部计算，不能只看 cross/collision。cross opportunity 存在时计算 strict success；coverage 单独验收。
接近小物体后 stop全部计算，不能只看 support recovery。stop drift、support recovery 和重新启动 lead。
大障碍左右偏置与正前方全部计算，不能只看 root 绕行。large clearance、avoidance progress。

禁止平均掩盖：验收必须同时检查每个 scenario x command x phase x shape 单元、每类场景 worst case 和全局汇总。总体均值通过不能覆盖任一单元失败。N/A 不计为成功；cross、stop、command-start 等事件必须另有最小 opportunity coverage。

stance equality连续 stance、多 phase、不同 command 和地形下 anchor residual、XY slip、Z gap 同时达标，不通过 postprocess 修改输出。
command touchdown前后、左右、斜向和不同速度下 touchdown lead 方向正确，步长随 command 连续变化，joint/reach 不越界。
足端先于 root每个 motion-start event 中 scheduled swing 足 relative-root motion 领先 root 20-80ms，提前 root leak 不超过 0.5mm；同期 stance anchor 有效。
联合场景矩阵每个场景单元都生成全部通用 JointMetrics；故意注入任一旧指标退化时，即使该场景主指标改善，总结果仍失败并定位具体单元。
平地与真实 viewer九命令 root 平均速度/方向、stance XY/Z、swing 主动推进、joint/foot 连续性和 actual readback 同时达标。
small crossing/stop原 strict cross、零分部位碰撞、stance-on-small、stop support/root drift 全部通过，同时新 coupling/slip/lead 指标不退化。
large/terrain绕行、上下台阶和粗糙地形继续安全推进，并同时满足 stance anchor、全身碰撞、joint、RTI 和 root-foot coupling 指标。
动态环境数1/40/512/1024 由同一上层参数构建；metric accumulator、scenario key、solver和报告不依赖固定 batch。

16. 性能基线、目标与实施顺序

当前真实性能基线：空闲 GPU、1024 环境、H16、1000 次同步 refresh、每环境 small 11x11 footprint 加 large 41x41 footprint 的正式结果为 7402.55ms。其中 field 平均 4.5884ms/次，MPC 平均 2.8416ms/次，完整 refresh 平均 7.4025ms/次，P95 7.4742ms，峰值显存约 1127.79MiB，nonfinite 为 0。旧单像素 4768ms 命中了非真实快速路径，继续明确拒绝作为验收结果。

最终性能合同继续继承 2026-07-15 和 2026-07-16 设计，不放宽：

  • 1024 x H16 x 1000 次同步 exact signed field + MPC 总耗时 <=5.0s。
  • 平均完整 refresh <=5.0ms，并报告 P50、P95、P99、最大值和峰值显存。
  • 计时包含 realistic multi-cell small/large signed field、field 发布、完整耦合 GGN/LQ、line search 和 x1 发布。
  • 不能通过单像素地图、减少环境数、缩短 H、删除碰撞几何、关闭 JointMetrics 对应优化合同或排除 field 计时通过。

实施严格分成两个修复阶段和一个最终联合复验阶段：

  1. 阶段 A：行为正确性。完成 root-joint 耦合、stance equality、command touchdown、足端先于 root 和统一 JointMetrics；平地、小物体、大障碍、地形、stop、viewer、rolling 和旧回归全部通过。阶段 A 只报告性能变化，不以 5 秒门阻止定位行为问题。
  2. 阶段 B：性能收口。冻结阶段 A 的 loss、constraint、几何、阈值和场景合同，再优化 exact EDT、耦合 Schur/Riccati、kernel fusion、workspace、编译和 CUDA Graph，直到 realistic full-refresh <=5s。任何性能修改都必须重新运行阶段 A 的完整联合矩阵。
  3. 阶段 C：最终联合复验。阶段 B 达标后，从同一个最终候选提交和干净运行状态重新执行完整阶段 A 行为/安全/旧回归矩阵，再执行阶段 B realistic 性能验收。不得引用阶段 A 修复完成时的旧行为结果，也不得引用性能优化前的旧性能结果；两个门必须在同一最终代码上同时通过。

新增 root-joint 交叉块可能使 MPC 时间高于当前 2.8416ms；因此性能优化必须同时给出 field、linearization、coupled solve、line search 和完整 refresh 的分项，先确认新增成本位于哪个阶段，再做结构优化。不得在行为修复过程中用 diagonal solver 临时恢复速度，因为那会重新制造本设计要消除的解耦。

17. 风险与控制

风险控制方式
stance equality 过强导致无可行解touchdown 在进入 stance 前满足 terrain/semantic/reach；使用 SQP constraint regularization和明确 infeasible status，不在发布后 snap。
root 平均 command 跟踪变慢用 horizon progress、terminal progress 和 rolling 平均速度验收；不恢复逐帧强锁定。
启动先摆腿导致原地等待lead 上限 80ms，随后由 progress loss恢复；稳定 trot 不重复强制 root 停止。
touchdown step 过大导致 joint 饱和连续 reach/joint barrier、速度相关步长界和完整 FK Jacobian共同限制。
结构化 solver 再次丢失耦合每次改动都与 dense 基线对齐，并以 cross-Hessian和 coupled-direction 指标作为硬回归。
新场景指标改善但旧场景退化所有场景使用同一 JointMetrics，按每单元 worst-case 联合失败，不允许仅看总平均。
耦合求解使当前 7.4025ms 基线进一步变慢行为合同通过后分解 field/linearization/solve/line-search 时间，优先优化结构化 Schur、kernel fusion、workspace 和固定图；不得退回解耦近似。

18. 完成定义

完成必须按三步顺序判定。第一步单独修复并通过行为门：完整 root-joint Jacobian、stance equality、command-conditioned touchdown、耦合 LQ、启动足端领先，以及平地、小物体 crossing/stop、大障碍、上下台阶、真实 viewer、rolling RTI、动态环境数的全部适用新旧 JointMetrics。第二步冻结行为合同，单独修复性能门：把空闲 GPU realistic multi-cell 的 1024 x H16 x 1000 同步 field + MPC 从当前 7.4025s 优化到不超过 5.0s。第三步在同一个最终候选提交上从头联合重跑第一门和第二门；只有最新行为结果和最新性能结果同时通过才算最终完成，阶段 A 或阶段 B 的历史通过记录不能替代最终联合复验。任何只修某个场景主指标、依赖全局平均掩盖、把 N/A 当成功、关闭旧 loss、修改 detector、恢复解耦 solver、使用单像素性能场景或在输出后修补轨迹的结果都不算完成。
