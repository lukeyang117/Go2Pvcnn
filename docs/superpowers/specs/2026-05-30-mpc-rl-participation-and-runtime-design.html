MPC 接入 RL 的参与环境选择与运行时优化设计

日期：2026-05-30 ｜ 主线：MPC semantic trajectory reward ｜ 文件范围： Go2Pvcnn/extension/batch_mpc_planner、 Go2Pvcnn/extension/mdp/rewards_reference.py、 Go2Pvcnn/go2_pvcnn/tasks/teacher_elevation_trajectory_mpc_semantic_env_cfg.py

1. 设计目标

把当前 MPC reference 接入 RL 训练时，不让所有环境都参与 MPC 规划。只允许用户配置范围内的环境进入 MPC 抽签；当前明确隔离的地形和难度组合不参与 MPC，其余环境仍可以参与抽签。

未被选中的环境不调用 MPC，不更新新的 MPC reference，其 MPC reference reward 返回 0。基础 locomotion reward、速度跟踪、碰撞惩罚等其他 reward 不受影响。

不变约束：本设计不修改 low-small loss 公式，不新增 optimizer loss，不新增硬约束，不改变 decode_parametric_trajectory() 的职责。2026-05-28 low-small 设计效果不能回退。

2. 25 帧对齐约束

MPC 规划帧数、reference cache 帧数和重规划周期必须对齐：

MPC horizon = reference cache horizon = replan interval = 25

任务配置需要显式设置：

reference_trajectory_horizon = 25
reference_replan_interval_steps = 25

MpcRuntimeCfg.horizon_steps 默认已经是 25。由于 planner_cfg_from_task_cfg() 会用 reference_trajectory_horizon 覆盖 runtime.horizon_steps，MPC semantic 任务必须显式覆盖父类默认值 50。

验收检查：

manager.horizon_steps() == 25
cache.horizon_length() == 25
cfg.reference_replan_interval_steps == 25

3. 参与环境选择函数

新增一个纯 selector 函数。它只判断哪些 env 本次允许参与 MPC，不做规划、不写 cache、不计算 reward。

建议位置：

Go2Pvcnn/extension/batch_mpc_planner/participation.py

函数接口：

select_mpc_reference_envs(
    *,
    num_envs: int,
    device: torch.device,
    terrain_types: Tensor | None,
    terrain_levels: Tensor | None,
    terrain_names: list[str] | None,
    cfg: MpcReferenceParticipationCfg,
    sample_count: int,
    cursor: int,
) -> tuple[Tensor, int]
输入含义
num_envs总环境数。
device输出 mask 所在设备。
terrain_typesshape 为 [num_envs]，IsaacLab terrain col / 地形类型 id。
terrain_levelsshape 为 [num_envs]，IsaacLab terrain row / 难度 id。
terrain_namescol id 到 terrain name 的映射，来自 terrain.cfg.terrain_generator.sub_terrains。
cfg用户可调参与规则。
sample_count本次最多选择多少 env 参与 MPC。
cursorround-robin 当前游标。

函数输出：

selected_mask: Tensor  # shape [num_envs], dtype bool
next_cursor: int

selected_mask[i] == True 表示第 i 个 env 本次参与 MPC 规划，并且后续 25 step MPC reference reward 生效。False 表示本次不参与 MPC，MPC reference reward 为 0。

4. 可调参数

新增配置对象：

MpcReferenceParticipationCfg:
    enabled: bool
    include_terrain_cols: tuple[int, ...] | None
    include_terrain_names: tuple[str, ...] | None
    include_terrain_rows: tuple[int, ...] | None

    exclude_pairs: tuple[MpcTerrainDifficultyPair, ...]
    selection_mode: str

其中 selection_mode 默认是 "round_robin"。

exclude_pairs 用于表达“这个地形和这个难度组合不参与 MPC”。

MpcTerrainDifficultyPair:
    terrain_cols: tuple[int, ...] | None
    terrain_names: tuple[str, ...] | None
    terrain_rows: tuple[int, ...]

5. 隔离规则：地形和难度是 AND 逻辑

用户希望隔离的环境必须同时满足“指定地形”和“指定难度”，才会被排除。只满足地形或只满足难度的环境，仍然需要参与抽签。

excluded(env) = terrain_match(env) AND row_match(env)

例子：

exclude_pairs = [
  {
    terrain_names = ("stairs_down", "rough_large"),
    terrain_rows = (7, 8, 9),
  }
]
env 情况是否排除原因
terrain 是 stairs_down，row 是 8排除地形和难度同时命中。
terrain 是 stairs_down，row 是 3不排除只命中地形，没有命中难度。
terrain 是 flat，row 是 8不排除只命中难度，没有命中地形。
terrain 是 flat，row 是 3不排除地形和难度都未命中。

如果 include_terrain_* 或 include_terrain_rows 被设置，它们先定义“允许参与抽签的大范围”；然后 exclude_pairs 在这个范围内按 AND 逻辑扣掉坏组合。

eligible(env) = include_match(env) AND NOT any_pair_excluded(env)

6. 轮转抽样

从 eligible_ids 里使用 round-robin 抽样，而不是每次随机抽样。

eligible_ids = 满足参与规则的 env ids selected_ids = eligible_ids[cursor : cursor + sample_count] 如果越过末尾，则 wrap around next_cursor = (cursor + sample_count) % len(eligible_ids)

好处是每个符合条件的 env 都会周期性拿到完整 25-step MPC reference，显存由 sample_count 控制，reward 覆盖稳定，日志更容易解释。

7. Manager 调用流程

MpcTrajectoryManager.refresh_from_env() 的流程调整为：

1. 每 25 step 触发一次 global_due
2. 从 IsaacLab terrain 读取：
   - terrain.terrain_types
   - terrain.terrain_levels
   - terrain.cfg.terrain_generator.sub_terrains names
3. 调 select_mpc_reference_envs(...)
4. 只对 selected_ids 构建 state / command / terrain subset
5. 只对 selected_ids 调 plan_segment(...)
6. selected_ids 的结果写入 full-shaped cache
7. reference_reward_mask = replace_mask
8. 未选中 env 的 reference reward 为 0

reward 侧已有 reference_foot_pos_reward() 乘 manager.reference_reward_mask() 的逻辑，因此未参与 env 不需要额外 reward 分支。

8. 训练信号密度

为了让模型学会轨迹，MPC reward 不能太稀疏。建议监控：

duty_cycle = selected_env_count / eligible_env_count

第一版建议 duty_cycle >= 0.25。例如：

eligible_env_count = 512
selected_env_count = 128
duty_cycle = 25%

未参与 env 只是不拿 MPC reference reward，其他基础训练信号仍然存在。

9. 显存和速度优化边界

第一版只做不改变 low-small 优化结果的优化：

  • 只规划 selected env。
  • horizon / replan / cache 全部对齐到 25。
  • 训练期关闭 CUDA sync profiling。
  • 优化结束后的 cache/export/FK 写回使用 detach 或 torch.no_grad()。
  • steps > 0 时，不再保留 Adam loop 前那次冗余 sampled loss 计算。
mpc_diagnostics_emit_runtime_counters = False
mpc_diagnostics_profile_cuda_sync = False

以下优化暂不做，因为可能改变 low-small 效果：

  • 减少 optimize_steps。
  • 让 FK collision / touchdown keepout 等 heavy loss 隔步计算。
  • AMP / float16。

10. reference_foot_pos_reward 世界坐标系跟踪

reference_foot_pos_reward() 需要改成世界坐标系下的足端跟踪。IsaacLab 当前足端和 MPC reference 足端都必须是 world frame。

当前真实足端：

current_foot_w = asset.data.body_pos_w[:, foot_body_ids, :]

MPC reference 足端：

ref_foot_w = cache.foot_pos_w[env_id, frame_id]

reward 公式：

err_e = mean_l || current_foot_w(e,l) - ref_foot_w(e,l) || R_foot(e) = exp( - err_e / sigma^2 ) * reference_reward_mask(e)

因此 ReferenceTrajectoryCache 需要新增字段：

foot_pos_w: Tensor | None = None

旧字段 foot_pos_root 第一版保留，用于兼容 together/legacy/已有测试；新的 MPC semantic foot tracking reward 读取 foot_pos_w。

同时，MPC backend 的参考帧选择需要使用 manager 自己维护的 phase：

frame_ids = manager.current_frame_ids()

而不是继续使用：

frame_ids = env.episode_length_buf % horizon

原因是 selected env 在任意 episode step 重新规划时，cache 第 0 帧对应当前状态；如果用 episode modulo，会出现当前真实足端追未来帧 reference 的错位。

11. 基于 IsaacLab 真实 contact 的语义碰撞 reward

当前 swing_leg_collision_reward() 基于 semantic_height_scanner 查询 height/semantic，这会受 scanner 更新周期和栅格分辨率影响。新的 RL 语义碰撞 reward 改为使用 IsaacLab / PhysX 的真实接触力。

IsaacLab ContactSensor 的关键限制是：filtered contact 只能可靠支持 one-to-many。也就是说，每个 sensor 在每个 env 中只能对应一个 robot body，然后 filter 到多个目标物体。不能用一个 sensor 写成 Robot/.*_foot 再 filter 到 semantic objects。

并行环境约束：每个 robot body 需要单独建 filtered contact sensor；语义物体是全局 prim，不在 {ENV_REGEX_NS} 下面。

语义物体 filter 使用全局路径：

/World/semantic_course/small/.*
/World/semantic_course/large/.*

单个 body 的 sensor 示例：

prim_path = "{ENV_REGEX_NS}/Robot/FL_foot"
filter_prim_paths_expr = ["/World/semantic_course/small/.*"]

filtered contact 数据读取：

sensor.data.force_matrix_w

shape：

[num_envs, 1, num_filter_shapes, 3]

对 env e、body b、语义类别 k，真实接触力聚合为：

F(e,b,k) = Σ_j || force_matrix_w(e,0,j,:) ||

其中 j 是该语义类别下的全局 obstacle shape。

碰撞激活：

c(e,b,k) = clamp( ReLU(F(e,b,k) - F_threshold) / F_scale, 0, c_max )

最终 penalty：

P(e) = Σ_b w_body(b) * [ w_small * c(e,b,small) + w_large * c(e,b,large) ] R_collision(e) = -P(e)

body 列表和权重需要可配置。第一版建议覆盖：

FL_foot, FR_foot, RL_foot, RR_foot
FL_calf, FR_calf, RL_calf, RR_calf
FL_thigh, FR_thigh, RL_thigh, RR_thigh
base

如果性能压力大，可以先缩小到 foot + calf + base。但无论覆盖哪些 body，都必须保持 one-body filtered sensor 的 IsaacLab 约束。

12. 新增文件边界

建议新增一个独立 reward 文件：

Go2Pvcnn/extension/mdp/semantic_contact_rewards.py

该文件只负责真实接触语义碰撞 reward，不放 MPC reference tracking 逻辑。

建议函数：

semantic_filtered_contact_collision_reward(
    env,
    small_sensor_names,
    large_sensor_names,
    body_weights,
    force_threshold,
    force_scale,
    force_clip,
    small_weight,
    large_weight,
)

rewards_reference.py 继续负责 reference tracking，例如 reference_foot_pos_reward()。这样可以避免把 MPC reference reward 和 IsaacLab 真实 contact reward 混在一个文件里。

不需要修改 IsaacLab 源码；需要在 teacher_elevation_trajectory_mpc_semantic_env_cfg.py 中增加 per-body filtered contact sensors，并把旧的高程图碰撞 reward 替换成新的真实 contact reward。

13. Low-small 不变项

为了保证 2026-05-28 low-small 设计效果不变，以下内容保持不变：

  • decode_parametric_trajectory() 只消费 nominal + variables。
  • 不新增 touchdown hard projection。
  • 不新增 touchdown snapping。
  • 不新增足端硬分离。
  • 不新增 optimizer loss。
  • 第 0 条 low-small FK semantic collision probe 仍然只作为优化后诊断。
  • 现有 low-small loss 集合和公式不变。
