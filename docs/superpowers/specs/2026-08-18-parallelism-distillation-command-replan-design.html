Parallelism 蒸馏训练：速度命令与独立重规划设计

日期：2026-08-18　分支：parallelism-large-obstacles-distillation-rl

本设计对齐 Go2Pvcnn 的速度奖励和线速度课程，同时保留 Parallelism reference 的 24 帧轨迹与独立 23 控制步重规划机制。速度命令保持时间与 reference 重规划时间明确解耦。

一、设计目标

  • 速度奖励使用 teacher_elevation_trajectory_mpc_semantic_env_cfg.py 的权重和误差尺度。
  • 线速度课程复用 Go2Pvcnn 的 lin_vel_cmd_levels，不再使用 Parallelism 自定义速度误差课程。
  • 角速度从第一个 episode 就使用完整范围 [-1, 1]，不参与课程扩大。
  • 速度命令保持约 100 秒，不因 reference 轨迹结束自动换命令。
  • Parallelism 每个环境独立计数，每 23 个已执行控制步重新规划一次。

本设计不增加额外的 root 位移课程门槛，也不修改 Parallelism 的运动学规划逻辑。奖励、课程、command 和 reference 重规划分别负责自己的时间尺度。

二、速度奖励

蒸馏任务继续使用当前实际 policy Go2 的 root 速度与 command 比较。奖励不直接比较 Parallelism reference 速度。

track_lin_vel_xy:
  function: go2_mdp.track_lin_vel_xy_exp
  weight: 1.5
  std: sqrt(0.25) = 0.5

track_ang_vel_z:
  function: go2_mdp.track_ang_vel_z_exp
  weight: 0.75
  std: sqrt(0.25) = 0.5

两个奖励每个 IsaacLab 控制步计算一次。其他 root、joint、foot、碰撞、能耗和稳定性奖励全部保留，不因本设计删除。

四、课程设计

4.1 线速度课程

蒸馏配置绑定 Go2Pvcnn 的：

lin_vel_cmd_levels = CurrTerm(go2_mdp.lin_vel_cmd_levels)

升级条件保持参考实现：

episode_mean(track_lin_vel_xy)
    > track_lin_vel_xy.weight * 0.8
    = 1.5 * 0.8
    = 1.2

课程只扩展 lin_vel_x 和 lin_vel_y，不扩展 ang_vel_z。课程在 episode 级别计算，不与每 23 步的 reference 重规划绑定。

4.2 其他课程

  • 保留当前复杂地形的 terrain_levels 课程。
  • 关闭当前配置中的 parallelism_velocity 自定义 joint/root 误差课程。
  • 不修改旧的 Go2Pvcnn 任务和旧的 Parallelism 训练配置。

五、Parallelism 三种重规划触发条件

每个环境独立保存一个 parallelism_step_count 和上一条 command。重规划只由以下三种事件触发：

触发条件处理
环境 reset清除旧 reference 和计数状态，读取 reset 后真实状态，立即规划。
速度 command 变化比较当前 command 与上一条 command；发生变化时立即规划，并清零计数器。
Parallelism 计数达到 23即使 command 没变，也读取当前真实状态重新规划，并清零计数器。

同一个控制步同时满足多个条件时只执行一次规划。速度比较使用小的浮点容差，避免数值噪声反复触发。command 的 100 秒采样周期不再作为 Parallelism 的计时依据。

控制周期 = sim.dt * decimation
          = 0.005 * 4
          = 0.02 s

reference 帧数 = 24
frame 0 = 当前真实状态，不执行控制、不参与奖励
frame 1~23 = 23 个未来控制步

Parallelism 重规划周期 = 23 * 0.02
                      = 0.46 s

六、reference 时间对齐

每次 reset、command 变化或 23 步到达后，统一执行同一套 reference 刷新流程：

读取当前 IsaacLab 真实 root、姿态、关节状态
        ↓
Parallelism 生成新轨迹
        ↓
reference_new[0] = 当前真实状态
reference_new[1] = 当前状态之后的第一帧
        ↓
下一次 policy observation 使用 reference_new[1]

旧 reference 不跨越重规划边界继续作为新轨迹的起点。reset 后也不提前显示一个与真实机器人不一致的 reference 第 0 帧。

当前轨迹缓存的 frame 0 是真实状态，不参与 teacher 输入、policy 动作和奖励；frame 1~23 才是未来控制帧。重规划计数是独立的 23 个已执行控制步计数。实现时必须明确计数器清零和新轨迹刷新发生在同一个 per-env 边界上，避免环境之间互相影响。

八、测试方案

8.1 配置测试

  • 验证速度奖励权重为 1.5 和 0.75，两个 std 为 0.5。
  • 验证 command 保持时间为 100.0 秒。
  • 验证 yaw 初始范围和上限始终为 [-1, 1]。
  • 验证课程使用 go2_mdp.lin_vel_cmd_levels，Parallelism 自定义速度课程关闭。

8.2 无 IsaacSim 的 manager 单元测试

  • reset 后立即规划，计数器清零。
  • command 不变时，第 23 个已执行控制步触发一次规划。
  • command 变化时立即规划，不等待 23 步。
  • command 变化和 23 步同时到达时只规划一次。
  • 多个环境分别 reset、改 command、到达计时点时互不影响。
  • 每次规划后 frame 0 是真实状态，下一次 policy 读取 frame 1。

8.3 回归与运行测试

  • 确认 flat、small obstacles 和旧 complex 配置未被改动。
  • 执行 Python 编译检查、pytest 和两个训练脚本的 shell 语法检查。
  • 启动 1024 环境 headless 训练，运行 4 个 iteration。
  • 检查启动、reset、23 步重规划和 command 保持期间没有 shape error 或 reference 越界。

九、验收标准

  • command 在 reference 周期内不自动变化，Parallelism 仍能按 23 个已执行控制步重规划。
  • command 变化时对应环境立即刷新 reference。
  • reset 后 reference 第 0 帧与真实 policy Go2 对齐。
  • yaw 从训练开始就是完整范围，课程不会扩大 yaw。
  • 速度奖励和线速度课程的数值、函数与 Go2Pvcnn 参考配置一致。
  • 1024 环境 4 iteration 冒烟测试通过。
