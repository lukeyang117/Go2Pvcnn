Parallelism 平地 Go2 Foot Planner 设计

日期：2026-07-27 ｜ 分支：Parallelism ｜ 目标目录：Go2Pvcnn/extension/parallelism/

目标：实现一个 flat-first、GPU 并行、暴力检索落脚点的 Go2 纯运动学 foot planner。第一版不搜索 root、不做动力学、不接 terrain gradient/SDF，只消费 Isaac Lab 返回的高程图、语义图和 valid mask；输出完整 24 帧 root、joint、foot、contact 轨迹，并能接入 extension/viz/go2_foostep_planner.py。
自包含实现边界：extension/parallelism 除了接入 extension/viz/go2_foostep_planner.py 外，不复用其它 extension 包代码。Go2 几何常量、FK、IK、腿部碰撞采样、高程查询、root rollout、candidate、filter 和 scoring 都在 parallelism 包内独立实现。
并行与 RL 边界：第一版所有核心路径都按 [B,...] batch tensor 设计，默认支持 GPU 上多环境并行。实现不得写只服务单环境 viewer 的 Python 逐环境主循环；viewer 是调试入口，最终消费者还包括后续强化学习环境的 batched reference/teacher 接口。

1. 目标与边界

第一版必须实现

  • 每次预测 24 帧，dt=0.02s。
  • 固定 trot：前 12 帧 FL/RR swing，后 12 帧 FR/RL swing。
  • 四条腿各自以对应 hip 为圆心，并行采样 50 个圆盘候选，四足合计 200 个候选。
  • 每个候选从高程图查询 touchdown z，再生成 swing，IK 出关节角，FK 回算真实足端与腿部几何。
  • 硬过滤后，只按速度跟踪位移评分；每条腿独立选一个最佳点。
  • 输出完整 24 帧 root、joint、foot、contact 轨迹和候选 diagnostics。
  • 所有 root、terrain query、candidate、swing、IK、FK、filter、score、argmin 和输出组装都保持 batch/GPU 并行。
  • 保留后续接入强化学习环境的 batched 输出边界。

第一版明确不做

  • 不搜索 root 轨迹；root 只由当前键盘/body-frame command 预测。
  • 不做四足组合搜索；没有 50^4 组合优化。
  • 不使用 terrain gradient、SDF、occupancy、distance field 或可导 terrain loss。
  • 不使用 body/base 碰撞过滤；body/base 留给后续 root 规划。
  • 语义图第一版只进入 diagnostics，不参与过滤或评分。
  • 不保留 smooth、hip-distance、warm-distance、Raibert 等额外 score 项。
  • 不接受只支持 B=1 viewer 的实现作为生产 planner。

3. 高程图与语义图合同

parallelism 第一版直接消费 Isaac Lab 返回的高程图和语义图，不构造 RTI perceptive field。

ParallelismTerrain
  height_w:    Tensor [B,H,W]
  semantic_id: Tensor [B,H,W]
  valid_mask:  Tensor [B,H,W]
  origin_w:    Tensor [B,3]
  yaw_w:       Tensor [B]
  resolution:  float
  • candidate touchdown z 从 height_w 查询。
  • 候选点、FK foot/knee/calf/thigh 碰撞采样点都通过同一 world-to-grid 查询高程。
  • valid_mask 为 false 的 candidate touchdown 直接 invalid。
  • semantic_id 第一版只记录 diagnostics，后续语义避障不需要改主入口。
  • 不需要也不传入 gradient、SDF、semantic distance、occupancy 或 propagated height。
  • 查询函数必须支持 batched packed points，例如 [B,N,2] world XY 一次返回 [B,N] height、semantic 和 valid。

4. Root 预测与 24 帧 Trot

horizon = 24
dt = 0.02
half_cycle = 12
T_half = 12 * dt = 0.24s

command clamp:
  vx   in [-1.0, 1.0]
  vy   in [-0.5, 0.5]
  vyaw in [-1.0, 1.0]

command 来自键盘/root 坐标系，是 body-frame 速度。root 不搜索，只按 command 预测。每个 12 帧 half-cycle 使用固定 smoothstep envelope，权重归一化后保证半周期总位移严格等于 v * 12 * dt，但帧内速度先慢后快。

yaw_k = yaw_0 + integrated_smoothstep(vyaw, k)
delta_xy_world_k = Rz(yaw_k) * ([vx, vy] * normalized_smoothstep_increment_k * T_half)
root_xy = cumsum(delta_xy_world)

4.1 固定 gait

帧范围Swing 腿Stance 腿候选 hip 参考帧root z
0..11FL, RRFR, RLFL/RR 用 frame 0 各自 hipmean(height(FR foot), height(RL foot)) + 0.3
12..23FR, RLFL, RRFR/RL 用 frame 12 各自 hipmean(height(FL foot), height(RR foot)) + 0.3

root z 使用对应 half-cycle 的 stance 足端高程均值加 0.3m。stance 足端高度来自高程图查询；第一版用 mean 聚合，后续若需要更保守净空可在设计修订中改为 max 或支撑平面估计。

5. 四足并行候选

  • 固定 50 个黄金角圆盘 offsets，半径最大 0.24m，shape [50,2]。
  • 四条腿各自用自己的 hip world position 作圆心。
  • FL/RR 的候选圆心取 frame 0 对应 hip。
  • FR/RL 的候选圆心取 frame 12 对应 hip。
  • 候选张量为 [B,4,50,3]，z 来自高程图查询。
  • 四腿并行过滤和评分，但每条腿独立 argmin；不做跨腿组合搜索。

6. Swing、IK 与 FK

每条 swing 腿从当前足端世界坐标到 candidate touchdown 生成 12 帧 swing。XY 线性插值，Z 使用固定抛物线摆高。

p_xy(tau) = (1 - tau) * p_start_xy + tau * p_touchdown_xy
p_z(tau)  = (1 - tau) * z_start + tau * z_touchdown + h_swing * 4 * tau * (1 - tau)
tau       = linspace(0, 1, 12)

候选 foot target 与 root trajectory 一起送入 batched analytic IK。IK 得到的关节角再送入 FK，后续 landing 和碰撞全部使用 FK 后的真实几何，不直接相信 swing target。

第一版不得导入或复用 extension.joint_mpc_rti、extension.batch_mpc_planner 或其它非 viz 的 extension 模块。Go2 FK、IK、hip offsets、joint limits、foot/knee/calf/thigh 采样和碰撞半径在 extension/parallelism 内独立实现。可以参考现有实现的几何语义做人工迁移，但运行时依赖必须保持自包含。

并行实现要求：IK/FK 不允许按环境、腿、候选或帧逐个 Python 调用。允许将 [B,4,50,12,...] reshape 成大 batch 后一次性进入 analytic IK/FK，再 reshape 回固定合同形状。

7. 硬过滤

过滤原则：第一版只保留用户确认的四类硬过滤。过滤是安全与可执行性合同，不做额外 soft filter，也不把 body/base 放进第一版。
Filter判定
valid_mapcandidate touchdown 在 valid_mask 内。
joint_limitIK 后 12 个关节角在 Go2 joint limit 内。
landing_groundedFK touchdown 足端 z 与高程图地面高度误差小于阈值。
leg_height_collision_freeFK 后 foot、knee、calf、thigh 的近似几何体相对高程图不碰撞。

腿部碰撞第一版使用近似几何体和高程图：

  • foot sphere
  • knee sphere
  • calf capsule samples
  • thigh capsule samples

每个采样点查询同帧高程图，若 sample_z - radius - margin < terrain_height，该 candidate invalid。body/base 不参与第一版 filter；后续 root 规划再加入。

7.1 Torch 条件组合合同

四类过滤必须全部用 torch 张量条件判断实现。每个 filter 生成一个 [B,4,50] bool tensor，不允许在 Python 层按环境、腿、候选、采样点写 if 分支或列表累积判断。

valid_map_ok = candidate_valid_mask                         # [B,4,50]
joint_ok = (joint >= joint_lower).all(dim=(-1, -2)) \
         & (joint <= joint_upper).all(dim=(-1, -2))       # [B,4,50]
landing_ok = (fk_touchdown_z - terrain_touchdown_z).abs() <= landing_tol
collision_ok = (sample_z - sample_radius - margin >= sample_height).all(dim=-1)

candidate_valid = valid_map_ok & joint_ok & landing_ok & collision_ok
reject_bits = torch.stack(
    (~valid_map_ok, ~joint_ok, ~landing_ok, ~collision_ok),
    dim=-1,
)                                                        # [B,4,50,4]

若需要处理 nonfinite 值，也必须用 torch 条件合入候选有效性，例如 candidate_valid = candidate_valid & torch.isfinite(score_raw) 或在 score mask 阶段置为 inf；不得用 Python 异常或逐候选分支作为正常过滤路径。

8. 速度跟踪评分

score 只有速度跟踪一项。所有 invalid candidate 的 score 设为 +inf。

score 使用固定 hip 截面：

  • FL/RR 只用 frame 0 的各自 hip pose。
  • FR/RL 只用 frame 12 的各自 hip pose。
  • 不使用 swing 过程中移动的 hip，也不累计过程 hip。
T = 12 * dt
dtheta = vyaw * T
r_body = hip_offset_body_xy[leg]
rot_yaw_displacement = R(dtheta) * r_body - r_body
target_step_body = [vx, vy] * T + rot_yaw_displacement

candidate_rel_body = Rz(yaw_ref)^T * (candidate_xy_w - hip_ref_xy_w)
score = ||candidate_rel_body - target_step_body||^2

vyaw 通过每条腿 hip offset 产生切向期望位移，进入同一个相对 hip 位移 score；不额外增加 yaw score。

8.1 Torch score 与一次选择合同

score masking 和最佳候选选择也必须是 torch 张量操作。invalid candidate 的 score 用 torch.where 或 masked_fill 置为 +inf，然后每条腿独立 argmin(dim=-1)。不得把候选搬到 CPU、不得用 Python 排序、不得按腿或候选循环找最小值。

score_raw = ((candidate_rel_body - target_step_body[:, :, None, :]) ** 2).sum(dim=-1)
score = torch.where(
    candidate_valid,
    score_raw,
    torch.full_like(score_raw, torch.inf),
)                                                        # [B,4,50]
selected_index = score.argmin(dim=-1)                    # [B,4]
selected_score = torch.gather(score, -1, selected_index[..., None]).squeeze(-1)
selected_valid = torch.isfinite(selected_score).all(dim=-1)

一次 planner 调用只允许这一轮候选生成、过滤、评分和选择。不得做 retry、ranked fallback、多轮候选扩张、多轮重打分或根据第一次结果再次搜索。selected_valid 为 false 的环境不能发布有效轨迹；viewer/RL adapter 可以显示候选和 reject bits，但不能把无有效候选的结果伪装为可执行轨迹。

  • frames 12..23：FL/RR=True，FR/RL=False

viewer_adapter.py 负责把这些字段转换成 go2_foostep_planner.py 可画的 root、foot、joint、contact、candidate 点云和 selected foothold。后续 CLI 增加 --planner-backend parallelism 后，viewer 可以在同一个入口切换当前 RTI backend 和 parallelism backend。

rl_adapter.py 后续负责把同一个 ParallelismTrajectory 转成强化学习环境可消费的 batched teacher/reference。该层不能重新规划或重新选择落脚点，只做字段裁剪、缓存和帧索引推进。第一版可以先定义 shape 合同，避免 viewer 适配成为唯一输出路径。
