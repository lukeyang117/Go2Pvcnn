Go2 官方碰撞体表面点碰撞检测设计

本设计用于 extension/parallelism 的 kinematic Go2 foot planner。目标是删除旧椭圆体碰撞逻辑， 改为使用 Go2 USD 官方 collision primitive，并在每个 primitive 表面放置固定碰撞点，用 Torch/GPU 并行完成 touchdown 与 swing 轨迹碰撞过滤。

1. 目标与边界

本次改动只改变碰撞几何体与碰撞点检测方式，不改变当前 planner 的候选选择策略。

  • 保留当前 active-leg-only 的碰撞筛选范围。
  • 保留每条腿独立 50 个候选点的规划方式，不做对角 swing pair 的 50 x 50 组合。
  • 保留现有 filter / score 行为。
  • standstill fallback 默认开启；当关闭时，规划失败不再输出默认保持轨迹，而是显式暴露 invalid 结果。
  • 删除旧的 ellipsoid 碰撞体配置和检测逻辑。
  • 新碰撞检测必须在 env、leg、candidate、time、shape、point 维度上并行。
本版本不检查 stance legs，也不做 trot 对角双腿联合碰撞。IK/FK 可以继续计算完整四腿姿态，但 reject 条件只看当前 active leg 的官方碰撞点。

3. 表面碰撞点设计

每个官方 primitive 会预先生成一组表面点。点先定义在 primitive local frame，再通过官方 translate + orient 变换到 link local frame，运行时再通过 FK 的 link pose 变到 world frame。

3.1 Thigh box 表面点

初版使用 6 个面心点，位于 box primitive local frame：

(+0.1065, 0, 0)
(-0.1065, 0, 0)
(0, +0.01225, 0)
(0, -0.01225, 0)
(0, 0, +0.0170)
(0, 0, -0.0170)

后续加密方式：在每个面上加网格点。例如 x 面在 y/z 范围内加密，y 面在 x/z 范围内加密，z 面在 x/y 范围内加密。

4. 碰撞判定逻辑

碰撞点不是逐个 Python 循环判断，而是一次性构造成张量并行处理。

  1. 根据 active leg 的 link pose，计算所有 surface points 的世界坐标。
  2. 使用 IsaacLab 返回的高程图和语义图，对这些点批量查询 height / semantic / valid。
  3. 如果点所在 map 无效，则该点对应 candidate 被过滤。
  4. 如果点落在障碍语义 1 或 2 上，则该点对应 candidate 被过滤。
  5. 如果地形高度高于碰撞点高度加容差，则认为该 surface point 被地形侵入，该 candidate 被过滤。

推荐的高度条件：

point_collision = terrain_height >= point_z - collision_margin_m

其中 collision_margin_m 默认继续使用 0.003。最终沿 point / shape / time 做 torch.any，得到每个 candidate 的碰撞状态。

5. Touchdown 与 Swing 检查

5.1 Touchdown collision

touchdown 检查使用 candidate 对应的 IK/FK 结果，取 active leg 的官方 surface points。此时可以把时间维视为 T=1。

5.2 Swing collision

本版本保留当前 active-leg-only 语义：

  • 每条 active leg 独立评估 50 个 candidate。
  • 每个 candidate 生成 12 帧 swing 轨迹。
  • 12 帧一次性展开到 batch 维度并行 IK/FK。
  • 只取 active leg 的 thigh / calf / foot surface points 做碰撞。
  • 任意一帧任意 surface point 碰撞，则该 candidate reject。

这不是时间步串行，也不是 t+1 依赖 t：

all swing targets
-> batched IK
-> batched FK
-> batched surface point collision
-> any over T / shape / point

6. 抬脚高度含义

swing_height_m 表示 swing 曲线中间峰值额外抬高的高度，不表示整段轨迹都抬高。

当前 swing 轨迹是从当前 foot 到 target touchdown 的线性插值，并在 z 上叠加单峰抛物线：

z = z_linear + swing_height_m * 4 * tau * (1 - tau)

当 tau=0.5 时，额外抬高达到最大值 swing_height_m；起点和终点额外抬高为 0。

7. 配置设计

不新增新的碰撞规格文件。官方 collision primitive 和 surface point 密度参数放入 extension/parallelism/config.py。

配置项 含义
official_collision_shapes官方 thigh/calf/foot primitive 参数集合。
box_surface_pointsbox 每个面上的采样密度。初版等价于 6 个面心点。
cylinder_layerscylinder 沿轴向的采样层数。初版可设为 1，加上端面中心点。
cylinder_anglescylinder 每层圆周采样点数。初版等价于 4 个方向点。
sphere_surface_pointssphere 表面方向点数。初版等价于 6 个轴向点。
collision_margin_m碰撞高度容差，默认 0.003。
contact_tolerant_collision_shape_names允许与地面接触的官方 shape 名称，默认包含 calf_lower_cylinder 和 foot_sphere；这些 shape 仍检查语义障碍。
standstill_fallback_enabled规划失败时是否输出当前 root、joint、foot 的保持轨迹，默认 True。

旧配置项 EllipsoidSpec、collision_ellipsoids、collision_probe_count、contact_tolerant_collision_names 应删除或改名，不再保留旧椭圆体语义。

8. 可视化设计

可视化入口为 extension/viz/go2_foostep_planner.py。新增命令行参数 --used-test-terminal，默认开启。

面板只包含以下控制：

  • vx 滑条：最左 0，最右 1。
  • vy 滑条：最左 0，最右 0.5。
  • vyaw 滑条：最左 0，最右 1。
  • swing_height 滑条：调节 swing 中间峰值抬脚高度。
  • show_mesh 勾选：显示或隐藏 Go2 视觉 mesh。
  • show_collision_body 勾选：显示或隐藏官方 collision body。
  • show_contact_points 勾选：显示或隐藏 surface contact points。
  • standstill_fallback_enabled 勾选：控制规划失败时是否输出默认保持轨迹，默认勾选。

surface contact points 在 IsaacSim 中显示为棕色。mesh 与 collision body 可以同时勾选，用来观察官方碰撞体与 Go2 mesh 是否贴合。

当 standstill_fallback_enabled=True 且所有候选点 invalid 时，输出当前 root、joint、foot 的保持轨迹，保持现有安全行为。当该选项关闭时，planner 仍返回 valid=False，但不把输出替换成默认保持轨迹；viewer 需要显示失败状态，便于观察为什么没有可用 touchdown。

9. 测试设计

9.1 Planner touchdown 有效性

  • 平地高程为 0，语义全可通行。
  • 给非零速度，例如 vx=0.3, vy=0, vyaw=0。
  • 断言 traj.valid == True。
  • 断言 candidate_valid.any() == True。
  • 断言每条腿至少有有效 candidate。
  • 断言 selected touchdown 高度接近地面。

9.2 无有效候选时保持不动

  • 构造全部 invalid 的 valid map。
  • 使用默认 standstill_fallback_enabled=True。
  • 断言 traj.valid == False。
  • 断言 root、joint、foot 都保持当前状态。
  • 断言 contact state 全部为 stance。

9.3 关闭 Standstill Fallback

  • 构造全部 invalid 的 valid map。
  • 设置 standstill_fallback_enabled=False。
  • 断言 traj.valid == False。
  • 断言 planner 不再把 root、joint、foot 输出替换成当前保持轨迹。
  • viewer 面板需要显示该失败状态，避免用户误以为 planner 仍然输出了默认 standstill。

9.4 Surface points 并行性

  • 验证 touchdown surface point 张量形状包含 B / leg / candidate / shape / point / xyz。
  • 验证 swing surface point 张量形状包含 B / leg / candidate / T / shape / point / xyz。
  • 验证碰撞结果通过 torch.any 聚合。
  • 避免在 candidate 或 point 维度使用 Python 逐项循环。

9.5 Viz 面板测试

  • 启动 go2_foostep_planner.py 时默认打开 used_test_terminal 面板。
  • 拖动 vx 滑条后，planner command 的 vx 发生变化。
  • 拖动 vy 滑条后，planner command 的 vy 发生变化。
  • 拖动 vyaw 滑条后，planner command 的 vyaw 发生变化。
  • 拖动 swing_height 滑条后，swing 中间高度发生变化。
  • 勾选或取消三个 checkbox 后，IsaacSim 中 mesh、collision body、棕色 surface points 显示状态变化。
  • 取消 standstill_fallback_enabled 后，人为制造无有效 touchdown，viewer 能显示 valid=False 且不再输出默认保持轨迹。

9.6 IsaacSim 真实 viewer 验证

参考命令保持 --planner-backend parallelism。验证日志需要输出：

  • valid
  • per_leg_valid
  • collision
  • collision_detail
  • 当前面板速度值
  • selected touchdown 信息

10. 实现边界

  • 不新增 official_collision_spec.py。
  • 不复用其他 extension 下除 viz 以外的代码。
  • 不修改 joint_mpc_rti 逻辑。
  • 保留当前 active-leg-only planner 行为。
  • 旧 ellipsoid 碰撞逻辑在实现阶段删除，不保留兼容分支。

11. 完成标准

  • 平地给速度时可以输出有效 touchdowns。
  • 碰撞点、时间步、候选点均通过 Torch 张量并行处理。
  • 旧椭圆体命名与诊断字段不再出现。
  • 可视化面板可以调节速度和抬脚高度。
  • IsaacSim 中可以按勾选显示 mesh、official collision body 和棕色 surface points。
