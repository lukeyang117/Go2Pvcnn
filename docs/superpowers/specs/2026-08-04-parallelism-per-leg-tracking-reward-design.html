Parallelism RL 逐腿跟踪奖励与指标设计

在不删除任何现有奖励、不修改 Parallelism 规划、observation、termination 和 curriculum 逻辑的前提下，增强 active swing 最差足端与全部 12 关节最差误差的训练信号，并补齐逐腿 TensorBoard 指标。

1. 背景与实测证据

使用 model_400.pt、固定命令 vx=0.5，在真实 Isaac Sim play 中运行 96 step，覆盖 4 次 24 帧重规划。测试使用 deterministic inference，因此观测到的偏差不是 action std 随机采样造成的。

腿Planner swing apex lift摆动期平均三维足端误差观察结果
FL约 13.3 至 15.1 cm5.7 cm能够明显抬腿，但仍低于 reference
FR约 13.3 至 15.1 cm9.7 cm大部分 swing 时段抬升不足
RL约 13.3 至 14.3 cm10.7 cm四腿中平均误差最大
RR约 13.3 至 14.3 cm8.7 cm与 FL 同相位摆动，但经常保持接地

Planner 对四腿生成的抬升高度基本一致，腿序为 FL, FR, RL, RR，步态相位为前 12 帧 FL+RR、后 12 帧 FR+RL。现有证据没有显示 planner swing 或腿序错位，问题集中在 policy 对不同腿的跟踪不均衡。

现有 reference_foot_pos 将四条腿合并为一个加权平均误差。一条 active leg 严重偏离时，其他三条腿仍会稀释该误差；现有 joint reward 同样以 12 个关节的整体误差为主，不能单独限制最差关节。

2. 目标与硬约束

  • 让 FL、FR、RL、RR 都跟踪相同质量的 Parallelism swing，不允许只学好一条腿。
  • 限制单个 hip、thigh 或 calf 关节出现很大误差而被其余关节平均掉。
  • 保留全部现有 reward term；允许调整其 weight、threshold 等参数。
  • 新增 reward 和 metric 必须使用 Torch 张量条件与归约操作，在环境、腿和关节维度上并行。
  • 不增加逐环境 Python 循环，适配后续 1024 环境及更大规模训练。
  • 不修改 planner、24 帧 reference 时序、重规划、standstill、actor/critic observation 和 action 定义。
  • 不修改 termination term、termination 阈值、curriculum 判定公式和 curriculum 阈值。

3. 时间与坐标系对齐

两个新增奖励必须和现有 tracking reward 使用同一个目标帧：当前动作执行后对应的 Parallelism 下一帧 reference。实际关节状态来自当前物理仿真结果，reference joint、foot 和 contact state 来自同一目标 reference 帧。

数据定义
Reference joint当前动作追踪的下一帧 12 维关节角，按 IsaacLab robot joint order 排列
Reference foot同一目标帧的四足世界坐标，顺序固定为 FL、FR、RL、RR
Active swing mask同一目标帧 contact_state == false 的腿
Foot error实际和 reference 足端都转换到当前 policy root frame 后计算三维差值
Joint errorIsaacLab articulation order 下的 abs(q_actual - q_reference)

足端误差在同一个当前 policy root frame 中计算，可以消除共同 root 平移和旋转表达差异，并与现有 foot reward 保持一致。

4. 新增 active swing 最差足端奖励

4.1 定义

foot_error[env, leg] = norm(actual_foot_b - reference_foot_b, dim=-1)
swing_mask[env, leg] = not reference_contact_state[env, leg]

masked_error = where(swing_mask, foot_error, -inf)
active_swing_max_error[env] = max(masked_error, dim=leg)

reward = exp(-(active_swing_max_error / 0.12) ** 2)

当前 trot 每帧有两条 active swing legs。奖励对这两条腿取最差三维足端误差，使另一条腿表现良好时不能掩盖未抬起的腿。

配置项最终值说明
Reward 名称reference_active_swing_foot_maxTensorBoard 对应 Episode_Reward/reference_active_swing_foot_max
Weight1.5足够影响最差摆动腿，但不覆盖 root 和整体 joint tracking
Std0.12 m与现有整体 foot reward 的空间尺度一致

误差为 5 cm、10 cm、15 cm 时，未乘 weight 的奖励约为 0.84、0.50、0.21。

不能用 error * swing_mask 后直接取最小或平均，因为 stance leg 的零值会参与归约。实现必须通过 torch.where 排除 stance leg，再在腿维度执行 torch.max。

5. 新增最差关节误差奖励

5.1 定义

joint_abs_error[env, joint] = abs(q_actual - q_reference)
joint_max_error[env] = max(joint_abs_error, dim=joint)

reward = exp(-(joint_max_error / 0.8) ** 2)

该奖励覆盖全部 12 个关节，不只检查 active swing legs。stance 腿关节同样需要随 root 和 reference 姿态变化，不能允许 stance 关节严重偏离。

配置项最终值说明
Reward 名称reference_joint_maxTensorBoard 对应 Episode_Reward/reference_joint_max
Weight0.75作为现有 joint mean 型奖励的补充
Std0.8 rad当前约 1.1 rad 的最差误差仍有非零梯度，避免突然收紧导致奖励消失

7. 新增 TensorBoard 指标

7.1 Active swing 总体指标

  • Episode_Tracking/episode_active_swing_foot_mean_error：所有 active swing 腿、所有有效 episode step 的三维误差平均值，单位 m。
  • Episode_Tracking/episode_active_swing_foot_max_error：episode 内 active swing 腿三维误差最大值，单位 m。
  • Episode_Tracking/episode_active_swing_foot_z_mean_error：active swing 高度绝对误差平均值，单位 m。
  • Episode_Tracking/episode_active_swing_foot_z_max_error：episode 内 active swing 高度绝对误差最大值，单位 m。

7.2 每腿 swing 指标

指标模板腿集合含义
episode_swing_foot_{LEG}_mean_errorFL、FR、RL、RR该腿只在自身 swing 帧内的三维误差平均值
episode_swing_foot_{LEG}_max_errorFL、FR、RL、RR该腿在整个 episode swing 帧内的最大三维误差
episode_swing_foot_{LEG}_z_mean_errorFL、FR、RL、RR该腿只在 swing 帧内的高度绝对误差平均值

例如：

Episode_Tracking/episode_swing_foot_RR_max_error
Episode_Tracking/episode_swing_foot_RL_z_mean_error

7.3 每腿关节指标

  • Episode_Tracking/episode_joint_FL_max_error
  • Episode_Tracking/episode_joint_FR_max_error
  • Episode_Tracking/episode_joint_RL_max_error
  • Episode_Tracking/episode_joint_RR_max_error

每帧先在对应腿的 hip、thigh、calf 三个关节中取最大绝对误差，再记录整个 episode 的最大值。现有全局 joint/foot/root metric 全部保留。

8. Metric 累计与并行实现

运行时只维护固定大小 Tensor，不保存逐帧历史：

  • 总体 active swing：sum、count、max 和 Z sum、Z max。
  • 每腿 swing：形状 [num_envs, 4] 的 sum、count、max 和 Z sum。
  • 每腿 joint：形状 [num_envs, 4] 的 episode max。
swing_sum += where(swing_mask, foot_error, 0).sum(dim=1)
swing_count += swing_mask.sum(dim=1)
per_leg_sum += where(swing_mask, foot_error, 0)
per_leg_count += swing_mask
per_leg_max = maximum(per_leg_max, where(swing_mask, foot_error, 0))

episode mean 使用 count.clamp_min(1)，避免 reset 边界除零。环境 reset 后只清零对应 env_ids 的累计量。所有判断使用 torch.where、布尔 mask、sum/max 和 elementwise 更新。

1024 环境下这些累计 Tensor 仅为少量 [1024] 和 [1024,4] 浮点或整数数据，显存开销远小于 observation、rollout storage 和 CNN feature，不应成为性能瓶颈。

9. Termination、curriculum 与恢复训练

  • 所有 termination term 和阈值保持不变。
  • curriculum 继续使用 root position、root rotation、joint mean 和 joint max episode error；不加入新的 foot metric 门槛。
  • 从当前稳定 checkpoint model_400.pt 恢复，不从零训练。
  • 恢复时使用 --keep_std，保留 checkpoint 中约 0.31 的 policy action std。
  • 不把 action std 重置到 1.0，避免新 reward 与大幅探索噪声同时破坏已有稳定步态。
  • 继续加载 optimizer；新增 reward 总权重受控，critic 允许在恢复训练初期重新适应 return 分布。

10. 验证与验收

10.1 单元测试

  • 只有一条 active leg 误差较大时，active swing max reward 必须由该腿决定。
  • stance leg 即使误差较大，也不能进入 active swing max reward。
  • 全部 12 关节中任一关节误差最大时，joint max reward 必须选择该关节。
  • 四腿 metric 的 mask、sum、count、max 和 reset-by-env-id 正确。
  • 验证奖励和 metric 在 CPU/CUDA Tensor 上形状、dtype 和 device 一致。

10.2 真实训练冒烟测试

  • 1024 环境启动真实 Isaac Sim headless 训练。
  • 至少运行 4 iteration，确认 epoch/iteration 递增、reward 和新增 metric 均有有限输出。
  • 确认 collection time 没有因 Python 同步或逐环境循环明显增长。

10.3 恢复训练阶段目标

先恢复训练 300 至 500 iteration，再根据以下指标决定是否继续：

指标目标
四腿 swing mean errorFL、FR、RL、RR 差距明显缩小
episode_active_swing_foot_max_error低于 0.15 m
全局 episode_foot_max_error从约 0.30 m 降至 0.20 m 以内
episode_joint_max_error从约 1.10 rad 降至 0.8 rad 以内
Mean episode length继续接近 1000
Root position/rotation error不相对当前 checkpoint 明显恶化

11. 明确不在本次范围

  • 不删除任何现有 reward term。
  • 不新增 reference contact matching reward。
  • 不修改 Parallelism IK、FK、swing curve、候选搜索和 collision filter。
  • 不修改 actor/critic 网络结构、observation 维度和 action 输出形式。
  • 不调整 termination 和 curriculum。
  • 不修改 terrain、语义图和高程图接口。
