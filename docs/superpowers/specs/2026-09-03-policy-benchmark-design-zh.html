Parallelism AMP / Distillation / PPO 统一策略评测

目标：在完全相同的仿真布局、速度命令和统计协议下，比较 AMP、Distillation、Pure PPO，并以 Teacher 作为使用规划特权信息的性能上界。

核心结论

评测只做仿真。四个权重分别启动、分别加载、分别完成全部 benchmark；不在同一个 Isaac 进程中切换模型，也不进行训练。AMP、Distillation student 和 Pure PPO 使用相同的 1069 维部署观测。Teacher 输入 1103 维规划特权观测，只标为 planner-conditioned upper bound。

一、研究问题与比较边界

  • 复杂地形和大小障碍同时存在时，AMP 是否比 Distillation 和 Pure PPO 具有更低的碰撞率、跌倒率和更大的通过位移。
  • 在平地大障碍跑道上，策略能否绕开障碍并到达终点。
  • 在平地小障碍跑道上，策略能否跨越小障碍且不发生任何接触。
  • AMP 和 Distillation 是否更接近 Parallelism 规划出的 24 帧 state 轨迹。
不把训练 reward 当作论文指标

训练 TensorBoard 只用于选择和诊断 checkpoint，论文结果来自独立固定 manifest 的仿真评测。行为指标统计全回合；只有 planner tracking MSE 使用 valid-only 过滤。统计协议参考 Watch Your Step 记录，但不机械复刻其语义地图消融。

复杂场景继承课程生成规则，但评测期间冻结 terrain level。不能根据不同模型的表现自动升降级，否则碰撞率和位移不再是配对比较。

四、速度命令与 Parallelism 时间对齐

复杂混合场景的 120 组命令

vx   = {-1, -0.5, -0.25, 0.25, 0.5, 1}
vy   = {-0.5, -0.25, 0.25, 0.5}
yaw  = {-1, -0.5, 0, 0.5, 1}
总数 = 6 × 4 × 5 = 120

vx 和 vy 都去掉 0；yaw 保留 0。每个 episode reset 时确定一组速度，20 s 内保持不变。每个速度组合与 500 个固定 layouts 配对。

专项跑道的目标点控制

专项跑道只给平移的 vx，不直接给 vy。目标点为跑道终点，方向由当前位置实时计算：

theta_target = atan2(y_goal - y, x_goal - x)
heading_error = wrap_to_pi(theta_target - robot_heading)
command = [vx, 0, clip(k_theta * heading_error, -1, 1)]

每个 density 初始化 500 个固定布局。连续执行三轮，每轮将 0.25、0.5、1.0 m/s 重新均衡打乱；每个 layout 在三轮中分别使用一次，每档 vx 共 500 条。

24 帧轨迹与 23 个 transition

Parallelism horizon = 24 states: B0, B1, ..., B23
replan interval   = 23 transitions: B0→B1 ... B22→B23

reset / replan
  → 生成 B0...B23
  → 执行 23 个 control steps
  → 第 23 步之前重新计算终点方向
  → 更新 [vx, 0, yaw]
  → 只触发一次下一段规划

如果每 24 步才更新，Parallelism 会先在第 23 步因 timer 触发旧命令规划，又在第 24 步因 command change 再规划一次，造成重复规划。因此方向更新锁定在真实的 23-transition 边界。

五、环境初始化与并行数据流

每次评测只初始化一次 vectorized environment，布局在环境生命周期内固定；不同 checkpoint 由不同进程顺序运行，但使用同一 manifest 重建完全相同的场景。

Manifest固定 seed、terrain、障碍位置、command 和 goal。
500-env scene一次创建 500 个并行布局，不在 episode 内重建地形。
Policy单个 checkpoint 的 deterministic actor mean。
MetricsGPU batch 更新状态、碰撞、valid window 和结果 shard。
condition manifest
      ↓
一次初始化 500-env Isaac 场景
      ↓
reset robot / command / episode accumulators
      ↓
obs[t] → policy.act_deterministic(obs[t]) → env.step(action[t])
      ↓                         ↓
实际 state Bk              shadow Parallelism reference
      └──────────────→ 对齐、碰撞、跌倒、位移、MSE
      ↓
原子写入 episode shard → progress.json → summary

shadow planner 对 AMP、Distillation 和 PPO 只用于生成评测参考与 MSE，不写入它们的 policy observation；Teacher 才允许读取规划观测。planner 的在线参考从每个模型当前真实状态开始，因此 MSE 表示“对当前可行局部计划的跟随能力”，不是对一条已经物理错位的离线轨迹做比较。

六、指标定义

复杂混合场景

指标公式/定义统计范围
large_collision_episode_rate至少触碰一次大障碍的回合数 / 总回合数。全部回合
small_collision_episode_rate至少触碰一次小障碍的回合数 / 总回合数。全部回合
fall_rate发生跌倒终止的回合数 / 总回合数。全部回合
traversed_path_m终止前水平 root 路径长度：Σ‖pxyt+1−pxyt‖。全部回合
command_progress_m实际速度在当前期望运动方向上的投影累计，作为位移的补充，防止原地绕圈虚增路径长度。全部回合
contact_step_rate发生接触的有效步数 / 总有效步数。全部回合

120 个 command 分别统计，再做等权 macro average。速度为零的组合已从 vx/vy 移除，因此不存在“无平移速度却被纳入位移均值”的情况。

大障碍专项跑道

  • goal_reach_rate：到达终点的回合比例。
  • collision_free_goal_success_rate：到达终点且没有大障碍接触。
  • large_collision_episode_rate：回合中至少一次触碰大障碍。
  • distance_to_failure_m：终止时沿跑道方向的有效进度。
  • path_efficiency：有效前进距离 / 实际 root 路径长度。
  • 到达时间、最小障碍间距、跌倒率和越界率作为补充指标。

小障碍专项跑道

  • contact_free_goal_success_rate：到达终点且任何机器人部位均未接触小障碍。
  • small_collision_episode_rate：回合中至少一次触碰小障碍。
  • step_collision_rate：发生接触的独立跨越事件数 / 实际遇到的小障碍事件数。
  • foot_over_rate、touchdown_on_small_rate 和摆动足最小净空。
  • 到达率、失败距离和跌倒率作为补充指标。

Planner tracking MSE

指标单位valid 条件
joint position MSErad²完整且连续的 B0...B23；所有 transition planner-valid；窗口内无 reset；plan_id 一致。
joint velocity MSE(rad/s)²
root position RMSEm
root rotation geodesic errorrad
root linear/angular velocity MSE(m/s)²、(rad/s)²
active swing-foot RMSEm

实际轨迹与规划轨迹统一锚定到本规划段的实测 B0 局部坐标系，避免重规划时世界坐标跳变。无效窗口不写成零误差，而是从 MSE 分母中排除，并单独报告：

valid_window_ratio = 完整且有效的 24 帧窗口数 / 发起的规划窗口数
关键统计边界：碰撞率、跌倒率、通过位移统计全部回合；只有轨迹跟随 MSE 统计 valid-only。否则规划失败的困难样本会被删除，造成虚假的低误差和高通过性。

  • 所有模型使用相同 layout seed、障碍位置、command 顺序和目标点。
  • 成功率、碰撞率和跌倒率使用 layout-level bootstrap 95% CI。

  • 相同 layout 上做 paired bootstrap 或 Wilcoxon；二值配对结果使用 McNemar；多重比较采用 Holm 校正。

十、测试与验收

不依赖 Isaac 的单元测试

  • 命令协议生成 120 组，vx/vy 均不含 0，yaw 含 0。
  • 专项每个 density 的 1500 条 episode 中三档 vx 各 500 条，并且顺序由固定 seed 打乱。
  • 目标方向只在 reset 和 23、46、69... transition 边界更新。
  • 24 帧窗口的 B0...B23 索引、valid mask 和 MSE 分母正确。
  • 大、小障碍 episode rate 只对同类障碍计数，重复接触不会重复计 episode。
  • manifest、原子写入和 resume 不重复、不丢失 condition。
  • 指标累加器不含逐 env Python 热循环。

真实 Isaac 验收

  1. 四个 checkpoint 分别执行 16-env smoke：真实加载 observation、deterministic action、env.step、shadow planner 和 JSONL 写入；断言 action/state/metric 无 NaN。
  2. 四个 checkpoint 分别执行 500-env 并行验收，至少运行 48 transitions；确认环境只初始化一次、Parallelism 批量规划正常、首个完整 valid 24 帧窗口产生 MSE，并正常退出。
  3. 单个模型执行三套 suite 的缩小版完整 episode，覆盖成功、碰撞、跌倒、位移、goal timeout 和 resume。
  4. 记录 policy、planner、env step、metric 和 I/O 耗时，输出 env-steps/s；不设置依赖机器负载的硬性能阈值。

Smoke 输出设置 is_smoke_test=true，汇总工具拒绝把 smoke 结果混入论文正式结果。

十一、已确认决策清单

  • 只做仿真，不做真实机器人定量实验。
  • 采用统一 benchmark harness；四个权重顺序运行。
  • 复杂混合场景与大小障碍同时存在，速度回合内固定。
  • 复杂场景使用去掉 0 的 120 组 mixed velocity。
  • 专项跑道为 10×2 m 平地，目标点计算方向，vy=0，yaw 由目标控制器生成。
  • Parallelism 使用 24 帧 horizon、23-transition replan；专项方向在该边界更新。
  • 环境一次初始化，500 个 layouts 并行，episode 只 reset 状态和 command。
  • 行为指标统计全回合，轨迹 MSE 只统计完整 planner-valid 窗口。
  • 固定 manifest、配对 seeds、deterministic inference、bootstrap CI 和 paired tests。
