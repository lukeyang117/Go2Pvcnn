Parallelism Joint AMP 训练

把 Parallelism 生成的 24 帧运动学可行状态轨迹作为 AMP expert 数据，让已有基本行走能力的纯 PPO policy 学习规划轨迹的局部运动模式；规划失败进入 standstill 时，AMP 奖励、AMP GAE、判别器样本和归一化统计均停止作用。

最终架构决定

新增独立实验 parallelism_tracking_cross_large_complex_amp。Actor 从 cross_large_complex_ppo 已训练 checkpoint 初始化；Parallelism 仅在训练期生成 expert state window；判别器只读取 24 帧关节与局部 root 状态，不读取 terrain、command 或 action；PPO 使用基础价值与 AMP 价值两个通道，standstill transition 的 AMP advantage 严格为 0。

一、目标与边界

要解决的问题

  • 已有 pure PPO policy 能基本行走，但没有利用 Parallelism 的避障运动学轨迹。
  • Parallelism 输出的是 state trajectory，不是力矩、关节 action，也不是动力学可执行控制序列。
  • AMP 的角色是给 policy 一个“真实执行状态窗口应接近 planner 状态窗口分布”的附加学习信号，不把 planner 输出直接监督成 action。
  • Parallelism 规划失败时，policy 应继续依靠原 PPO reward 学习或站立，不能被无意义的 AMP 信号惩罚。

明确不做

  • 不把 terrain、semantic map、velocity command 或 policy action 输入判别器。
  • 不把世界绝对 root XY 输入判别器，避免 D 记住地形 tile 或环境原点。
  • 不把 Parallelism 24 帧当成 24 个 action target，不增加行为克隆 loss。
  • 不修改 distillation 实验和 pure PPO 实验的现有训练语义。
  • 不让部署 Actor 依赖 planner、判别器、AMP 历史或任一 Critic。
  • 首版不加入足端、接触相位和障碍物语义；先验证 root + joint state window 是否有效。
运动学 expert 的限制

Parallelism 只保证运动学与几何可行，不保证真实动力学可执行。基础 locomotion reward、接触仿真和已有 PPO checkpoint 仍负责动力学稳定性；AMP 权重必须作为附加项渐进引入，不能覆盖基础 PPO 目标。

二、总体架构

Parallelism从真实 s_t 与地形规划 24 帧 expert state。
AMP History逐步压入 expert r_{t+1} 与 agent s_{t+1}。
Discriminator判断 24 帧 window 来自 expert 还是 policy。
Dual Value PPO分别估计 base return 与 AMP return，再组合 Actor advantage。
Deployment仅导出 Actor；其他训练模块全部移除。
critic_obs_t ───────────────┬─> V_base(s_t)
                            └─> stop-grad critic feature + AMP context ─> V_amp(s_t)

policy_obs_t ─> Actor ─> a_t ─> Isaac physics ─> s_{t+1} ─┐
Parallelism(s_t, terrain) ────────────────> r_{t+1} ───────┼─> 24-frame paired history
                                                           └─> D(agent window) ─> r_amp_t

base env reward ─> base GAE ─┐
AMP reward + gate ─> AMP GAE ├─> A_actor = A_base + lambda_amp * A_amp ─> PPO Actor update
                              └─> separate value losses

合计3939 × 24 = 936 维 discriminator observation

局部 root 变换

p_ref = root_pos[:, -1]
yaw_ref = heading(root_rot[:, -1])
R_ref = Rz(yaw_ref)

root_pos_local[k]     = R_ref^T (root_pos[k] - p_ref)
root_rot_local[k]     = R_ref^T R(root_rot[k])  -> first two columns -> 6D
root_lin_vel_local[k] = R_ref^T root_lin_vel_world[k]
root_ang_vel_local[k] = R_ref^T root_ang_vel_world[k]

expert 与 agent 各自使用自己窗口的末帧建立局部 frame。这样 D 能看到避障轨迹的弯曲、横移和高度变化，但看不到世界绝对位置，也不需要 terrain 输入。

禁止进入 D 的信息

terrain、semantic id、height map、command、action、plan id、plan_valid、amp_active 和 history ratio 均不拼入 936 维 D 输入。门控字段只服务算法和 AMP Critic，不能让 D 通过有效性标签投机分类。

四、逐步时间对齐

一个 transition 的严格顺序

时刻 t，环境真实状态为 s_t

1. Actor(policy_obs_t) 采样 a_t
2. AMP Critic 读取 history 在 s_t 时刻的 context_t
3. ParallelismReferenceManager.prepare_step_reference()
   - 必要时先 replan
   - 冻结下一控制目标 r_{t+1}
   - 冻结本 transition 的 step_plan_valid
4. physics(a_t) 得到 s_{t+1}
5. 若 transition 有效：push(expert=r_{t+1}, agent=s_{t+1})
6. 由更新后的 24 帧 agent window 计算 r_amp_t
7. storage 写入属于 (s_t, a_t, s_{t+1}) 的 base reward、AMP reward 和 gates

判别器比较的是同时刻的 r_{t+1} 与 s_{t+1}。不能把执行后的 s_{t+1} 与旧的 r_t 比较，也不能在 physics 后才决定本步使用哪个 reference。

replan 边界

Plan A: A0 是实测状态，控制目标为 A1 ... A23
Plan B: B0 是 step 23 后的新实测状态，控制目标为 B1 ... B23

transition 23: push(A23, S23)
transition 24: prepare 时 replan B，push(B1, S24)
transition 40: push(B17, S40)

step 40 的 expert window = [A17 ... A23, B1 ... B17]  共 7 + 17 = 24 帧
step 40 的 agent  window = [S17 ................ S40]  共 24 帧

历史不记录 plan id，也不因正常成功 replan 清空。它只表达连续执行时间，允许一个窗口跨越相邻 planning segment。新 plan 的 frame 0 只在 reset 或从 invalid 恢复时用于初始化历史；正常滚动 replan 不重复压入 B0。

五、24 帧历史与 40 步 rollout

24 帧是 state window，不是 24 个 PPO action

窗口包含 24 个状态采样点，时间跨度为 (24 - 1) × 0.02s = 0.46s。episode/reset 或 invalid 恢复时，frame 0 使用同一真实状态初始化 expert 与 agent，位置、姿态及速度都取当前实测值；随后每个 transition 追加一帧。

时刻history 内容valid_countAMP reward
reset/recovery 成功 plan[r0=s0] / [s0]10
transition 1 后[r0,r1] / [s0,s1]20
transition 22 后23 帧230
transition 23 后完整 24 帧24启用
transition 24..40ring buffer 每步丢最老帧、追加最新帧24保持启用

40 步 rollout 的含义

第一个 PPO iteration

从新 reset 开始，40 个 transition 全部存入 PPO storage。前 22 个 transition 只有 base PPO；第 23 到第 40 个 transition 有完整 24 帧窗口，共 18 个 AMP-active transition。

后续 PPO iteration

rollout storage 在 update 后清空，但 AMP manager 的 per-env ring buffer 不清空。若没有 done 或规划失败，下一个 40 步 rollout 从第 1 步起即可继续产生 AMP reward。

4096 环境 memory guard

现有 scripts/train.py 会把 4096 环境的 num_steps_per_env 从 40 改为 24。AMP history horizon 仍为 24，且跨 PPO iteration 保留；rollout 变短不会改变 D 的窗口长度，也不会要求在每个 rollout 内重新凑满历史。

六、规划失败与 standstill 门控

状态机

事件history算法行为
正常成功 replan保留，不按 plan id 分段AMP 连续
plan_valid=False 或 standstill_latched=True立即清空，valid_count=0r_amp=0，不进 D/replay/normalizer，AMP GAE 截断
invalid 期间持续 standstill保持空只有 base PPO 继续训练
下一次 plan 恢复有效用当前实测状态与新 plan frame 0 初始化为 count 1继续收集，但 reward 仍为 0
恢复后 history 达到 24完整 window从当前 transition 恢复 AMP
episode done/reset对应 env 行清空；新 episode frame 0 重新初始化禁止跨 episode 拼 window；timeout 对 base PPO 保持原 bootstrap，对 AMP 视为边界并截断
 
history_ratio = valid_count / 24

amp_state_active = plan_valid
                   AND NOT standstill_latched
                   AND valid_count == 24

amp_reward_active_t = step_plan_valid_t
                      AND NOT standstill_latched_after_step
                      AND valid_count_after_push == 24

r_amp_t = amp_reward_active_t * AMPReward(D(agent_window_t))

amp_active 与 history_ratio 的区别

  • amp_active 是硬门：决定当前 transition 是否有 AMP reward、AMP advantage、AMP value loss 和 D 样本。
  • history_ratio 是进度：告诉 AMP Critic 当前离完整有效窗口还有多远，使它能区分“刚恢复 1/24”和“即将恢复 23/24”。
  • 两者都不输入 Actor 和 D；只作为 AMP value 分支的 critic context 与算法 mask。

七、双价值通道

不是两个 Actor，而是两个 return estimator

分支预测目标输入训练范围
V_base原环境 locomotion/base reward return现有 critic observation全部 transition
V_amp门控后的 AMP reward returnbase critic feature 的 stop-gradient 副本 + [amp_state_active, history_ratio]仅 AMP-active transition

代码上是一个 AmpActorCriticCNN 模块，保留现有 actor、critic、CNN 和 std 参数名，并新增 amp_value_head。AMP value loss 不反向更新 Actor、base critic 或 base critic CNN；这样 pure PPO checkpoint 可精确加载，AMP loss 也不会直接扰动基础价值分支。

AMP GAE 的严格边界

m_t     = amp_reward_active_t
m_next  = 下一状态是否仍处于完整有效 AMP 段
terminal = done_t

delta_amp_t = m_t * (
    r_amp_t
    + gamma * (1 - terminal) * m_next * V_amp(s_{t+1})
    - V_amp(s_t)
)

A_amp_t = delta_amp_t
          + gamma * lambda * (1 - terminal) * m_t * m_next * A_amp_{t+1}

当本步 standstill 或下一步进入 standstill 时，递归立即断开。未来恢复后的 AMP reward 不会穿过 invalid 区间回传。

Advantage 归一化与组合

A_base_norm = normalize(A_base, all rollout rows)
A_amp_norm  = masked_normalize(A_amp, only m_t == 1 rows)
A_amp_norm[m_t == 0] = 0

A_actor = A_base_norm + lambda_amp(iteration) * A_amp_norm

组合后不再做全局二次归一化。否则 AMP-active 样本改变全局 mean/std，会间接改变 standstill 行的 base advantage，破坏“standstill 不受 AMP 奖励作用”的要求。

严格不变量

对任意 m_t=0 的 transition，必须逐元素满足 A_actor_t == A_base_norm_t；其 AMP value loss、AMP reward、D sample weight 均为 0。

八、判别器与 PPO 更新

Discriminator

  • 输入：flatten 后的 [batch, 936]。
  • 网络：MLP 936 -> 1024 -> 512 -> 256 -> 1，LeakyReLU，输出 logit。
  • 标签：Parallelism expert window 为 1，policy agent/replay window 为 0。
  • loss：二元交叉熵 + expert/agent input gradient penalty + final logit weight L2。
  • 首版参数参考 MimicKit Go2：grad_penalty=5、logit_reg=0.01、reward_scale=2。

AMP reward

p_expert = sigmoid(D(normalize(agent_window)))
r_amp_raw = -log(max(1 - p_expert, 1e-4)) * 2.0
r_amp = amp_reward_active * r_amp_raw

该公式与 MimicKit AMPAgent._calc_disc_rewards() 对齐。首版 lambda_amp 从 0 线性升到 0.1，用 500 个 PPO iteration 完成 warm-up；基础 reward 权重保持 1.0。warm-up 防止随机初始化 D 在训练初期压过已有行走能力。

每个 PPO iteration 的数据流

  1. 冻结 D 与 AMP normalizer，在 40 步 rollout 中逐步计算 active transition 的 AMP reward。
  2. active expert/agent window 立即压入定长 AMP replay；inactive 行完全跳过。
  3. rollout 完成后，分别计算 base GAE 与 masked AMP GAE。
  4. 使用组合 advantage 更新 Actor，同时分别更新 base value loss 与 masked AMP value loss。
  5. 只用本轮 active expert/agent 原始窗口更新 normalizer，再从最新样本与 replay 采样更新 D；更新后的 normalizer 与 D 从下一轮 rollout 开始用于 reward。
  6. 清 PPO rollout storage；不清 environment AMP history 和 D replay。

九、初始化、恢复与部署

从 pure PPO warm start

  • 新参数 --amp_init_checkpoint /absolute/path/model_x.pt 只允许 AMP 新 run 使用。
  • 精确加载 pure PPO 的 Actor、action std、Actor CNN、base Critic、base Critic CNN 和 observation normalizer。
  • 不加载 pure PPO optimizer，不继承 pure PPO iteration；AMP run 从 iteration 0 和新 optimizer 开始。
  • amp_value_head、D、D optimizer、AMP normalizer 与 replay 全部重新初始化。
  • 加载时逐项报告 missing/unexpected keys；除明确的 AMP 新增 key 外，任何缺失都报错，禁止静默部分加载。

AMP run resume

  • --resume 从 AMP 自己的 experiment log root 加载完整 Actor、两个 value 分支、D、两个 optimizer、normalizers 和 iteration。
  • 不保存 simulator AMP history；resume 后新环境从 frame 0 重新积累，达到 24 帧再恢复 AMP。
  • 首版不保存 replay buffer，避免 checkpoint 体积膨胀；resume 后 replay 重新填充。

部署导出

play/export 仅调用 act_inference(policy_obs)。部署 checkpoint 可以只保留 Actor、Actor CNN、std/normalizer；不创建 Parallelism manager、AMP manager、D 或任一 value branch。
