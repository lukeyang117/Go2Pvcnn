Parallelism 有效轨迹与速度 Fallback 设计

日期：2026-08-20　范围：large teacher RL　状态：设计确认后进入实现
当 Parallelism 成功规划时，policy 学习有效的 joint、root、foot reference；当规划失败或 standstill 时，reference 输入置零，policy 改为跟踪当前速度 command。碰撞检测奖励不依赖规划有效性，large teacher 的权重从 -2.0 调整为 -10.0。

一、目标与边界

  • 保留现有 Parallelism 的规划逻辑、24 帧轨迹和第 23 个控制步重规划时序。
  • 不新增 planner root velocity observation。
  • Actor 和 Critic 都能识别当前规划是否有效。
  • 规划失败时不能因为无效 reference 牵制 policy，也不能因为 reference 误差触发 reset。
  • 规划失败时仍然保留 command velocity reward，使 policy 能够继续学习走路。
  • large teacher 的速度 command 每 10 秒刷新一次：resampling_time_range=(10.0, 10.0)。
  • 碰撞惩罚与 DOF 类行为约束一致，始终有效，不因 planner 失败而关闭。
本设计以 large teacher 为主要目标。distillation 可以继承 large teacher 的 planner-valid 接口和环境行为；本次不额外改动其 student 专用 reward/observation 定义。

二、时间与状态定义

每个控制步的目标仍然是 reference 的下一帧：

当前真实状态 t
    |
    | Parallelism 当前周期缓存
    v
policy observation 使用 reference[t+1]
reward / termination 使用同一 reference[t+1]
physics 执行动作
    |
    +-- 到第 23 个控制步：重新规划，下一周期从新轨迹的第 1 帧输入

plan_valid 是每个环境独立的状态，在一次规划周期内保持不变：

事件plan_valid处理
reset 后规划成功1输入真实 reference，开启 reference reward 和 reference termination。
reset 后规划失败0reference 置零，保留 command reward，屏蔽 reference termination。
第 23 步重新规划成功1下一周期恢复真实 reference。
第 23 步重新规划失败0下一周期进入速度 fallback。
10 秒 command 刷新并触发重规划按新轨迹更新command 刷新周期为 10 秒；planner 仍保持第 23 个控制步的独立重规划。

三、Manager 修改

文件：

Go2Pvcnn/tracking/managers/parallelism_reference_manager.py

新增 step 级别的有效状态：

step_plan_valid: Tensor[num_envs] bool

它与当前已经缓存的 step_joint_pos、step_root_pos_w、step_foot_pos_w 使用相同的 t+1 时间戳。不能把“reference cache 已准备”误当成“planner 轨迹有效”。

  • trajectory.valid 为真时，step_plan_valid=1。
  • trajectory.valid 为假时，step_plan_valid=0，并保持整个规划周期有效。
  • reset 时清理周期状态。
  • 成功重规划时清除 standstill 状态。
  • 失败重规划时只更新 fallback 状态，不修改 IsaacLab 真实机器人状态。

5.3 碰撞惩罚

文件 parallelism_small_obstacles_env_cfg.py 中的基础默认值保持不动。large teacher 在：

Go2Pvcnn/tracking/parallelism_cross_large_complex_env_cfg.py

显式覆盖：

parallelism_geometry_collision.weight = -10.0

当前值为 -2.0，本次提高到 -10.0。碰撞函数的检测逻辑不改，仍然使用 Parallelism 几何碰撞检测；只提高负奖励强度。

该惩罚不乘 plan_valid：

plan_valid=1：碰撞会惩罚
plan_valid=0：碰撞仍然惩罚

这样 planner 失败时，policy 仍然不能通过撞击障碍物来获得速度跟踪收益。

large teacher 同时将安全跨越小障碍的足端奖励覆盖为：

active_swing_foot_on_small_obstacle.weight = 10.0

该奖励只在 large teacher 配置中提高；small-obstacles 基础配置仍保持 0.5。

6.1 Reference termination

以下 termination 仅在 plan_valid=1 时检查：

parallelism_ref_root_z_too_far
parallelism_ref_projected_gravity_too_far
parallelism_ref_joint_pos_too_far

当 plan_valid=0 时返回 false，不能因为无效 reference 与机器人真实状态不同而 reset。

6.2 安全 termination

以下 termination 不受 plan_valid 影响：

base_contact
bad_orientation
time_out

它们代表真实机器人状态问题，fallback 阶段也必须保留。

6.3 Standstill

large teacher 继续关闭 parallelism_consecutive_standstill。standstill 只作为 planner 诊断和 fallback 触发原因，不直接终止 episode。

八、Curriculum 修改

文件：

Go2Pvcnn/tracking/mdp/curriculums.py
  • 有效轨迹：使用有效帧的 joint/root/reference tracking error。
  • 无效轨迹：不使用置零 reference 产生的误差。
  • fallback 阶段：使用 command velocity error、运动进度和安全 termination 判断 policy 是否仍能走路。
  • planner invalid 本身不作为 terrain curriculum 的失败条件。
  • planner invalid ratio 只作为诊断，判断 terrain 是否让规划器频繁失败。
这样 terrain curriculum 的失败原因可以分开：是 planner 没有轨迹、policy 没跟上速度，还是机器人发生了真实安全问题。

large teacher command 配置：

commands.base_velocity.resampling_time_range = (10.0, 10.0)

这只决定速度 command 什么时候变化，不改变 Parallelism 每 23 个控制步重规划的周期。

十、验证标准

  1. planner 成功时，Actor/Critic 收到真实 reference 和 plan_valid=1。
  2. planner 失败时，Actor/Critic 收到置零 reference、当前 command 和 plan_valid=0。
  3. 无效轨迹不会触发 root/joint reference termination。
  4. base contact、bad orientation 和碰撞奖励在有效、无效两种状态下都正常工作。
  5. large teacher 的碰撞 reward 权重实际为 -10.0，small-obstacles 基础配置仍为 -2.0。
  6. TensorBoard 中 valid 和 invalid 指标不混合、不共享错误分母。
  7. 1024 环境短训练可以正常 reset、重规划、采集和 PPO 更新。
新增 Actor/Critic 的 plan_valid 后，观测维度会增加一维。旧模型不能直接 resume，需要重新训练 large teacher。
