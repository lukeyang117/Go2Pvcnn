Go2 AME 六通道基线训练设计

在现有 Go2 PPO 复杂混合任务上加入 AME 网络架构，建立不使用 Parallelism 数据的对比实验。

一、已确认结论

  • 环境、机器人、动作空间、terrain、障碍物课程和 reward 使用现有 cross_large_complex_ppo。
  • 算法使用 Go2 当前 PPO 配置；只把策略网络替换成 AME 编码器，避免 PPO 超参数成为额外变量。
  • AME 不读取 Parallelism reference、planner validity、AMP discriminator、teacher action 或 24 帧轨迹。
  • AME 的地图输入扩展为六通道：[x_local,y_local,z_local,terrain,small_obstacle,large_obstacle]。
  • 所有 AME observation 不加噪声；保留有限值处理和确定性的裁剪。
  • 所有代码通过新增文件实现，不修改现有 PPO、AMP、Distillation、Teacher 的源文件和配置。

二、AME 原版依据

参考仓库 raw/AME_Locomotion 的 ray_hits_s() 与 ActorCriticEncoder：

  • 射线命中点由 world frame 转换为传感器 local frame，得到每个网格点的 (x,y,z)。
  • 原版默认 map_scan_dim=(33,21,3)，CNN 第一层为 Conv2d(3,16,kernel_size=5,stride=2)。
  • CNN 输出 64 维局部 token，state 投影为 64 维 query，再经过 MultiheadAttention(64,16)。
  • Actor 和 Critic 采用独立的 state projection，MLP 均为 [512,256,128]，激活函数为 ELU。
  • AME 原版没有 semantic channel；本实验的后三个通道是 Go2 语义信息扩展。
论文表述约束：六通道版本应称为“AME with semantic augmentation”或“AME-XYZ-Semantic”，不能称为未经修改的原版 AME。它与 PPO 的差异包含输入表示和编码器结构两部分。

三、六通道观测定义

通道内容来源处理
0x_localsemantic height scanner 的 ray hitworld 点减 sensor position，再做 local inverse rotation；有限值检查
1y_local同上与 AME 相同的局部坐标定义；不加噪声
2z_local同上保留 AME 的局部高度语义；确定性裁剪，不加噪声
3terrain one-hotsemantic id = 0固定类别 mask，max-pool 到 16×16
4small obstacle one-hotsemantic id = 1固定类别 mask，max-pool 到 16×16
5large obstacle one-hotsemantic id = 2固定类别 mask，max-pool 到 16×16

输出张量为 [N,6,16,16]。xyz 使用 area pooling，语义 mask 使用 max pooling，避免小障碍在下采样时被平均为背景。Actor 和 Critic 使用相同的空间排列，但分别来自 policy 与 critic observation group。

传感器姿态处理遵循 AME：当 scanner 为 yaw alignment 时使用 yaw-only quaternion；不把 world root position 作为策略输入。

六、数据流和时间顺序

reset()
  -> semantic scanner 更新 ray_hits_w / semantic_map
  -> ame_xyz_semantic_scan() 生成 [N,6,16,16]
  -> AME runner 获取 policy_obs 与 critic_obs

for rollout step t = 0 ... 39:
  1. policy_obs_t -> ActorCriticAME.act() -> action_t
  2. env.step(action_t)
  3. 收集 reward_t, done_t, critic_obs_{t+1}
  4. PPO storage 写入 observation_t, action_t, log_prob_t, value_t, reward_t, done_t

after 40 steps:
  5. critic_obs_40 -> evaluate() 得到 bootstrap value
  6. PPO 按 gamma=0.99, lambda=0.95 计算 GAE/return
  7. 5 epochs × 4 minibatches 更新 Actor、Critic 和共享 AME encoder
  8. 清空 rollout storage，进入下一轮采样

AME 没有历史轨迹缓存。每个 PPO transition 是单帧 state/map 输入；AME 的 attention 只在当前帧的地图 token 与当前 state query 之间计算。40 步只决定 PPO 的采样批次，不改变 AME 的地图帧数。

八、Checkpoint 与恢复

  • AME checkpoint 独立保存完整 ActorCriticAME、PPO optimizer 和训练迭代号。
  • 不能从现有 PPO/AMP/Distillation/Teacher checkpoint 直接恢复，因为网络参数名、CNN 输入通道和内部结构不同。
  • AME 自己的 checkpoint 可以通过显式路径 resume；恢复时校验 observation dimension、action dimension 和 AME architecture signature。
  • 训练目录和 TensorBoard run name 使用 cross_large_complex_ame，不与既有日志目录复用。

十、风险与论文解释

  • 六通道 AME 与两通道 PPO 不是纯架构 ablation。论文需要把输入差异单独写清楚，并可增加“AME encoder + 两通道输入”的附加 ablation。
  • xyz area pooling 可能弱化局部尖锐几何；语义 max pooling 用于保留障碍存在性，但不保证精确边界。
  • 关闭所有 observation noise 会改变当前 PPO 的训练分布。若论文要求严格复现 PPO 训练分布，应另做一组 AME-with-PPO-noise 对照；本设计的主 AME 实验遵循用户确认的无噪声口径。
  • AME 的 BatchNorm 在训练和 play 必须正确切换 train()/eval()，否则评测结果不可比较。
