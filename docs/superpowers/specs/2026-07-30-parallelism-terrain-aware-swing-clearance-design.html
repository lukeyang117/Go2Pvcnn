Parallelism 地形感知 Swing Clearance 设计

目标是在不放松 hard filter、不增加 clearance score、不改变 touchdown score 的前提下，让 foot swing 的抛物线自动越过 XY 路径上的高程障碍，使小障碍物前的规划不再因为 FL/RL 摆腿碰撞全灭而进入 standstill。

背景与结论

当前复现中，机器人向前走到小障碍物前后，规划进入 standstill。按腿拆解后，卡住轮次为 per_leg_valid=[0,29,0,29]，即 FL 和 RL 的候选被 hard filter 全部清空。

进一步检查 official collision surface points 与 Go2 visual mesh 的 USD local AABB，thigh/calf 碰撞点与 mesh 基本对齐；因此本设计不处理 collision frame 错位，而是处理 swing 轨迹本身对高程障碍不感知的问题。

本次设计不改 score。最终 touchdown 选择仍只使用速度跟踪 score；semantic、joint、landing、collision 仍然是 hard filter。

核心思路

保留抛物线形式，但抛物线高度不再是固定的 swing_height_m。对每条 swing，从当前 stance 足端到候选 touchdown 足端，沿 XY 路径采样高程，计算一条能够越过这些高程点的最小抛物线高度。

xy(t) = lerp(start_xy, touchdown_xy, t)
terrain_z(t) = height_map_query(xy(t))
safe_z(t) = terrain_z(t) + swing_clearance_m

base_z(t) = lerp(start_z, touchdown_z, t)
shape(t) = 4 * t * (1 - t)

required_A(t) = (safe_z(t) - base_z(t)) / shape(t)
A = max(min_swing_apex_m, max_t(required_A(t)))

foot_z(t) = base_z(t) + A * shape(t)

其中 A 是每条 swing 轨迹的标量抛物线高度，不是矩阵。实际张量形状会随调用方变化，例如候选检查中为 [num_envs, candidates] 或扩展后的 [num_envs, legs, candidates]。

参数语义

可视化面板swing_clearance_m

调试面板只调这个参数。它表示 foot swing 轨迹相对 XY 路径高程图的额外安全高度。

建议滑条范围保持 [0.0, 0.25]。默认值可以先使用 0.05，也可以继承当前面板初始值的可用体验。

配置固定min_swing_apex_m

配置中保留默认最小抛物线高度 0.08m，不放到调试面板。

平地或者路径高程很低时，实际抛物线仍保持自然抬脚高度，避免脚尖贴地。

旧的 swing_height_m 语义应迁移为 min_swing_apex_m 或逐步废弃。新面板标签和传入配置统一命名为 swing_clearance_m。

代码结构设计

新增 terrain-aware swing 函数

在 Go2Pvcnn/extension/parallelism/swing.py 中保留旧 swing_curve()，新增函数，例如：

terrain_aware_swing_curve(
    start_w,
    touchdown_w,
    terrain,
    frames,
    clearance_m,
    min_apex_m,
)

这个函数负责构造 XY 插值、批量查询高程、计算 A、输出连续抛物线轨迹。

替换 planner 中两处 swing 调用

  • _swing_collision_mask()：候选硬过滤时使用 terrain-aware swing。
  • _assemble_foot_targets()：最终输出执行轨迹时使用同一套 terrain-aware swing。

这样检测轨迹和执行轨迹一致，避免“检查通过但播放轨迹不同”的问题。

并行实现要求

实现必须保持 GPU 并行风格，不使用 Python 分支决定单个候选是否有效。允许当前已有的按腿循环，但每条腿内部的 candidate × frame 高程查询、A 计算、IK/FK/collision 都应使用 torch 张量批处理。

# 候选 swing 检查中的典型形状
start_w:      [B, C, 3]
touchdown_w:  [B, C, 3]
xy_path:      [B, C, T, 2]
height_query: [B, C*T]
A:            [B, C]
swing:        [B, C, T, 3]

端点 t=0 和 t=1 的 shape(t) 为 0，计算 required_A 时必须用 torch mask 或 clamp 跳过端点，最终强制端点 z 等于 start/touchdown z。

Viewer 调试面板

Parallelism 调试面板中，原 swing_height 控件改为 swing_clearance_m。用户只调 clearance，不直接调最小抛物线高度。

  • 面板显示名：swing_clearance_m 或短标签 clearance_m。
  • 传入 ParallelismCfg.swing_clearance_m。
  • ParallelismCfg.min_swing_apex_m = 0.08 固定保留在 config 中。

测试与验收

单元测试

  • 平地时 terrain-aware swing 与旧抛物线高度行为一致：实际 apex 至少为 min_swing_apex_m。
  • 路径中间有高程障碍时，抛物线在采样点满足 z >= terrain_z + swing_clearance_m。
  • 端点保持：第一帧 z 等于 start z，最后一帧 z 等于 touchdown z。
  • 函数支持批量 [B, C, 3] 输入，输出 [B, C, T, 3]。

IsaacLab 真实测试

在 standstill_fallback_enabled=True 的情况下，复现“小障碍物在前方”的场景，连续多周期播放 parallelism 轨迹。

需要并行测试多组速度，至少覆盖：

vx:   [0.2, 0.5, 1.0]
vy:   [-0.5, 0.0, 0.5]
vyaw: [-1.0, 0.0, 1.0]

验收指标：

  • 正向小障碍场景中，连续规划不进入 standstill=True。
  • result.feasible=True，每条腿 per_leg_valid 都大于 0。
  • root 在非零速度命令下有对应方向位移，不能卡在障碍物前。
  • root 的 XY 轨迹必须穿过前方小障碍物区域：测试中记录小障碍物的世界坐标和外接半径，检查 root path segment 在命令方向上的投影从障碍物前侧越过障碍物后侧，且横向距离落在障碍物影响宽度内。
  • hard filter 仍保持有效：无 joint limit、landing、semantic touchdown、collision 的无效候选被选中。

非目标

  • 不加入 leg-link clearance score。
  • 不放松 collision hard filter。
  • 不修改官方 collision shape 参数或 link frame。
  • 不改变 candidate 圆采样、semantic touchdown margin、速度 tracking score。
