Parallelism 大障碍物横向绕行设计

日期：2026-08-11　分支：parallelism-large-obstacles-rl

1. 设计目标

在现有 Parallelism root 轨迹生成之前，根据当前速度方向上的 semantic_id=2 大障碍物，给 root 速度增加横向分量，使 root 在大障碍物前提前绕行。

本设计只修改 root 轨迹生成前的速度命令，不修改以下逻辑：

  • touchdown 候选采样；
  • swing 足端轨迹生成；
  • 足端 IK；
  • 官方碰撞点检测；
  • standstill、重规划周期和已有规划输出接口。
整个绕行判断必须保持批量 GPU 并行。不能按环境、障碍物点或轨迹点使用 Python 循环逐个处理。

2. 大障碍物和检测矩形

当前 semantic course 中，大障碍物的基础尺寸为直径 0.45m、高度 0.55m。横向检测矩形参考该障碍物宽度， 并额外覆盖 Go2 的横向占用和安全余量。

参数初始值含义
large_obstacle_rect_width_m 0.70m 矩形总宽度，横向覆盖约 0.45m 大障碍物和 Go2 横向安全范围。
large_obstacle_rect_length_m 1.20m 矩形沿当前速度方向的长度，用于判断前方障碍物和距离衰减。
large_obstacle_lateral_speed_max_mps 0.25m/s 障碍物足够近时允许增加的最大横向速度。

矩形起点为当前 root 的世界坐标，root 位于矩形后边的中点。矩形长边沿当前 平移速度方向，短边沿速度方向左侧。

3. 速度方向坐标系

不使用 root 朝向作为检测前方，而使用当前平移速度方向。

当前 root 在自身坐标系下的平移速度为：

v_b = [vx, vy]

使用当前 root 的 yaw 将它转换到世界坐标：

vw = Ryaw vb

当速度足够大时，定义世界坐标中的前进单位向量：

f = vw / (||vw|| + ε)

定义速度方向左侧单位向量：

l = [-fy, fx]

当平移速度接近零时，没有可靠的速度方向。此时不触发大障碍物横向绕行， 保持原有速度命令和原有 standstill 逻辑。

4. 语义体素投影

对当前 1.5m × 1.5m 地图内每个体素点计算相对于 root 的位置。设第 i 个体素世界坐标为 p_i，当前 root 世界坐标为 p_r：

di = pi - pr

沿速度方向和横向方向的投影分别为：

Si = di · f
Li = di · l

其中：

  • S_i 是体素沿当前速度方向的前向距离；
  • L_i 是体素相对速度中心线的横向位置；
  • L_i > 0 表示障碍物偏左；
  • L_i < 0 表示障碍物偏右。

5. 矩形触发条件

只把同时满足以下条件的体素作为当前前方大障碍物：

semantic_id == 2
0 <= S_i <= large_obstacle_rect_length_m
abs(L_i) <= large_obstacle_rect_width_m / 2

批量触发掩码为：

front_large_i =
    (semantic_i == 2)
    & (S_i >= 0)
    & (S_i <= rect_length)
    & (abs(L_i) <= rect_half_width)

每个环境是否触发：

has_front_large = front_large_i.any(dim=(-1, -2))

如果没有满足条件的体素，则不增加横向速度。矩形外的大障碍物不会触发当前 root 的绕行。

6. 加权 mean_L：只决定方向

mean_L 不再决定横向速度大小，只决定向左还是向右。 对矩形内的大障碍物点，横向距离越远，权重越小。

横向投影距离：

Di = |Li|

横向权重：

wi = exp(-Di2 / (2σL2))

其中：

σL = large_obstacle_rect_width_m / 2

加权横向平均位置：

mean_L = (Σ front_largei wi Li) / (Σ front_largei wi + ε)

方向判定：

mean_L >  deadband  -> 障碍物偏左，横向速度向右
mean_L < -deadband  -> 障碍物偏右，横向速度向左
abs(mean_L) <= deadband -> 使用 large_obstacle_default_side

当障碍物左右对称导致 mean_L≈0 时，方向使用固定的 large_obstacle_default_side。此时不会因为 mean_L=0 而关闭横向绕行。

7. 按障碍物距离生成横向速度

横向速度大小只由障碍物沿速度方向的最近距离决定。对当前矩形内的大障碍物点：

Smin = min {Si | front_largei}

定义接近程度：

ρ = clamp(1 - Smin / large_obstacle_rect_length_m, 0, 1)

因此：

  • 障碍物在矩形远端时，ρ 较小，横向速度较小；
  • 障碍物靠近 root 时，ρ 较大，横向速度较大；
  • 障碍物接近 root 时，横向速度达到设定上限。

最终横向速度大小：

|vlat| = large_obstacle_lateral_speed_max_mps · ργ

初始使用线性衰减，即 γ=1。不额外增加第四个必调参数； 指数可以作为后续固定实现参数，后续确有需要再暴露为配置项。

最终横向速度带方向：

vlat = side · |vlat|

其中 side 已经由 mean_L 和 large_obstacle_default_side 决定。横向速度最后限制在已有 vy_limit 内。

8. 速度合成和 root 轨迹

横向绕行速度在世界坐标系中为：

vavoid,w = vlat l

将它转换到当前 root 坐标系后，与用户原始速度命令相加：

vcmd,new = vcmd,original + RyawT vavoid,w

之后继续调用原有 root 轨迹生成逻辑：

修正后的速度命令
    → root XY / yaw 轨迹
    → terrain-following root Z / roll / pitch
    → 原有 touchdown、swing、IK、碰撞检测

大障碍物逻辑不直接修改足端轨迹，也不直接修改关节角，只改变 root 轨迹的输入速度。

9. GPU 并行实现要求

设环境数为 B，语义地图为 H×W：

张量形状说明
障碍物世界坐标[B,H,W,2]由地图原点、yaw、分辨率一次性生成。
语义 ID[B,H,W]只通过 Torch mask 过滤 ID=2。
前向投影 S[B,H,W]与速度方向做批量点积。
横向投影 L[B,H,W]与左侧方向做批量点积。
触发状态[B]使用 any。
最近距离[B]对无效点填充正无穷后使用 amin。
mean_L[B]使用加权 sum 和 clamp_min。

禁止使用以下实现方式：

  • 遍历每个环境；
  • 遍历每个语义体素；
  • 为左右方向分别执行 Python 级别的规划函数；
  • 把地图体素复制为每个环境独立的 Python 对象。

计算复杂度为 O(B×H×W)，显存主要是现有语义地图和少量 S/L/weight/mask 临时张量。计算结束后不保存历史障碍物状态。

10. 参数汇总

参数初始值调大后的效果
large_obstacle_rect_width_m 0.70m 检测更宽，更多横向区域会被视为可能挡路。
large_obstacle_rect_length_m 1.20m 更早检测前方障碍物，距离衰减范围更长。
large_obstacle_lateral_speed_max_mps 0.25m/s 靠近障碍物时横移更快。
large_obstacle_default_side 按现有配置 仅在左右对称或 mean_L≈0 时决定兜底方向。

11. 边界情况

  • 平移速度接近零：不构造速度方向，不触发横向绕行。
  • 矩形内没有 semantic=2：横向速度为零。
  • mean_L=0：使用默认方向，但速度大小仍由最近障碍物距离计算。
  • 最近障碍物在矩形远端：横向速度较小，提前开始绕行。
  • 最近障碍物接近 root：横向速度接近最大值。
  • 横向速度超过已有 vy_limit：使用已有速度限制裁剪。
  • 障碍物点数量为零：分母使用 clamp_min(ε)，不会产生 NaN。

12. 验证指标

测试时建议按环境并行记录以下指标：

  • large_obstacle_triggered：是否检测到前方大障碍物；
  • large_obstacle_mean_L：加权横向平均位置；
  • large_obstacle_nearest_forward_m：最近前向距离；
  • large_obstacle_proximity：接近程度 ρ；
  • large_obstacle_lateral_velocity_mps：实际增加的横向速度；
  • large_obstacle_avoid_side：最终绕行方向；
  • large_obstacle_standstill_count：绕行后触发 standstill 的次数。

验证重点是：障碍物距离 root 越近，横向速度绝对值是否增大；障碍物只在 左侧或右侧时，绕行方向是否正确；左右对称时是否仍能按默认方向产生横移； 以及 1024 个环境批量运行时是否保持无 Python 循环。
