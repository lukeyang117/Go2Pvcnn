Joint MPC RTI GPU 规划器设计

日期：2026-07-15 ｜ 目标路径：Go2Pvcnn/extension/joint_mpc_rti/ ｜ 后端名：planner_backend="joint_mpc_rti"

最终决策：新增一套独立的纯 GPU、批量、运动学 rolling MPC。规划器每个 IsaacLab step 都从真实观测重新开始，预测未来 H=16 步，只发布 dt=0.02s 后的第一帧 reference；优化采用 multiple-shooting SQP-RTI、Generalized Gauss-Newton、Primal-Dual iLQR、时间维 associative scan 和并行简化 line search。当前 mpc 后端保持不变，用于 A/B 对照。

1. 要解决的问题

当前轨迹规划器一次生成固定长度轨迹，并在一段时间内持续消费同一条轨迹。它可以产生较好的单段运动，但面对不同障碍距离、地形变化、实际动作偏差和 command 变化时，无法像传统 MPC 一样及时把真实状态重新植入预测。

新规划器需要同时满足以下行为：

  • 平地和普通地形上稳定跟踪前进、横移与转向 command。
  • 通过连续损失形成对低矮小语义物体的抬腿跨越，不依赖大量离散行为 gate。
  • 对不可跨的大障碍物形成 root、机身和腿部整体绕行。
  • 在粗糙地形、台阶和局部高差上保持运动学可达、足端触地和全身净空。
  • 每帧只执行未来第一步，并使用下一帧真实状态继续滚动优化。
  • 作为 PPO 的 reference reward 来源，不直接替代 policy action，也不进入 policy/critic observation。
  • 在 1024 个独立环境中保持全批量 GPU 并行。

2. 范围与非目标

属于本设计不属于本设计
root pose、joint position/velocity 的运动学预测与优化。质心动力学、接触力、力矩、摩擦锥和执行器动力学优化。

高程图、语义图、small/large 距离场的世界坐标查询。不让 planner 在每次 RTI 内重建 RayCaster 地图或距离场。

完整预测 horizon + 第一未来 reference 输出。不把整段预测直接作为未来若干步的开环执行命令。

2.1 修改约束：唯一允许的结构性硬约束

行为选择不得通过硬 gate 决定。允许存在的硬约束只用于定义系统和数据的一致性，并集中限定如下：

  • X[:,0] = measured_state：每次 RTI 的起点严格等于当前真实 IsaacLab 状态。
  • 状态节点满足离散运动学转移；multiple-shooting defect 属于求解器等式约束，不是可随意调权重的行为 loss。
  • 足、膝、小腿和机身采样点严格由 root/joint 的解析 FK 生成，不引入另一套独立足端状态。
  • v1 的 trot contact/swing mask 由外部 scheduler 给定，优化器不改变 gait topology、phase offset 或 swing duration。
  • terrain field 必须按同一 env id、scanner pose、timestamp 和 version 原子发布；不能读取半更新字段。
  • 外部 command 固定为 body frame；内部世界坐标转换只能执行一次。
  • 规划器发布的第一参考严格是未来 x1，不能用当前 x0 代替。
  • 非有限输入、失效 field 或非有限解必须标记 invalid；这是数据有效性约束，不是语义行为 gate。
禁止的硬 gate：不得使用 if small then cross、if large then turn left/right、crossable_small、指定某条腿跨越、固定避障侧、根据 terrain row/col 切换行为、优化后 snapping、hard projection 或 optimize-then-repair。small/large 语义只构造连续代价场，跨越、绕行、减速或停止由总目标自然竞争得到。

3. 成功标准

行为目标

  • 无障碍时跟踪 command，方向不随世界 yaw 错位。
  • 小物体场景出现真实足端抬高、越过、落地。
  • 大障碍场景不穿越障碍，形成可观察的绕行轨迹。
  • 触地足贴合地形，足、膝、小腿和机身不穿地。
  • 连续重规划没有明显 root、joint、foot 跳变。

系统目标

  • B=1024、H=16、dt=0.02s。
  • 每控制步只做一次 RTI 更新。
  • 1000 次 planner hot-path 调用总计不超过 3 秒。
  • 平均 planner hot-path 不超过 3 ms/次。
  • 无 Python per-env 和 per-horizon 主循环。
计时边界：3 秒目标只统计已经完成编译、已经建立 terrain/SDF cache 后，从 batched state/command/field-ready 输入到第一未来 reference 输出的 planner hot path。Isaac 仿真、渲染、RayCaster 射线计算、首次编译和首次距离场初始化分别计时；距离场更新必须能与 planner 并行，不允许在 planner 热路径中同步重建。

6. 坐标系和数据契约

6.1 外部 command

Viewer、IsaacLab CommandManager 和 planner 的统一输入为：

command_body = [vx_body, vy_body, yaw_rate]

vx_body  > 0 : 朝机器人自身前方
vy_body  > 0 : 朝机器人自身左方
yaw_rate > 0 : 绕世界 +Z 左转

外部不提供 world-frame command。世界线速度由预测节点自己的 yaw 转换：

v_world(k) = Rz(yaw(k)) @ v_body(k)

该转换只发生一次。Viewer 不预旋转 command，避免 double rotation。

6.2 状态与控制

x = [root_pos_w(3), root_rpy_w(3), joint_pos(12)]   # nx = 18
u = [root_lin_vel_body(3), root_ang_vel_body(3), joint_vel(12)]  # nu = 18

核心形状：

state.x0       [B, 18]
shooting.X    [B, H+1, 18]
controls.U    [B, H,   18]
contact       [B, H+1, 4]
foot_pos_w    [B, H+1, 4, 3]
link_samples  [B, H+1, G, 3]

数值热路径默认 float32。状态输入可来自其他 dtype，但进入 planner 时统一转换，不能让 viewer 的 float64 传播到 1024 环境求解器。

6.3 运动学离散化

p(k+1)     = p(k) + dt * Rz(yaw(k)) * v_body(k)
rpy(k+1)   = rpy(k) + dt * T(rpy(k)) * omega_body(k)
q(k+1)     = q(k) + dt * qdot(k)

初始状态是严格等式约束：

X[:, 0] = measured_state

multiple shooting 中其他节点允许暂时存在 defect，但 RTI 子问题会惩罚并校正：

defect(k) = X(k+1) - f(X(k), U(k))

7. 固定 Trot 与足端轨迹

v1 采用外部固定的 trot 拓扑：

diagonal group A: FL + RR
diagonal group B: FR + RL
group A / group B 交替 swing

固定 trot 只锁定接触拓扑与初始时间表，不意味着足端摆动轨迹长度固定。不同障碍距离通过 rolling horizon、落点变化、root 速度和连续重规划处理；v1 可以接受少量时间误差，但不把 phase offset 作为优化变量。

  • stance 足端在世界坐标中保持锁定并贴合 height field。
  • swing 足端从当前真实足端出发，以 touchdown 为终点。
  • 足端中间高度由 terrain 和 small-object clearance residual 推动。
  • touchdown 必须落在有效地图内，并满足地形、语义和运动学可达性。
  • 足端不是独立自由状态；规划足端必须与 root/joint 的解析 FK 一致。

8.1 地图尺寸

每个环境拥有独立地图。地图随 SemanticRayCaster 的实际更新批次刷新，而不是 planner 自己使用另一套定时器。

9. 连续损失设计

Loss 分为任务、步态、地形、语义、可行性、平滑和终端七组。等式关系只放在第 2.1 节的修改约束中；行为层只使用连续 residual 和 relaxed barrier。

min  Σ(k) 0.5 * ||r_k(X,U)||²_W
     + relaxed_barrier(inequalities)
     + terminal_cost(X_H)

不建立 crossable_small 之类决定整条行为的硬 gate。small/large 分类只负责构造不同风险场；最终跨越还是绕行由轨迹代价共同决定。

9.1 Loss 的三种数学角色

类型适用内容实际作用
平方 residualcommand、姿态、落脚形状、平滑。表达“希望接近什么”，允许和其他目标折中。
Relaxed barrier关节限位、地形穿透、障碍距离、地图边界。远离边界时影响小，接近边界时快速增加；轻微越界仍保持有限梯度。
求解器等式真实 x0、运动学转移。定义问题本身，不放进普通行为 Loss 调权重。

所有按 horizon、腿或几何采样点累计的项都必须按有效元素数量归一化，避免修改 H 或 link sample 数量后等效权重改变。

9.2 Command 与运动任务

Loss作用范围实际做什么
command_linear_velocity全部 horizon 节点。比较预测 body-frame vx/vy 与外部 command，决定机器人希望走多快、朝机身哪个方向走。
command_yaw_rate全部 horizon 节点。跟踪 yaw rate；纯转向 command 下配合零线速度目标，避免边转边漂移。
command_progresshorizon 起点到终点。比较实际世界位移和 command 期望位移，防止通过原地抬腿、长期停车或过度绕行逃避障碍。
command_direction非零平移 command。惩罚最终位移与 command 方向相反或横向偏离过大；零 command 时连续关闭。
 
L_command_velocity = mean_k ||v_body(k) - v_command||²
L_command_progress = ||p(H)-p(0)-T_horizon*Rz(yaw(0))*v_command||²

逐节点速度和整体 progress 同时存在：前者管局部速度，后者防止 horizon 末端没有真正完成运动任务。

9.3 Root 姿态与高度

Loss实际做什么注意事项
root_support_height让 root Z 跟随 stance 支撑位置的高程加 nominal body clearance。防止上台阶不抬机身，也防止为了跨小物体整体抬高 root。
root_roll_pitch平地趋近零姿态；粗糙地形允许跟随局部支撑面小幅倾斜。权重不能压过腿部可达性。
root_vertical_velocity抑制单帧 root Z 跳变。不能替代 support-height tracking。
root_roll_pitch_rate抑制机身快速摇晃。只约束 roll/pitch rate，不抑制 command yaw。

9.4 Joint 可行性与自然姿态

Loss数学形式实际做什么
joint_nominal_posture低权重平方 residual。在多个可行关节姿态中选择自然姿态，避免膝盖翻转；swing 腿可降低该权重，避免妨碍抬腿。
joint_position_limit_barrier上下限 relaxed barrier。接近关节角边界时快速增加代价。
joint_velocity_limit_barrierqdot_max-|qdot| 的 relaxed barrier。防止第一步或跨越时产生不可接受的关节速度。
touchdown_reach_margin腿工作空间内外边界 relaxed barrier。让 touchdown 远离腿完全伸直、完全收缩和运动学奇异区域。
FK 一致性不作为 Loss：foot、knee、shank 和 body samples 全部由 root/joint 的解析 FK 直接产生，因此不存在另一条“规划足端”需要用 loss 拉回。FK 只保留有限值、Jacobian 和几何误差诊断。

9.5 Stance Loss

以下项只乘固定 gait scheduler 给出的 stance_mask，mask 不是语义行为 gate。

Loss实际做什么与其他项的区别
stance_xy_lock让 stance foot 的世界 XY 保持在接触 anchor，防止随 root 滑动。控制累计位置漂移。
stance_ground_contact让 stance foot Z 等于同一张 height_w 在足端 XY 的表面高度。负责贴地，不负责禁止踩语义物体。
stance_slip_velocity惩罚 stance foot 世界速度。控制瞬时滑动，权重低于位置锁定。

如果 stance/touchdown 位于 small 或 large 物体上，语义 avoidance barrier 会与贴表面 residual 竞争并把落点推离物体；不需要第二张地面高度图。

9.6 Swing Loss

Loss实际做什么激活范围
swing_nominal_shape提供无障碍时自然前摆的弱参考，避免 joint optimizer 生成绕圈或折返轨迹。固定 swing_mask；权重低于安全 clearance。
terrain_swing_clearance要求 swing foot 高于唯一高程图 height_w(x,y) 加基础 margin，防止擦坡面、台阶或任何可见表面。全部 swing 节点。
swing_velocity_smoothness限制 FK 足端速度变化，避免摆动曲线折角。相邻 swing 节点。
touchdown_velocity降低 touchdown 时的足端水平和垂直速度，避免扫地或砸地。swing 结束附近。
 
terrain_clearance = foot_z - height_w(foot_xy) - terrain_margin
L_terrain_swing = relaxed_barrier(terrain_clearance)

9.7 Touchdown Loss

touchdown 定义为固定 swing 结束时刻的 FK 足端，不增加独立 touchdown 优化变量。

Loss实际做什么
touchdown_ground_height让 touchdown Z 贴合唯一高程图的表面高度。
touchdown_valid_map对靠近或超出 151×151 有效范围的 touchdown 施加连续边界 barrier；实际越界查询仍返回 invalid。
touchdown_reach_margin让 touchdown 对应 joint pose 保持足够运动学余量。
touchdown_foot_separation约束必要腿对之间的最小距离，防止左右腿交叉、前后腿过度拥挤。

9.8 普通高程图碰撞与净空

Loss采样对象实际做什么
foot_ground_penetration全部 foot。所有 gait phase 都不允许足端低于 height_w；与 stance 贴地、swing 额外净空分开。
knee_ground_clearance四个 knee。避免膝盖撞坡面或台阶。
shank_ground_clearance每条小腿多个插值采样点。避免只检查 knee/foot 两端而漏掉中间连杆穿地。
body_ground_clearance机身底面、边缘和角点。避免 root 点安全但倾斜机身角落撞地。

9.9 Small Semantic Loss

small 语义不触发跨越模式，只提供三个连续 loss。由于 height_w 已包含小物体顶部，语义项只增加额外安全语义和禁止落脚，不建立第二高度场。

Loss实际做什么为什么不会形成硬 gate
small_object_foot_over当 swing foot XY 接近 small footprint 时，在基础 terrain_swing_clearance 上增加连续的额外 clearance margin。影响权重由 small SDF 连续衰减；脚横向远离后自然趋近 0。
small_object_touchdown_avoidance对 touchdown 和 stance foot 到 small footprint 的距离施加 relaxed barrier，防止落在或站在小物体顶部。只表达落脚风险，不指定必须跨越还是绕行。
small_object_link_clearance约束 foot、knee、shank 与小物体的三维净空；link 高于物体顶部时 XY-SDF 影响连续减弱。通过连续水平距离和垂直权重计算，不使用碰撞布尔分支选择轨迹。
 
small_influence = smooth_kernel(small_sdf_xy)
extra_over_margin = small_influence * small_extra_margin
small_foot_over = relaxed_barrier(
  foot_z - height_w(foot_xy) - terrain_margin - extra_over_margin
)

small_vertical_influence = sigmoid(
  (height_w(link_xy) + link_margin_z - link_z) / temperature
)

root 不设置 small_object_root_avoidance。保持 command/progress 目标，同时让 foot-over、touchdown 和 link clearance 竞争，才能让可跨场景自然出现抬腿；不适合跨时仍允许自然减速或绕行。

9.10 Large Obstacle Loss

Loss实际做什么
large_root_footprint_barrier对机身平面 footprint 多点查询 large SDF，形成 root 绕行的主要梯度。
large_body_collision结合障碍表面高度和 body 采样点，避免机身与大障碍发生三维碰撞。
large_foot_collision对 swing、stance 和 touchdown 足端使用保守 large-SDF barrier。
large_knee_shank_collision避免膝和小腿在 root 绕行时切过障碍边缘。
large_terminal_risk同时惩罚 horizon 末端过小距离和继续朝障碍接近的速度，避免短 horizon 拖延绕行。
 
large_margin = large_sdf(sample_xy) - configured_margin
L_large = relaxed_barrier(large_margin)

所有方向选择都来自连续 SDF 梯度和总目标；不固定向左或向右绕。

9.11 平滑与 RTI 连续性

Loss实际做什么
control_rate限制 horizon 内相邻 root/joint velocity 控制变化。
first_control_continuity限制新 u0 与上一帧已执行控制趋势的差异，减少 rolling replan 第一帧跳变。
joint_acceleration减少 joint velocity 的快速变化和关节抖动。
root_acceleration减少 root linear/angular velocity 的突变。

不增加整条轨迹的 warm_start_tracking loss。上一帧解只是初值，不应该阻止新观测和新 command 修正未来轨迹。

9.12 Terminal Loss

Loss实际做什么
terminal_command_velocity避免 horizon 末端无理由减速到零。
terminal_obstacle_safety避免末端停在障碍边缘或仍高速接近障碍。
terminal_posture避免末端 root/joint 处在极端、不利于下一帧 warm start 的状态。
terminal_contact_viabilityhorizon 在 swing 中结束时，保证足端仍朝安全 touchdown 延续，不在最高点突然截断。

10. SQP-RTI 优化过程

10.1 Warm Start

previous X: [x0, x1, ..., xH]
previous U: [u0, u1, ..., uH-1]

shifted X guess = [measured_x_now, x2, ..., xH, extrapolated_xH]
shifted U guess = [u1, ..., uH-1, uH-1]

真实状态只替换新 x0。上一帧解的后半段继续提供未来结构，因此一次 RTI 更新不需要从零收敛。

10.2 并行线性化

所有环境和 horizon 节点同时计算：

  • kinematic dynamics 与 Jacobian。
  • Go2 analytic FK 与 link Jacobian。
  • height/SDF bilinear query 与世界梯度。
  • 所有 residual 和 barrier 一阶导。

不使用通用 autograd 对整条轨迹做反向传播；核心 FK、动力学和 field query 使用解析或专用 Jacobian。

10.3 Generalized Gauss-Newton

gradient ≈ Jᵀ W r
Hessian  ≈ Jᵀ W J + convex_barrier_curvature + regularization

不使用完整二阶 SQP Hessian。完整二阶会引入 residual 二阶导、更多显存和更差的 GPU 批处理稳定性；RTI 每帧只有一次更新，稳定的正定近似比理论上更精确但昂贵的 Hessian 更合适。

10.4 Primal-Dual iLQR 与 Associative Scan

线性二次子问题由 primal-dual iLQR 求解。传统 Riccati 在时间维顺序递推；这里把可组合的仿射/二次消息写成 associative operator，在 GPU 上使用 scan：

传统时间关键深度: O(H)
并行 scan 关键深度: O(log H)

环境维 B、时间节点 H 和几何采样点 G 同时批处理。算法总工作量仍随 B×H 增长，但 GPU 等待的串行时间明显减少。

10.5 并行简化 Line Search

candidate alpha = [1.0, 0.5, 0.25]

三个候选同时 rollout 和评估 merit。每个环境独立选择满足有限值、约束改善且 merit 最低的最大可接受步长。没有候选改善时保留 shifted warm start，并提高下一帧正则化。

10.6 每帧 RTI

for each control step:
  inject measured state
  shift warm start
  parallel evaluate and linearize
  build GGN subproblem
  solve with primal-dual scan
  parallel line search
  accept one SQP update
  publish trajectory[:, 1]

11. 1024 环境并行与性能设计

原则设计
固定 shapeB=1024、H=16、nx=18、nu=18，主热路径不创建可变长度 tensor。
无环境循环状态、terrain query、FK、loss、line search 都以 batch tensor 运行。
无时间 Python 循环rollout/solve 使用编译图和 scan；允许图内固定展开，不允许解释器逐节点调度 kernel。
固定 GPU 图预分配 workspace，避免每帧 allocator 抖动；稳定后捕获 CUDA Graph 或等价固定执行图。
避免同步热路径不调用 .item()、CPU logging 或逐 stage synchronize。
字段缓存SDF、梯度和 field transform 在 RayCaster 更新时构建，优化内只查询。
每帧一次 RTI不执行 16/25 次 Adam 梯度下降，不做外层多轮 SQP。
按环境容错失败环境 masked fallback，不让少量坏样本阻塞整个 batch。

主要计算规模近似：

geometry/loss work: O(B * H * G)
block solver work:  O(B * H * block_cost(nx, nu))
time critical depth with scan: O(log H)

最终性能报告必须同时给出 warm-up 后总耗时、平均值、P50、P95、P99、最大显存和非有限环境数量。

12. Rolling Runtime 与 PPO Reference 时序

12.1 每步运行语义

time t, before action:
  measured state = x_real(t)
  planner.step(...) -> x_ref(t+1)
  reference_buffer stores pending x_ref(t+1)
  policy outputs action(t)

Isaac sim advances to t+1

reward at t+1:
  compare x_real(t+1) with pending x_ref(t+1)
  then plan again from x_real(t+1)

这保证 PPO 学的是“跟踪下一步 reference”，而不是奖励当前状态等于当前状态。

12.2 Reference ABI

planner 输出可以继续转成现有 reference reward 所理解的字段，但 rolling manager 不再依赖“整段 cache 播放到 phase 结束”的语义。

12.3 Reset 和命令变化

  • 环境 reset：清空该环境 warm start、dual、pending reference 和 field-ready 消费状态。
  • command 突变：不丢弃全部解；保留几何 warm start，通过新 command residual 在下一次 RTI 修正。
  • command 清零：逐步收敛到稳定站立，不能在 swing 中突然把足端冻结在空中。
  • 某环境 solver 失败：该环境使用安全 shifted reference 或站立 reference，其他环境继续正常求解。

15. 失败处理

失败该环境处理必须记录
输入 state 非有限输出 invalid，不进入求解。env id、输入字段。
terrain field 不可用短时使用绑定正确 pose 的上一 ready version；无历史则站立。field age/version。
所有 line-search 候选不改善保留 shifted warm start，提升正则化。merit、alpha、regularization。
solver 输出非有限回退到安全 shifted reference 或站立。首个非有限 stage。
未来第一步出现非有限值、无效地图查询或违反第 2.1 节的数据有效性约束不发布该步，输出站立/减速 reference。具体无效字段与 safety margin。
部分环境失败只 mask 失败行。失败数量与原因分布。

16. 验收测试：只描述必须达到的结果

测试原则：以下验收项是独立、可观测的系统结果。它们不依赖某个旧测试脚本、旧 planner、旧 loss key、旧 probe 或旧设计文档存在。测试文件如何组织属于实现计划；只要输入条件等价、指标定义一致、结果可重复，就可以证明达成。

16.1 数学与坐标系结果

输入条件必须达到的结果
相同 body-frame 前进 command，分别令机器人世界 yaw 为 0°、90°、180°。预测位移分别沿世界 +X、+Y、-X；body-frame 前进量保持一致。
纯左移 command。预测运动始终沿机器人自身左方，不随世界坐标固定为某一轴。
纯 yaw command。root XY 不出现显著平移漂移，yaw 按命令符号连续变化。
随机可达 joint pose。解析 FK 与可信几何计算的足端位置误差满足数值容差，Jacobian 的方向导数与有限差分一致。
已知解析高度平面和已知圆形障碍距离场。世界坐标高度、距离和梯度方向正确；旋转 scanner 后查询结果保持世界几何不变。

16.2 Rolling MPC 结果

场景必须达到的结果
上一帧预测与下一帧真实状态存在人工偏差。新 horizon 的 x0 精确等于真实状态；不能继续从旧预测状态开环推进。
连续 100 个相同 command step。每步只发布 x1；root、joint、foot reference 在重规划边界连续，无周期性整段跳变。
前进 command 突然变为横移或转向。下一次 RTI 即开始改变预测方向，同时第一步变化受平滑和限速约束。
运动中 command 清零。root 速度逐步降至零，摆动腿完成安全落地，不出现足端悬空冻结或单腿突跳。
不同环境在不同时间 reset。只清空对应环境的 warm start/reference；其他环境轨迹和 solver 状态不受影响。

16.3 平地 Command 跟踪

至少覆盖前进、后退、左/右横移、左/右转向和斜向命令。必须达到：

  • 沿 command 方向的累计进度符号正确。
  • 方向 cosine 为正且没有系统性左右镜像。
  • root 高度、roll/pitch、joint 不出现振荡发散。
  • stance 足不滑动，触地足高度误差绝对最大值不超过 0.005m。
  • 足端对地最大穿透不超过数值容差，穿透计数为 0。

16.4 小语义物体真实跨越

在平坦地面放置可由 Go2 运动学跨越的低矮小物体，并从多个初始距离、横向偏移和 command 速度接近。成功必须同时满足：

  • 至少一条腿出现明确的 lift → over-object → land 时序。
  • 同一条腿在物体 XY footprint 上方时，足底 Z 高于物体顶面和安全 margin。
  • touchdown 不落在小物体 footprint 内。
  • 足、膝、小腿和机身与小物体碰撞计数均为 0。
  • root 沿 command 方向通过物体，不允许仅靠远距离横向绕行被判为“跨越成功”。
  • root Z 不通过整体抬升机身来伪造足端 clearance。
  • 跨越后恢复稳定 trot 和 command 进度。

还必须覆盖“不适合直接跨”的小物体相对位置；此时允许自然绕行或减速，但仍不得发生碰撞或不可达姿态。

16.5 大障碍物绕行

在 command 走廊内放置明显不可跨的大障碍物。成功必须同时满足：

  • 预测 horizon 在接近障碍前产生横向绕行或安全停止趋势。
  • root footprint、机身、足、膝和小腿的 large-SDF margin 不小于配置的验收安全余量。
  • 不允许依靠越界地图、穿越障碍或 root 突然跳高通过。
  • 障碍离开走廊后，轨迹逐渐恢复 command 方向，不长期保留无意义横向偏置。
  • 障碍在左/右侧时，绕行方向能根据连续风险场选择，不固定只向一侧绕。

16.6 粗糙地形与台阶

覆盖上坡、下坡、连续台阶、局部高差和不同起始 offset。必须达到：

  • 所有 touchdown 位于有效地图并贴合对应世界高度。
  • stance foot 与 touchdown 在接触后的误差绝对最大值不超过 0.005m。
  • 足、膝、小腿和机身对地穿透计数为 0。
  • joint position/velocity 不超过配置硬限制。
  • 规划足端与 FK 足端误差保持在数值容差内。
  • root Z 连续，不出现单帧大幅抬升或下降。
  • 连续滚动规划能够前进多个 gait 周期，而不是第一段可行、后续逐段漂移。

16.7 地图同步与环境独立性

输入条件必须达到的结果
RayCaster 只更新一部分 env ids。只有相同 env ids 的 field version 更新；其余环境数据、pose 和 version 不变。
scanner 移动/旋转后生成新地图。新字段绑定新 pose；旧字段仍使用旧 pose 查询，不能发生坐标漂移。
查询点超出 151×151 覆盖范围。返回 invalid 并触发安全处理，不返回边界复制值。
1024 环境拥有不同障碍布局。每个环境只响应自己的地图，不发生 batch 行串扰。
field 构建和 planner 并行。planner 只读取完整 ready version，不读取半更新的 height/SDF 组合。

16.8 PPO Reference 时序

  • 时刻 t 生成的 reference 必须带目标时间 t+1。
  • reward 必须用真实 x(t+1) 对比对应的 x_ref(t+1)。
  • reset 后的旧 pending reference 不得参与新 episode reward。
  • reference 不进入 policy/critic observation。
  • planner 关闭或 reference invalid 时，reward 有明确的 neutral/disabled 行为，不产生随机惩罚。

16.9 Solver 容错

  • 单个环境注入 NaN 时，只有该环境 invalid，其余环境仍产生有限结果。
  • line search 全部失败时，输出有限、安全且连续的 fallback reference。
  • 短时 field stale 时使用上一完整版本，并记录 field age；超过配置时限后转安全站立。
  • 所有公开输出均携带 status、valid 和 fallback 标志。

16.10 1024 环境性能

在固定 GPU、固定 shape、关闭逐步诊断同步、完成 warm-up 和编译后：

  • 1024 环境、H=16、1000 次 rolling planner 调用总耗时不超过 3.0s。
  • 平均 planner hot-path 不超过 3.0ms。
  • 1000 次调用中不出现非有限输出、显存持续增长或临时 allocator 长尾。
  • 输出必须报告 P50、P95、P99、最大值和峰值显存，不能只报告异步 kernel enqueue 时间。
  • 计时开始和结束需要正确 GPU 同步，但循环内部不得每步同步。
  • terrain/SDF 构建单独报告，并证明它可与 planner 重叠且不会污染 planner hot-path 数字。

18. 风险与降级顺序

风险优先处理不得采用的掩盖方式
一次 RTI 改善不足改善 warm start、尺度、正则化、line search 和 residual 条件数。直接增加大量外层迭代。
小物体总被绕开降低 root-small 横向排斥，强化 swing-over 与 touchdown-safe 的相对代价。写死场景 gate 或指定某条腿跨。
足端跨过但 knee/shank 碰撞增加 link sample 密度和解析碰撞 Jacobian，调整 swing shape。只看 foot clearance。
大障碍绕行不足提高 large-SDF barrier、terminal risk 和 root/body footprint sampling。规划后 snapping 或硬改 root 位置。
性能超过 3ms剔除同步、固定 workspace、融合 query/Jacobian、scan、CUDA Graph，再做专用 kernel。删除关键安全几何或伪造异步计时。
地图更新慢同 RayCaster chunk 更新并使用独立 stream，planner 消费最近 ready version。在 RTI 内同步等待全量 SDF 重建。
