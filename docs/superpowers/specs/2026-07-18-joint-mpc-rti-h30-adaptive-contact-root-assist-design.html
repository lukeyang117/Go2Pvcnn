1. 新证据与问题定义

144 个小障碍 rolling 场景覆盖 sphere/cuboid、八个平移方向、0.1/0.2/0.4m/s 和 -0.4/0/0.4rad/s yaw，每个场景 160 帧。与同配置平地对照相比：

小障碍碰撞帧为 foot 75、knee 38、calf 144、thigh 1、base 15；foot 的 71/75 与 calf 的 140/144 发生在 continuing stance。问题不是单纯 swing clearance 不足，而是固定时间 contact 切换、空中 anchor、短周期、关节可达压力与 root-joint 分配共同造成。

2. 设计目标与非目标

目标

  • 生产 horizon 固定从 H16 改为 H30，dt=0.02s 不变。
  • nominal stance/swing 各 15 帧；每腿 touchdown 可独立延长最多 10 帧。
  • 只有真正贴地且 foot/knee/calf/thigh/base 对小障碍安全时才建立 stance anchor。
  • 联合规划受限 root 横移、roll、pitch、yaw，足端仍先于 root 主动运动。
  • 所有碰撞、接触、姿态和可达性项同时进入 LQ/GGN、非线性 merit、line search 与 JointMetrics。
  • 保持 1/40/512/1024 任意环境数、固定 tensor shape、CUDA Graph 和只发布 x1 的接口合同。

非目标

  • 不引入动力学、接触力或在线 gait topology 优化。
  • 不使用输出后的 root/foot/contact 修补。
  • 不使用语义硬 gate 选择手写跨越轨迹。
  • 不允许通过关闭旧 loss、缩小碰撞几何、减少环境数或改 detector 通过指标。
  • 不以 H16 性能替代 H30 的 Stage B 正式结果。

该合同覆盖一次完整 nominal stance-swing-stance 边界。原计划中 H16/H20/H24/H30/H40/H50 的探索任务被本设计修订：H30 不再只是候选，而是生产目标和 Stage A/Stage B/Stage C 的统一固定 shape。H16 仅保留为历史诊断基线。

4. 每腿自适应接触 Scheduler

Scheduler 保存固定 shape 的逐腿状态，不把 phase 增加为连续优化变量：

contact_state[B,4]
phase_age[B,4]
swing_extension_age[B,4]
stance_age[B,4]
stance_anchor_w[B,4,3]
recovery_state[B,4]

4.1 Touchdown readiness

每条腿独立满足下列联合条件才进入可靠 stance：

touchdown_ready =
    map_valid
    AND abs(foot_z - terrain_z - foot_contact_offset) <= 0.010m
    AND foot_not_moving_up
    AND foot_small_sdf >= 0.052m
    AND foot/knee/calf/thigh collision_free
    AND base collision_free
    AND joints_inside_safe_limits
    AND x1/x2 short_stance_lookahead_safe

碰撞判断使用 XY signed distance、物体 top height 和部位半径的三维组合，允许 link 从障碍上方安全经过，不把纯 XY proximity 误判为碰撞。

4.2 Anchor 与逐帧延长

  • readiness 成立：anchor_xy=current_foot_xy，anchor_z=terrain_z+foot_contact_offset。
  • readiness 不成立：该腿保持 swing，extension_age+=1，不建立 anchor。
  • 已经 grounded 但仍碰小障碍：进入 grounded-but-unsafe recovery，不计为可靠支撑，重新小幅抬起并沿 SDF 梯度移动到安全地面。
  • extension_age=10 后仍不安全：保持 recovery，不强制 stance。

4.3 独立 touchdown 与 liftoff 支撑保护

对角摆动腿不再被要求同帧 touchdown。已安全落地的腿立即 stance，未落地腿独立延长。下一组 liftoff 只有在抬腿后仍保留至少两条可靠 stance 腿，且新 touchdown 腿已经 grounded 至少一帧时才获准发生。该规则允许受限 per-leg timing offset，但保留 nominal trot 顺序。

延长期间 root progress 连续缩放：

progress_scale = clamp(1 - max_extension_age / 10, 0, 1)

原始用户 command 不被覆盖；缩放发生在 MPC 内部 horizon progress reference。达到 recovery 时沿 command 的 nominal progress 为零，root 仍可在已批准 clamp 内做安全横移和姿态恢复。

5. 受限 Root 辅助联合规划

Root 变量继续位于同一个 18 维 state/control 中，不新建输出后控制器。以 command 世界方向定义 e_parallel 与 e_lateral，root XY 碰撞 Jacobian 从纯 command-axis 投影改为：

P_root_xy = P_parallel + w_root_assist * P_lateral
w_root_assist = small_sdf_proximity * swing_phase_release * reachability_pressure

三个权重均为连续 sigmoid/smoothstep：远离障碍时保持 nominal；swing 前段以足端/关节为主；接近障碍且关节余量下降时逐渐释放 root；touchdown 与稳定 stance 后回收到 nominal。

关节可达压力由安全边界余量连续产生：

joint_safe_margin = min(q - safe_lower, safe_upper - q)
reachability_pressure = sigmoid((margin_threshold - joint_safe_margin) / temperature)

5.1 双层 Clamp

自由度累计状态范围每帧控制范围
root lateral相对 command nominal ±0.06m横向速度偏差 ±0.20m/s
roll相对 upright nominal ±6°角速度 ±0.6rad/s
pitch相对 upright nominal ±6°角速度 ±0.6rad/s

Root Z 不作为小障碍直接避障自由度，继续由 support-height 与地形高度管理。所有 clamp 在 candidate 非线性 rollout 前执行，并由 line search 看到一致结果；禁止发布后裁剪。

6. LQ/GGN、碰撞与 Line Search

小障碍线性化必须为 foot、knee、calf/shank、thigh、base 全部生成一阶 signed-distance gradient 和 Gauss-Newton curvature。root XY lateral 与 root RPY 乘连续 assist 权重进入同一 LQ；joint block保持完整 per-leg Jacobian。任何在 JointMetrics 中作为安全门的碰撞都不能只存在于最终 merit。

候选顺序固定为：

base + alpha * delta
→ control trust-region clamp
→ H30 joint-position projection
→ root per-frame clamp
→ root cumulative nominal-relative clamp
→ per-leg stance equality projection
→ collision feasibility restoration
→ nonlinear FK rollout
→ joint constraint violation + merit

四个 alpha 在 [B,4,H,18] 固定 shape 上并行评估。若 base 可行，候选必须保持可行并降低 merit；若 base 不可行，候选必须严格降低联合约束违反量；全部失败才允许 alpha=0。

7. JointMetrics 统一数据合同

统一原则：每个场景都产生同一份原始 trace，并计算全部适用指标。报告维度保留 [scenario, command, phase, shape, speed, yaw, environment, time, leg_or_body_part]；每个字段记录 value、numerator、denominator、valid count、N/A 原因、worst-case key 和阈值结果。

8. 场景 × 指标联合矩阵

以下每个单元都计算第 7 节全部适用指标，不允许只检查该场景主指标：

  • 平地：零速、前后、左右、四个斜向、yaw-only、平移+yaw；速度覆盖 0.1/0.2/0.4m/s。
  • 小障碍：sphere/cuboid/cylinder/capsule/cone，全部方向、速度、yaw、进入 phase、横向偏置；同时覆盖 nominal touchdown、1-10 帧 extension、grounded-but-unsafe 和 recovery。
  • 小障碍 stop/restart：root 位于障碍前、上方和越过后；验证支撑、无飞起、独立 touchdown 与足端再次领先。
  • 大障碍：正前、左右偏置和 mixed command，确认 H30 与 root assist 不破坏绕行。
  • 地形：平地、坡面、上台阶、下台阶、局部高差，确认 terrain grounding 与逐腿 readiness。
  • 真实 viewer/IsaacLab：九命令与小障碍 crossing/stop，读取 actual root/joint/foot，不以 planner 内部 state 自证。
  • 动态 batch：num_envs=1/40/512/1024，相同上层参数构建，不出现 shape、cache、Graph 或 solver 错误。
禁止平均掩盖：每个 scenario×command×phase×shape×speed×yaw 单元、每类 worst case 和全局汇总必须同时通过；N/A 必须给出数学原因和 opportunity coverage，不能计为成功。

9. Stage A：行为与安全门

Stage A 固定 H30，不再选择更短 horizon。完成顺序是先让新 H30/contact/root-assist 行为通过，再联合重跑所有继承指标：

  1. H30/15+15 时序、逐腿 scheduler、最大延长 10、recovery 和 liftoff guard 的确定性合同通过。
  2. root lateral/RPY 连续 soft release、双层 clamp、foot-leading-root 和完整 root-joint GGN/LQ parity 通过。
  3. foot/knee/calf/thigh/base 小障碍方向同时进入 LQ、merit、constraint violation；全身碰撞率降为 0。
  4. root roll/pitch 在每个小障碍单元 abs max 不超过 6°，yaw/lateral/rate clamp 不越界；不能通过 root 饱和代替足端跨越。
  5. airborne touchdown、unsafe anchor、forced touchdown、short-lookahead collision 均为 0；extension/recovery 能结束到真实安全 stance。
  6. 原实施计划的 flat/small/stop/large/terrain/viewer/rolling/dynamic-batch/legacy 联合门全部重新运行并通过。

Stage A 期间性能只记录，不以五秒门阻止行为定位；但任何行为修改必须保持 fixed-shape GPU 并行可实现，不能引入按环境 Python 分支。

10. Stage B：H30 性能门与当前暂停进度

正式性能合同：空闲 GPU、1024 环境、H30、1000 次同步 exact signed field + MPC full refresh 总耗时 <=5.0s；平均 <=5ms/update，field version 增加 1000，nonfinite=0，保留 realistic small 11×11 与 large 41×41 footprint、完整 H30 几何、四档 line search 和全部 Stage A loss/constraint。

Stage B 继承原计划 Tasks 10-13，并记录 2026-07-17 暂停点：

  • CUDA Graph 已移除 capture 内同步 solve/cholesky、主机常量创建和 device-to-host 参数校验，补齐 stance dual、command startup 等 solver-state 固定地址回写；真实 capture/replay 已通过。
  • coupled Riccati 已使用 graph-safe fixed-size Triton SPD solve 代替 MAGMA，1/40/512/1024 batch capture 均 finite，解决 batch>1 的 magma_queue::setup_ptrArray 崩溃。
  • 繁忙 GPU 的 1024×H16 short screening：field 6.54-8.94ms、MPC 61.30-88.47ms、full 69.20-95.30ms，只用于定位，不是正式验收。
  • fixed general Triton solve 与 conditional-value factor 三因子结合律已独立验证；PyTorch 2.7 generic associative_scan 在 symbolic-vmap batched matmul 失败，未完成路径没有接入 planner。
  • Stage B 当前仍暂停且未通过。Stage A H30 行为门通过后，性能工作从自定义 scan lowering/显式树形 factor composition、packed query、候选复用、kernel fusion 与 workspace 继续。

所有后续性能结果必须使用 H30；不得引用旧 H16 7402.55ms 正式基线或繁忙 GPU short screening 作为 H30 通过证据。

11. Stage C：同一候选联合复验

Stage B 达标后，在同一个最终 HEAD 和固定 H30 上从头执行：

  1. 完整 Stage A 场景×指标笛卡尔积、joint/legacy pytest、真实 viewer、rolling manager 和动态 batch。
  2. 完整 Stage B 空闲 GPU 1024×H30×1000 realistic synchronous full-refresh。
  3. 记录同一 HEAD、配置、地图、环境数、H30、指标报告和性能报告；任何一门失败都回到对应阶段修复，修复后两门都重新运行。

12. 完成定义

完成定义与 2026-07-17 原设计保持一致，只把最终 horizon 从待选 H_selected 固定修订为 H30。第一步单独修复并通过 Stage A：H30/15+15、自适应逐腿 touchdown、最大延长 10、全身无小障碍碰撞、受限 root lateral/RPY、root roll/pitch 小障碍偏差不超过 6°、足端先于 root、所有新旧 JointMetrics 与旧回归同时通过。第二步冻结 Stage A 的 H30、loss、constraint、几何、阈值和场景，完成 Stage B：空闲 GPU realistic 1024×H30×1000<=5.0s。第三步在同一个最终候选上从头联合重跑两门；只有最新行为与最新性能同时通过才算完成。

以下结果均不算完成：只改善 crossing 主指标；只在 merit 诊断碰撞而 LQ 无方向；强制空中 touchdown；达到 extension 上限后伪 stance；使用全局 phase 延长阻塞其他腿；依赖 root clamp 饱和代替足端运动；把 H30 改回更短 horizon 通过性能；修改 detector/阈值；减少环境数；排除 field 时间；引用历史通过结果；在输出后修补轨迹。
