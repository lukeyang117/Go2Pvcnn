Go2 AME + Parallelism AMP 续训设计

从已训练的 AME 策略 warm-start，复用现有 Parallelism AMP 数据与算法，进行 3500 个独立 AMP iteration。

一、目标与已确认结论

  • 源模型固定为 /share/home/tm884089579940000/a915071960/lhy/kinematic/Go2Pvcnn/logs/rsl_rl/cross_large_complex_ame/2026-09-08_15-40-23/bfb8b7f/model_19999.pt。
  • 保留 AME 的六通道地图、CNN、BatchNorm、MultiheadAttention、Actor、base Critic 和当前 action std。
  • AMP expert 继续来自现有 Parallelism planner；不使用 AME 自身轨迹充当 expert，也不引入外部动作数据集。
  • AMP 算法、双 GAE、24 帧缓冲、standstill/无解屏蔽、discriminator 和 replay 逻辑直接复用当前实现。
  • 只创建新的 AME-AMP 适配文件，不修改现有 AME、PPO、Parallelism AMP、Distillation 或 Teacher 源文件。
  • 本次训练是独立的 AMP 阶段，iteration 从 0 重新计数，训练 3500 轮，最终权重名为 model_3499.pt。
实验命名：该模型应称为 AME-XYZ-Semantic + Parallelism-AMP。它不是原版 AME，也不是不使用 planner 数据的 AME baseline。

源 checkpoint 已验证为 AME signature ame_xyz_semantic_v1_c6_s16_mha64_h16，包含 39 个模型张量；当前 12 维 std 的范围约为 0.2953-0.3883。

新增 AMP value head

AME critic observation [1584]
  -> shared AME CNN + BatchNorm + MHA
  -> concat(attention[64], raw critic state[48]) = critic feature[112]
  -> detach
  -> concat(amp_active[1], history_ratio[1]) = [114]
  -> Linear(114,256) -> ELU
  -> Linear(256,128) -> ELU
  -> Linear(128,1) = V_amp

AMP head 与现有 AmpActorCriticCNN 一致：Linear 层采用 orthogonal 初始化，最终层 weight/bias 初始化为 0，因此 warm-start 时 V_amp=0。

四、梯度与 BatchNorm 边界

损失允许更新禁止更新
PPO surrogateAME map encoder、attention、Actor、stdAMP discriminator
base value lossAME map encoder、attention、base CriticAMP discriminator
AMP value loss仅 amp_value_headAME encoder、attention、base Critic
discriminator loss仅 D 与 D normalizer整个 Actor-Critic

Actor、base Critic 与 AMP head 使用一个新的 Adam optimizer，初始学习率 1e-3，共同受 max_grad_norm=1.0 约束。D 使用独立 Adam，学习率 1e-4，保持现有 D 的梯度裁剪行为。

AME 的共享 encoder 含 BatchNorm。evaluate() 计算 critic feature 后缓存一个 detached 版本，紧接着的 evaluate_amp() 复用该 feature。这样一个 rollout/minibatch 不会因 base Critic 和 AMP Critic 对同一输入重复前向而额外更新一次 running mean/variance。

禁止：不能让 AMP value loss 反向进入 AME encoder，也不能为了计算 V_amp 对同一 critic batch 再独立执行一次训练态 BatchNorm。

五、24 帧 expert/agent 数据定义

每帧保持现有固定 39 维布局，discriminator 的窗口输入为 24 x 39 = 936 维：

0:1212 个 joint position12

24:27root position3
27:33root rotation 6D6
33:36body-frame root linear velocity3

agent frame 来自实际 Go2 状态；expert frame 来自 Parallelism 当前有效规划。窗口重建后，以末帧 root 为平移原点并消除末朝向，因此不会把绝对世界位置作为 D 的捷径。

六、逐步时间对齐

每个环境 step t:
  1. 记录 robot agent_start_t
  2. AME policy(obs_t) -> action_t
  3. ParallelismAmpEnv.step(action_t)
  4. 得到 robot agent_target_t 和 planner expert_target_t
  5. 写入 agent/expert transition delta
  6. 重建截至当前时刻的 24 帧窗口
  7. 写入 infos["amp"]

每个 PPO iteration:
  step 0 ... 39: 收集 40 个 transition
  -> base GAE 与 masked AMP GAE 分开计算
  -> 5 epochs x 4 minibatches 更新
  -> AMP 环形历史不随 PPO storage 清空
  • 重新规划时，新段第一条 transition 固定为 B0 -> B1，不产生旧段 A23 -> B1 的位置跳变。
  • 第一条有效 transition 同时提供 anchor 和 target，即 2 帧；累计到连续 24 帧后才令 amp_active=1。
  • history_ratio=valid_count/24 在 0 到 1 之间，告诉 AMP Critic 当前历史完整程度；它不替代 amp_active。
  • 40 步只是 PPO rollout 长度。24 帧 ring 跨 rollout 保留，所以第 40 步之后继续使用新规划或当前规划产生的真实连续 transition。

七、planner 无解与 standstill

沿用当前 AMP manager 的严格连续有效策略：

  1. 只要当前规划 transition 无效，对应环境立即清空 agent/expert ring、valid_count 和 write index。
  2. 该时刻 amp_active=0，AMP reward 被 gate 为 0，AMP GAE 和 actor 中的 AMP advantage 也为 0。
  3. base PPO 的环境 reward、base value 和 base advantage 继续训练，因此机器人 standstill 时不会停止整个 policy 学习。
  4. planner 恢复后从新的有效 transition 重新累计，只有重新达到 24 帧才恢复 AMP。
  5. episode reset 同样清空该环境的 AMP history，禁止跨 episode 拼接。

九、Checkpoint 生命周期

首次 AME warm-start

  1. 校验源文件存在、AME architecture signature、actor/critic/action 维度。
  2. 逐 key 严格加载 std、CNN、BatchNorm 参数与 running statistics、state projection、MHA、Actor 和 base Critic。
  3. 不加载源 PPO optimizer；为增加了 AMP head 的完整 Actor-Critic 创建新 Adam。
  4. AMP head、D、D optimizer、AMP replay 从新状态开始；AMP-local iteration 置 0。

完整 AME-AMP resume

  1. 严格恢复 AME 网络、AMP head、std、Actor-Critic optimizer、D 和 D optimizer。
  2. 恢复 AMP-local iteration，从该 iteration 继续调度与编号。
  3. 与当前 AMP 一致，device-local replay queue 不写入 checkpoint，resume 后由新有效窗口重新填充。

所有新 checkpoint 记录 AME-AMP signature、源 checkpoint 绝对路径、SHA256、源 iteration 19999、观测维度和动作维度。普通 AME checkpoint、普通 PPO checkpoint和 CNN-AMP checkpoint 均不能误作为完整 AME-AMP resume。
