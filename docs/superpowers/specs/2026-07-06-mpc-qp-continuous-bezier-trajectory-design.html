MPC-QP Full SQP/QP Trajectory Design

Date: 2026-07-06

Scope: Redesign the opt-in mpc_qp backend so a fixed-shape SQP/RTI-style QP directly optimizes root, foot-control, and touchdown variables over differentiable terrain/semantic fields, then samples the resulting trajectory.

Non-goal: Do not change the default planner_backend="mpc". This design only applies to the isolated planner_backend="mpc_qp" path.

1. Core Decision

The new mpc_qp must be a full QP/SQP trajectory optimizer. Touchdowns and trajectory controls are decision variables solved by the QP; they must not be selected by search, candidate enumeration, ring repair, nearby safe-point lookup, or post-hoc snapping.

old mpc_qp shape:
  nominal discrete frames
  -> detect unsafe frame
  -> hard replace / lift / reland individual points
  -> IK / viewer playback may become discontinuous

new mpc_qp shape:
  nominal warm start
  -> build differentiable height / semantic / roughness fields
  -> build fixed gait/contact schedule and fixed QP variable layout
  -> linearize field, reachability, clearance, and support residuals
  -> solve one batched local QP by default
  -> optimize four-leg/root/touchdown variables jointly
  -> sample fixed frames from the optimized continuous trajectory
  -> IK / cache / viewer consume sampled trajectory

The key requirement is that viewer, cache, reward, and downstream consumers read points sampled from a single optimized continuous curve. They should not receive a trajectory assembled from frame-wise safety fixes.

2. Hard Constraints

  • mpc_qp remains explicit opt-in and isolated from the current mpc backend.
  • The current mpc package is reference-only for this redesign. Do not edit Go2Pvcnn/extension/batch_mpc_planner/ to make mpc_qp pass unless the change is a separately justified shared-interface bug fix.
  • New continuous-QP code must live under Go2Pvcnn/extension/batch_mpc_qp_planner/ and must not change the default planner selection, current MpcTrajectoryManager, or current plan_segment() behavior.
  • Trajectory variables are optimized jointly for all four legs and root/base motion.
  • Each swing leg uses Bezier/B-spline control points; the horizon frames are sampled from the curve.
  • touchdown_xy is an optimization variable. It must be solved by the QP/SQP step, not found by scanning nearby cells or evaluating fixed candidates.
  • touchdown_z is not a free variable. It is always bound to the differentiable height field: touchdown_z = h(touchdown_xy); inside a local QP, use h0 + grad_h^T delta_xy.
  • Stance feet are world anchors. They should not be moved by per-frame repair.
  • Gait/contact phase is explicit. Alternating diagonal gait must be encoded in the variable mask/constraints rather than expected to emerge from soft losses.
  • Velocity tracking is low priority. Semantic safety, terrain crossing, foothold quality, height clearance, reachability, and continuity dominate.
  • If tests look bad, do not add new hard repair layers, candidate search, or touchdown lookup. Tune field construction, QP weights, constraints, fixed sampling density, QP iterations, or warm-start quality.

3. Memory And Runtime Contract

RL high-concurrency use is a first-class requirement. The optimizer must use fixed shapes and preallocated buffers.

  • Terrain maps are prepared once per planner refresh. Optimization iterations only query them.
  • Semantic maps are prepared once per planner refresh. Optimization iterations only query them.
  • Height, semantic-risk, roughness, clearance, and optional signed-distance vector fields are prepared once per planner refresh or deterministic resize. QP iterations only query values and gradients at fixed sample points.
  • Bezier basis matrices, sample phases, gait masks, stance/swing masks, footprint offsets, body samples, shank/knee samples, residual buffers, diagnostics buffers, and QP work buffers are allocated during planner/backend initialization or deterministic resize.
  • Do not build Python constraint lists inside the QP loop.
  • Do not scan the full map inside every QP iteration to create obstacle-specific constraints.
  • Do not allocate dense global pairwise tensors such as [B, K, H*W, ...].
  • All obstacle, semantic, clearance, reachability, and stability residuals use fixed-shape masks and buffers.
  • Do not use K-candidate endpoint line-search, fixed offset foothold selection, ring search, nearby safe-point search, or any other candidate-selection method as the main path.
allowed inside optimize loop:
  fill preallocated variables
  sample fixed Bezier points
  query differentiable fields and gradients through fixed buffers
  compute fixed-shape residuals
  assemble/fill fixed-size QP matrices
  solve fixed-iteration SQP/RTI local QP updates

forbidden inside optimize loop:
  create new obstacle list
  create variable-size constraints
  append tensors
  rebuild semantic geometry
  evaluate candidate footholds/endpoints and choose the best one
  add hard per-frame repair for new failures

4. Trajectory Parameterization

4.1 Swing Leg Curve

Each swing segment is represented as a cubic Bezier curve:

B(s) = Bezier(P0, P1, P2, P3), s in [0, 1]
Control PointRoleQP Behavior
P0Swing start foot positionFixed from current/nominal state
P1Early swing shapeOptimized xyz
P2Late swing shape / obstacle crossingOptimized xyz
P3TouchdownOptimized xy by QP; z = h(P3.xy) via height-field binding

User decision: do not add explicit penalties that keep P1/P2 close to nominal control points, and do not add direct P1/P2.z bounds. Their behavior is controlled by semantic/clearance/reachability/smoothness losses.

4.2 Stance Foot

Stance feet are anchored in world coordinates. The optimizer may evaluate stance safety and stance slip loss, but it must not use stance repair as the main behavior. After touchdown, the new stance anchor is the terrain-bound touchdown point.

4.3 Root/Base Trajectory

The QP must jointly consider root/base and all four feet. The exact root parameterization can use fixed horizon samples or spline/control points, but it must be optimized together with the four-leg variables so one leg cannot satisfy its local objective while degrading the other legs or the body path.

4.4 Fixed Gait Schedule

The optimizer must encode an alternating diagonal gait schedule. The first implementation can use a fixed two-phase schedule aligned to the horizon:

phase A:
  swing:  FL + RR
  stance: FR + RL

phase B:
  swing:  FR + RL
  stance: FL + RR

For stance legs, foot motion is constrained or heavily penalized through fixed masks. For swing legs, P1/P2/P3 are optimized under clearance, semantic, roughness, reachability, smoothness, and trust-region constraints. This prevents all four legs from drifting together or a single leg chasing velocity while degrading support for the others.

4.5 QP Variables

delta_x =
  root_delta_xy[t]
  root_delta_z_or_height[t]
  optional_yaw_delta[t]
  foot_control_delta_xyz[leg, P1/P2]
  touchdown_delta_xy[leg]
  semantic_slack
  roughness_slack
  clearance_slack
  reachability_slack
  stability_slack

Touchdown variables are part of delta_x. They are not lookup results. Slack variables keep the local QP feasible while making semantic, roughness, clearance, reachability, and stability violations expensive.

5. Semantic And Terrain Representation

The design converts discrete maps into fixed-shape differentiable fields before optimization. The QP loop must query field values and gradients, not perform cell search.

  • height field h(x,y) with grad_h(x,y), built from the height map.
  • semantic risk field s(x,y) with grad_s(x,y), built from semantic classes and smoothed risk or distance transforms.
  • roughness field r(x,y) with grad_r(x,y), built from local height variation, slope, edge, stair/box boundary cues, and support quality.
  • clearance field c(x,y,z) or equivalent fixed sampled residuals for swing/body/knee/shank clearance.
  • Fixed footprint and body stencils for center-plus-offset checks, evaluated through fields.
local QP linearization:
  h(xy + dxy) ~= h0 + grad_h^T dxy
  s(xy + dxy) ~= s0 + grad_s^T dxy
  r(xy + dxy) ~= r0 + grad_r^T dxy
Semantic TypeSwing RuleTouchdown/Stance Rule
ground Allowed with normal terrain clearance Allowed if foothold quality is good
low_small May pass over in xy if z clearance exceeds obstacle height plus margin Forbidden for touchdown and stance footprint
large/object Prefer keepout; if crossing is allowed, require stronger clearance Forbidden
High variation / stair / box edge Require robust clearance and bounded curve shape Penalize height variance, slope, edge proximity, and invalid support

6. Loss Design

The loss must be evaluated on fixed samples from the optimized continuous trajectories:

sampled_foot = bezier_sample(control_points, fixed_sample_s)
touchdown_xy = P3.xy
touchdown_z = h(touchdown_xy)
stance_anchor = fixed world anchor

6.1 Touchdown Semantic And Keepout Loss

Touchdown safety is optimized through differentiable fields and QP slack, not by searching for nearby safe cells or circles.

L_touchdown =
  w_touchdown_semantic * ||s0 + grad_s^T delta_xy - safe_threshold + semantic_slack||_+^2
+ w_touchdown_footprint * fixed_footprint_field_residuals
+ w_touchdown_surface   * field_surface_bad(P3.xy)

The touchdown center and footprint must avoid low-small and large/object semantic regions. P3.xy is a QP variable. Touchdown height is bound to h(P3.xy) and does not float.

6.2 Stance Semantic And Slip Loss

L_stance =
  w_stance_semantic * stance_footprint_bad(anchor_xy)
+ w_stance_slip     * ||stance_foot_sample - stance_anchor||^2

Stance anchor quality is high priority. Stance feet should not slide to satisfy velocity tracking.

6.3 Swing Clearance And Crossing Loss

L_swing_clearance =
  w_clearance * relu(required_clearance(xy, semantic, height) - foot_z)^2

Low-small objects may be crossed by the swing curve, but sampled foot height must clear the obstacle. Large/object regions use keepout or stronger clearance. This replaces frame-wise low-small lift repair.

6.4 Foothold Terrain Quality Loss

This loss prevents touchdown on obvious bad terrain such as high slope, stair edges, box edges, or high local height variation.

L_foothold =
  w_height_var * roughness_field_residual
+ w_slope      * slope_field_residual
+ w_edge       * edge_field_residual
+ w_support    * invalid_support_residual
+ w_boundary   * boundary_risk_residual

Footprint checks must use fixed offsets and differentiable field gradients. Center-only touchdown checks are insufficient. Bad footholds must push QP touchdown variables through gradients, not through candidate selection.

6.5 Body, Knee, Shank, And Root Safety Loss

Sample root/body/knee/shank points using fixed stencils and the optimized/sampled trajectory.

L_body_leg =
  w_body_semantic  * body_semantic_bad
+ w_knee_semantic  * knee_semantic_bad
+ w_shank_semantic * shank_semantic_bad
+ w_body_clearance * body_leg_clearance_violation

This prevents a foot trajectory that crosses successfully while the knee, shank, or body hits the object.

6.6 Reachability And IK/FK Readback Loss

L_reach =
  w_reachability * reachability_violation
+ w_fk_readback  * ||FK(IK(sampled_foot)) - sampled_foot||^2

If full FK readback is too costly in every iteration, use fixed-shape reachability residuals in the QP loop and run FK readback as a diagnostic or lower-frequency term. The design goal is to avoid trajectories that look safe in target space but become invalid after IK clamp.

6.6.1 Shared Coupled Readback Loss

The readback/reachability family must be a shared coupled loss, not a foot-only correction. If planned feet are terrain-bound but IK/FK feet float above them because the root is too high or the target is outside leg reach, the QP must be allowed to move root height and foot controls together.

shared decision block:
  delta_root_xy[t]
  delta_root_z[t]
  delta_P1_xyz[leg]
  delta_P2_xyz[leg]
  delta_P3_xy[leg]

coupled residual:
  e_fk = FK(IK(root + sampled_foot_controls)) - sampled_foot_controls
  L_shared_readback = w_fk * ||e_fk||^2
                    + w_reach * reachability_violation(root, foot)
                    + w_joint * joint_limit_violation(root, foot)

Adding losses into one scalar is not enough if each loss only sees its own private variable. The important geometric losses must directly depend on the shared root and foot-control variables. Local losses can stay local, but FK/readback, reachability, joint limits, body/knee/shank clearance, and FK terrain clearance must couple root and feet so the optimizer can negotiate a physically reachable trajectory instead of making the swing arc higher or the touchdown farther.

Loss GroupVariables It Must SeeReason
FK/readbackroot_z, root_xy, P1/P2/P3Allows root to lower when FK feet float above terrain-bound planned feet.
Reachability and joint limitsroot and sampled foot controlsPrevents unreachable feet from being hidden by IK clamp.
Body/knee/shank clearanceroot, sampled foot controls, fixed body/leg samplesPrevents a safe-looking foot path from colliding with object geometry through the leg or body.
Touchdown semantic/roughnessMostly P3.xy plus fixed footprint samplesCan remain local because touchdown quality is a foothold-field query.
Foot/root smoothnessCorresponding trajectory samplesCan remain local unless used to damp a coupled update.

6.9 QP Form

minimize:
  1/2 delta_x^T H delta_x + g^T delta_x

subject to:
  A delta_x <= b
  E delta_x  = e
  lower <= delta_x <= upper

The default solve is one SQP/RTI local QP iteration: linearize fields and reachability around the warm-start trajectory, solve a fixed-shape batched QP, update variables, then decode and sample the continuous trajectory. qp_iterations remains configurable for manual sweeps.

6.7 Smoothness And Continuity Loss

L_smooth =
  w_vel * sum ||B(s[k+1]) - B(s[k])||^2
+ w_acc * sum ||B(s[k+1]) - 2B(s[k]) + B(s[k-1])||^2
+ w_root_acc * root_acceleration_cost

This is not velocity tracking. It prevents Bezier control freedom from producing visually unstable or dynamically hostile foot paths.

6.8 Tracking And Nominal Guidance Loss

L_tracking =
  w_progress * root_progress_error^2
+ w_yaw      * yaw_error^2
+ w_nominal  * weak_nominal_guidance

Tracking weights must remain low. On hard terrain, the optimizer should prefer safe terrain crossing and foothold quality over command speed.

8. QP Iteration And Tuning Policy

When tests fail, tune fields, QP weights, constraints, sampling, warm start, or QP iterations. Do not add hard repair, candidate search, or touchdown lookup to hide the failure.

Observed FailureAllowed ResponseForbidden Response
Semantic collision or touchdown on object Improve semantic risk field and gradients, increase semantic/footprint weight, adjust slack penalty, increase QP iterations Add a post-QP per-frame point replacement, ring search, nearby safe touchdown lookup, or candidate touchdown selection
Foot trajectory discontinuity Increase smoothness/reachability/readback weights, adjust Bezier sampling, reduce tracking dominance Add a local lift/reland repair
Fails to cross low-small obstacle Tune low-small clearance and crossing loss, touchdown keepout radius, foothold scoring, QP iterations Force swing frames over obstacle with hard blend or choose a hand-picked crossing endpoint
Lands on stair/box edge Improve roughness/edge/support fields and gradients; increase roughness/edge/support slack penalties After touchdown, snap to a nearby point or scan fixed offsets for a lower-risk touchdown
Velocity tracking poor Only after safety is clean, slightly raise progress/tracking weights Reduce safety/foothold losses to chase speed

9.2 Required Probe Gates

Do not judge the redesign only by whether semantic objects are avoided. The test suite and real probes must also report collision rate and FK/planned foot overlap.

  • Semantic/object pass rate: no touchdown or stance on low-small/semantic objects, and no FK foot/knee/shank/body semantic collision.
  • Collision rate: FK terrain/object penetration rate must stay within the probe tolerance; row 8, col 12 must be included.
  • FK/planned overlap: FK(IK(planned_foot)) should overlap the planned foot trajectory under the strict readback gate; high overlap is required even when the planned touchdown itself is on the terrain.
  • Low-small crossing: use the old MPC low-small probe metrics from 2026-05-28-parametric-low-small-loss-redesign.html as reference, but implement them as QP loss/diagnostics rather than repair.
  • Trajectory quality: foot jumps, joint jumps, and swing height over terrain must stay bounded so small obstacles are crossed without excessive arcs.

10. Implementation Shape

The implementation should introduce a new internal path under Go2Pvcnn/extension/batch_mpc_qp_planner/. The old mpc code is used as semantic/loss reference, not as a mutable target.

batch_mpc_qp_planner/
  bezier.py             # fixed Bezier basis and sampling
  buffers.py            # preallocated work buffers
  fields.py             # differentiable height/semantic/roughness/clearance fields and gradients
  gait.py               # fixed alternating gait/contact masks
  variables.py          # fixed QP variable layout for root, foot controls, touchdowns, slacks
  qp_assembly.py        # fixed-shape H/g/A/b/E/e fill from linearized residuals
  solver.py             # fixed-shape batched SQP/RTI QP solve
  losses.py             # diagnostics from sampled trajectory and QP residuals
  planner.py            # mpc_qp orchestration and cache-compatible output

11. Open Design Checks Before Coding

  • Remove or bypass current candidate/search/repair-style continuous solver paths from the mpc_qp main path.
  • Choose differentiable field construction for semantic risk, roughness, edge, clearance, and height gradients.
  • Choose fixed Bezier sample count per swing segment.
  • Choose fixed footprint sample offsets and body/knee/shank samples.
  • Define fixed QP variable ordering and gait masks for alternating diagonal gait.
  • Define the first batched QP solve method: fixed KKT solve, projected active-set, or differentiable box-constrained solve.
  • Define memory budget for target RL concurrency and enforce it in tests.
  • Add automated probe coverage for terrain-row=8, terrain-col=12 in addition to interactive viewer acceptance.
