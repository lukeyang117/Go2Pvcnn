M1 RL：AME / AME-AMP Agent 实施设计

目标分支：m1_rl，基于当前已推送的 m1。本文档供 Agent 直接执行，要求 M1 适配不改变 parallelism-amp 的强化学习算法。

版本：2026-09-14　|　M1 基线：844c72d　|　算法参考：parallelism-amp

1. 任务结论

必须实现：在 M1 上新增 AME baseline 与 AME_AMP 两套训练入口。算法、Runner、Policy、AMP critic、判别器、PPO/GAE 更新和 checkpoint/resume 语义必须完整复现 parallelism-amp；M1 只替换机器人资产、观测映射、奖励几何参数和 Parallelism backend。
不可误解：M1 的 RL action 保持 16 维。Parallelism 只提供 12 个腿部关节参考，4 个轮子 action 完全由 RL 学习。轮子 joint position/velocity 不进入 policy state、AMP critic/context 或 ParallelismState。

7. 环境与观测设计

7.1 AME baseline

  • 继承 AME 的 map/state 分组、corruption 设置与 ActorCriticAME 输入 contract。
  • scene.robot 替换为 M1_CFG；scanner prim path 和 contact selectors 使用 M1 USD 名称。
  • joint position、joint velocity、last action history 均显式 slice 为 12 个腿部关节，不含 wheel state/history。
  • policy action head 仍为 16 维，并按 M1 asset joint order 输出。

7.2 AME-AMP

  • 复用 AME observation contract、AMP window、Runner 和 checkpoint 生命周期。
  • AMP critic/context 的 joint state 固定 12 维；禁止拼接 wheel joint position/velocity。
  • 允许使用轮心位置、轮子接触和 terrain map：它们是足端/环境几何，不是轮子关节状态。
  • ParallelismState.joint_pos 为 12 维，foot_pos_w 是按 M1 support body 名字排序的四个轮心。

8. Parallelism 接入

  1. 给 reference manager 注入 RobotBackend，按 env.cfg.robot_name 选择 get_robot_backend("m1")；Go2 默认路径不变。
  2. 从 16 维 robot state 按名字抽取 12 维 planner state，禁止 wheel joint 进入 m1_fk 或 plan_trajectory。
  3. 足端查找由 backend.support_body_names 驱动，不能保留 Go2 的 .*_foot 和 _PLANNER_FOOT_ORDER 假设。
  4. reference cache 的 joint pos/vel 固定 12 维。RL policy 的 16 维 action 直接进入 M1 actuator，Parallelism 仅作为 reference/AMP 信号。
  5. 每步只执行一次 batch plan；不得为 wheel action 增加候选搜索或 planner 分支。
asset_joint_16 = read_robot_joint_state(env)
planner_index_12 = backend.asset_to_planner_indices(robot)
planner_joint_12 = asset_joint_16.index_select(-1, planner_index_12)
state = ParallelismState(root_pos_w, root_rpy_w, planner_joint_12, wheel_centers_w)
reference_12 = plan_trajectory(state, command, terrain, robot_backend=backend)
policy_action_16 = policy(observation_without_wheel_joint_state)
env.step(policy_action_16)  # wheel 四列由 RL 决定，不被 planner 覆盖

类别需核验项目M1 规则

Foot trackingreference_foot_pos、active swing使用四个 FOOT_LINK 轮心；z/contact offset 包含 wheel radius。
Collisiongeometry collision、undesired contact使用 M1 base/link 名称和已有 wheel/calf/thigh primitive surface；不得套 Go2 regex。

9.2 参数验收顺序

  1. 静态检查每个 reward term 的 selector、shape、单位和 M1 解析 ids；reference joint 必须为 12 维，RL action 必须为 16 维。
  2. 几何检查默认站姿下四个轮心高度、轮底高度、root z 和 foot reference 偏差均有限；平地不触发 clearance/非法接触。
  3. 行为检查平地轮式滑行、非平地 terrain-following、box/楼梯跨越小障碍，记录 reward 均值、95 分位和触发次数。
  4. 一次只改一个尺寸相关参数，并保存 Go2/M1 参数快照，确保不改变 Go2 分支。

每个修改参数都要在提交说明中给出：旧值、M1 新值、单位、来源（USD/公式/实测/实验）、影响项和测试。没有来源的“调到能跑”不接受。

11. Agent 执行顺序

  1. 先写 contract 测试：16 action、12 planner state、无 wheel policy/AMP state、M1 joint/body selectors。
  2. 把 Go2 专用 reference manager 改为 backend 驱动，保留 Go2 默认行为。
  3. 创建 M1 AME env/config，完成 observation 与 16 维 action wiring。
  4. 创建 M1 AME-AMP env/config，接入 12 维 reference window 与无 wheel AMP context。
  5. 逐项完成第 9 节 reward/termination 尺寸对齐和测试。
  6. 新增两个 Python launcher、两个 headless launcher 和独立 env ids。
  7. 按 8 env、1024 env 顺序完成真实 Isaac Lab smoke。
  8. 按 contract、adapter、AME、AME-AMP、reward、smoke evidence 分拆提交。

13. 禁止事项与完成定义

  • 禁止复制或修改 ParallelismAMPPPO、AmpActorCriticAME、discriminator、Runner 核心算法来适配 M1。
  • 禁止把 wheel joint 塞进 policy state、AMP critic/context、ParallelismState 或 reference joint reward。
  • 禁止使用未经核验的 joint_names=".*"、body_names=".*_foot"。
  • 禁止逐 env 调 planner、逐 env 查 USD、CPU IK 或训练 step 内动态构造 joint index。
  • 禁止为了 smoke 关闭碰撞、删除终止项、跳过 reward 或把 action 置零。
完成定义：m1_rl 包含可训练的 M1 AME/AME-AMP 配置与入口；算法行为和参数与 parallelism-amp 一致；差异只存在于 M1 资产、12/16 维接口、几何及奖励尺寸；Go2 不回归；两套 M1 smoke 都完成至少一个 RL update 并保存证据。
