# Joint MPC Root / Foot Propulsion Order Quantification

- Purpose: quantify the viewer observation that the root appears to move first and carry the feet, instead of planted feet establishing support and swing feet advancing the body.
- Stage: `Go2Pvcnn/extension/joint_mpc_rti`, flat-terrain rolling `x1` execution.
- Related todo: [T302v.7](../todo/T302v-joint-mpc-rti-gpu.md).
- Baseline Ref: `7dba008`.
- Candidate Ref: `7dba008`.
- Key Files: `Go2Pvcnn/extension/joint_mpc_rti/planner.py`, `Go2Pvcnn/extension/joint_mpc_rti/model/dynamics.py`, `Go2Pvcnn/extension/joint_mpc_rti/losses/rollout_objective.py`.

## Procedure

- Ran 64 rolling `x1` updates at `dt=0.02s` on a flat field, using the same H16 planner path as viewer playback.
- Commands covered forward `0.10/0.20/0.40m/s`, backward `0.25m/s`, left/right `0.25m/s`, and two diagonal commands at `0.25/0.403m/s`.
- Projected root and foot XY displacement onto each command direction.
- Measured consecutive-stance foot displacement, the fraction of stance samples moving no more than `1mm/frame`, and complete liftoff-to-touchdown swing displacement split into world-foot, root, and foot-relative-to-root components.
- CUDA/NVML was unavailable in this session. This small-batch diagnostic ran on CPU; it measures trajectory semantics, not performance.

Aggregate results:

- Mean signed stance displacement / root displacement: `1.040`.
- Mean absolute stance displacement / root displacement: `1.062`.
- Only `4.02%` of consecutive-stance samples moved no more than `1mm/frame`.
- Mean swing relative-to-root progress / root progress: `0.070`.
- `6/8` commands had swing relative-to-root progress no greater than `10%` of root progress; several were negative.
- Root command motion begins in the first published `20ms` frame. Swing-foot world motion also begins in that frame, so the defect is not a simple multi-frame onset delay. Most foot world motion is explained by root translation rather than active foot motion relative to the body.

## Root Cause Evidence

- `kinematic_step()` integrates root position directly from the root velocity control, independently of contact forces or support-foot feasibility.
- `_control_from_joint_target()` writes `command_body` directly into every horizon root XY control.
- `_nominal_joint_target()` depends on contact phase and fixed thigh/calf swing angles, but has no command input.
- The joint MPC backend has no command-conditioned foothold/touchdown XY target. Swing loss tracks FK positions generated by that fixed joint-angle motion, while stance anchoring is a soft residual.

The viewer observation is confirmed. The current backend is kinematically root-driven: root motion is prescribed first by command integration, and the feet are optimized around that root trajectory. Existing stance-grounding acceptance checks Z contact but allows roughly `15mm` XY step, so it did not reject this gait-quality failure.

## Result

- Reproduced and quantified; no planner behavior was changed.
- Existing collision, crossing, grounding-Z, and command-tracking passes do not establish support-driven locomotion.
- Performance work is explicitly deferred per user request.

## Follow-up

Define a gait-quality contract before implementation: near-zero world-frame stance slip, command-conditioned swing touchdown lead, and root progress coupled to the support/swing schedule rather than independently integrated at full command speed from the first frame.
